### §0.1 一条必须先裁决的口径冲突（真实、来自上游原文）

`spark-output/context/edge.json` → `states_matrix[flow2/Cert Focus].states[offline-no-network]`，`implemented: false`，原文：

> 主屏进度显「座X 待同步」，**不把缺席当成弃权**；fallback_behavior：等待该端重连；超时后可**主持人代决**。

这条设计意图与本链今天得到的三条结论**方向相反**：

| 本链结论 | 出处 | 冲突点 |
| --- | --- | --- |
| 超时兜底应执行「最不动别人利益」的保守动作（我们已改判为弃权 + 设上限） | `bench.takeaway-6`（天凤 60s 强制摸切） | Edge 说"不把缺席当弃权"，即**弃权是错误的默认** |
| AI 手番**不得要求任何真人代为抽/选/弃/结算** | `bench.takeaway-10`（波多黎各「需要替自动机结算」）+ `metric.driver_metrics[D2]` 目标 = 0 | Edge 的 fallback 正是**主持人代决** |
| 沉默/无参与是失败态：AI 参与认证事件数 ≥ 1/局，否则判「隐形座位」 | `metric.driver_metrics[D3]` | "一直等待该端重连"会把座位做成隐形 |

**为什么会分叉**（这句写进规格，避免下次又被改回去）：Edge 那条针对的是**临时网络抖动**——人还在场，只是消息没到，此时判弃权是对真人的不公。本链三条针对的是**这个人根本不在场**——等待的对象不存在，等多久都不会来人。**它们是两种状态，不是同一条规则的两种写法。**

**建议裁决（需 G3 拍板）**：状态机拆成两档——
- `seat_offline_temporary`（真人已绑定座位、链路未同步）→ 沿用 Edge 原意：**等待 + 不把缺席当弃权**；主持人代决仅在超时 ≥2 分钟后开放，且必须留下 `human_takeover_click` 记录。
- `seat_filled_by_ai`（开局即由程序占据）→ 走本链口径：**永不向真人索取操作**，超时执行保守动作，无合法招记 `ai_forfeit`。

两档必须可区分（依赖 `seat_control_assigned.controlledBy`），否则 `human_takeover_click == 0` 这条底线指标会被 Edge 的合法代决污染，导致 D2 永远红。

## §1 Summary（60 秒）

为一个**实体 + 单文件网页双轨**的聚会桌游《创界山·活人认证》新增一项能力：当约好的 6–8 人局临时少一个人时，由**一个程序座位（稳座档）**顶上那张椅子，让局照样开成，而桌上另外 **5 个会玩的人不觉得这一局被拖废**。它服务的不是"一个人也不想等"的人（那是 v2 之后的另一条链），而是「聚会局长」大林和他的朋友桌。之所以是现在：这条方向的关键假设从 11-07 押到今天仍是 **0 真人证据**，而补位把"跑一局"的门槛从 6 真人降到 **5 真人 + 设计者自己**——它是目前唯一能撬开验证死结的杠杆；同时行业三源（Automa 六原则 / BGA 开发者文档 / 王者官方公告）在"别做真 AI，做保底"上已经撞车，成熟答案存在且**不需要语言模型**。成功长这样一件事：**A 组（5 真人 + 1 程序座位，6 人档）相对 B 组（5 真人，5 人档）的"全桌同频时刻"增益 ≥ +1.0 次/局，且散场时"想换回真人"人次 = 0**；增益 ≤ 0 即判零代码方案够用，本批次关闭。

## §2 Background & Problem

**问题（用户视角）**：大林攒了一场 6 人局，有人来不了。他拉了一个不玩桌游的朋友凑数——那位朋友不会玩、撑不住，另外 5 个会玩的人被这个座位拖废，那一晚**不欢而散**。真正受伤的还有那位凑数的人：他是这局里唯一被迫待在不懂的位置上的人。

**当前 workaround 及为何不够好**（来自 `frame-ai-seat.persona.workaround`）：拉不熟的人凑数 + 全程当免费规则老师；或改玩 5 人能玩的别的游戏；或拖到下周；或不开。四个出口里只有"不开"没有代价，而它的代价是**大林独自承担「局是我组的，散也是我凑不齐人害的」**——这条情感量级比 11-07 记录的"避免冷场"重一档。

**为什么是现在**：① 三源撞车说明"程序座位"的实现范式已成熟；② Probe 招募 16 天 0 人，补位直接降低跑局门槛；③ 反方时间信号——BGA 论坛 2026-11（本月）付费 AI 对手提案遭社区敌意。**必须区分**：敌意针对"AI 顶替真人当对手"，本 PRD 做的是"AI 顶替缺席者"，文案与规则书不得混用两者的措辞。

**本 PRD 故意不解决什么**（来自 `brief.out_of_scope` + `frame-ai-seat`）：
1. **不做 AI 陪练/对抗型对手**（Brief 第 4 条明写不做 AI 陪练；规格 `...design.md:1055` 亦裁定 V1 不做——**本 PRD 是在申请翻这条，翻案即 Ask 3，未翻案前实现属于违规施工**）。
2. **不做全 AI 局 / 半桌（1–3 真人）/ 挂机旁观局**：填补量是名场面的稀释曲线，0 真人时没有人在验活人，"AI 通过活人认证"从反讽退化为空转。
3. **不解决"约不到人当被试"**：补位降低的是玩起来的人数门槛，不是实验招募；Probe 的社会半边仍需真人局，见 §8。
4. **不接 Host 原型**（见 §0 G5）。

## §3 Personas

**Primary — 大林**（31 岁，朋友圈的「聚会局长」）
- 情境：局约好了、差一个人 → 拉不熟的人凑数 → 他不会玩、撑不住 → 那一局被拖废 → 不欢而散
- JTBD：当约好的 6–8 人局临时少一个人，大林想在不把不会玩的朋友塞进座位的前提下照样把局开成，从而那一局不被单个座位拖废、不半途散场
- 当前 workaround：拉人凑数 + 当免费规则老师；或改玩别的；或拖期；或不开
- 痛点：教学即冷场、名场面密度当场归零；凑数的人是真受害者而没人替他说话；组局的人独自承担散场的责任

**Secondary（打分人，非买家）— 桌上另外 5 个会玩的人**
- 情境：他们来是为了自己玩，不是为了陪大林教新手
- JTBD：当有人缺席，他们想这一局不因缺人而降质，从而不必忍一个不会玩的座位
- 关键性质：**验收判据写给他们，不写给大林**（`frame-ai-seat` Ruling 5）。任何只从大林视角写的 AC 都在测错人。

**Tertiary（本 PRD 的替代受益者，但 v1 不为其设计）— 那位被拉来凑数的人**
- 补位一旦可用，他的座位被程序收走。**长期风险**：这条座位是新人入坑的唯一进水口（`bench.takeaway` 真人新手上桌 Counter），v1 必须显式盯住而不是默认放弃。

**不为谁做**：不为"一个人也不想等、想随时开一局"的单人玩家做（那是 0 真人填补量，persona 不是大林，是另一条链）。

## §4 Goals & Success Metrics

**产品目标（outcome-framed）**：让"差一个人"不再是"这一局作废"的理由，同时不让另外 5 个人付出体验税。

度量体系来自 `metric.json`（NSM + 5 Drivers + 6 Counters + 5 Health），此处只列交付相关项：

| 指标 | 度量什么用户行为 | 目标值 | 时间窗 |
| --- | --- | --- | --- |
| 🌟 **补位名场面增益（NSM）** | A 组（5 真人 + 1 AI，6 人档）与 B 组（5 真人，5 人档）每局全桌同频时刻数之差 | **≥ +1.0 次/局** 且「想换回真人」人次 = 0 | 3 周 6 局（3A+3B，≥2 个 seed） |
| D1 AI 手番墙钟耗时中位 | 桌上真正等了多久（引擎 log 是逻辑时间，测不出，必须 UI 侧新增） | ≤ 人类同局中位 **1.0×**；绝对 ≤ 3000ms | 首 3 局 |
| D2 真人代操作次数 | 有没有人被迫替 AI 动手 | **= 0**（底线，非优化项） | 首局即判 |
| D3 AI 参与的认证/质疑事件数 | 座位是否真的在场而非隐形 | ≥ 1.0 次/局 | 首 3 局 |
| D4 非法动作率 / 降级深度 | "塌"的字面含义 + 是否全靠兜底 | 非法率 **0**；兜底档 ≤ 25% | 每次构建（并入 `release:check`） |
| D5 组局兑现率 | 功能是否用在它被发明的场景 | ≥ 60%，且 ≥2 场为真实缺人场景 | 60 天 |
| 💊 位次极差（补位档单列） | 平衡不被补位破坏 | ≤ 8pp 报告 / ≤ 14pp 门禁 / RMS ≤ 6.5pp | 每档 100 局固定 seed |
| 💊 门⑨ + release 100 组 | 确定性不被污染 | **逐字节一致**（不是"接近"） | 每次构建 |

**Anti-metrics（本 PRD 明确不优化，优化它会做错产品）**：

1. **AI 座位的胜率 / 名次** —— 补位的价值是"不塌"，不是"打得对"。若把胜率当目标，就会去接模型、掀三条红线，并复制王者「不如挂机了」的套利反噬。
2. **单座位笑声占比 > 40%** —— 为拉名场面计数把 AI 调成小丑，会让 5 个人变成观众，恰好摧毁"全桌同频"的定义。
3. **"代操作次数 = 0" 靠禁掉按钮达成** —— 零代操作有两种来源：契约清晰，或座位黑箱。故每局须有 ≥1 次"桌友指出 AI 动作异常并被当场归类"，否则该局判**不可解释**、不直接计入样本。
4. **AI 发言量**（v2 相关）—— Among Them 数据：token 越多胜率越低（r=−0.070）、说服句越多胜率越低（−0.237）。话多不等于有戏。

**关键假设**：`一个能合法、不卡轮、不冷场的补位座位，就能把「不欢而散」接住` —— **机制半边有证据**（release 模拟跑局 + 平衡报告），**社会半边 0 证据**（`probe.json participants=0`）。**若此假设错，做错的是产品而不是实现。**

## §5 Value Proposition

**对大林**：
> 大林终于可以在差一个人的晚上照样开一局不塌的局，而不必把一个不会玩的朋友塞进为老手设计的座位——因为补位座位遵守与真人完全相同的合法性与节奏约束，并且**永远不会需要桌上任何人为它代劳**。

**对那 5 个打分的人**（实际买家 ≠ 打分人，这条必须单列）：
> 他们终于不必"陪一场有新手拖着的局"，因为程序座位的失败模式被限定为"像新手一样可被原谅"，而不是"像 bug 一样要有人管"。

**竞争差异化**（来自 `bench` + `frame-ai-seat.competitive_landscape`）：

| 对手族 | 做对了什么 | 留下的空白 | 我们填哪个 |
| --- | --- | --- | --- |
| 王者荣耀 AI 托管 | 补位进场交互 + 官方定调"比本人弱但看起来更聪明、绝不拖后腿" | 只接管操作层，不接管发言层 | 稳座档填**操作层 + 零代操作**；发言层留 v2 |
| BGA zombie bot | 补位接管、**results no longer count toward statistics**、只按当前可见信息、不得提前结束游戏 | 无强制 Bot 标识（被投诉 invisible）；对 bot 回合时长零要求 | 填**公开不可关闭标识** + **手番时长上限**（后者行业是空白） |
| Automa Factory | 空壳化、三级降级链、控分不控智能、Charterstone 明文 stand-in for absent players | Pedersen 明文：发言/社交类 **won't cut it** | 我们**只做不塌这一半**（机制层），主动放弃发言层到 v2 |
| CICERO / LLM 群 | 唯一真做了发言层 | 幽默 0/25、话多有害、不记仇被欺负、更早被票出；未产品化 | v2 的地基是**恩怨计数**而非模型强度 |

**我们的差异不在聪明，在敢做一个刻意不最优、但可被原谅的座位**——这是四个对手族都没占的中间缝（像人但闯祸 / 正确但无聊，两端都被试过）。

## §6 Solution & Feature Scope

> ⚠️ **设计资产现状（已交叉核验）**：对 `stories / check / edge / sitemap / flow-web` 五个主链文件整词检索 `AI|机器人|托管|补位|代打|程序座位|单人|bot|robot|npc|solo`，**零命中**。唯一命中的"缺席"4 处均为真人掉线语义。因此本节所有屏/组件/状态为**待生成**，无现成 .tsx 可接。可复用的只有：§0.1 的缺席异常态原文、`page-host-setup` 的配置槽位、以及 14 屏的既有布局语言。

### Story S1 — 差一个人的局里，程序座位自己把自己那部分玩完（P0，⭐关键假设载体）

> **S1 状态（2026-11-24）**：核心已实现并通过真实决策点回归；生产 AI 座位开关仍 blocked on Ask 5，S3 质疑/作答路径未开放。

**Persona**：大林（买家）× 5 位会玩的人（打分）
**Job**：缺席发生 → 座位被顶上 → 一局不打折地跑完
**关键假设标记**：⭐ 本 Story 就是 `frame-ai-seat.critical_assumption` 的测试载体

**功能描述**：开局时把一个座位标记为程序控制。轮到这个座位时，引擎枚举它的合法动作，由决策器选一个，提交、推进、继续轮转。它不需要任何人为它抽牌、选目标、点确认；它做错时表现为"像新手"，不表现为"卡住"。

**In Scope（本版要做的）**
- `Player` 新增 `controlledBy: 'human' | 'ai'`（现无此字段；座位归属目前只活在 `ui.seat` 这个 UI 变量里）
- 新增**统一提交口** `applyAction(state, action): State`，内部分派现有 11 类入口（`performAction` / `resolveGate` / `resolveCompareGate` / `resolveBarrier` / `submitDuelCard` / `castVote` / `useCouncilVeto` / `certify*`）——现缺此口，`probeAction` 已把这套分派折叠过一次，可作参照实现
- AI 决策器 = **启发式档**（复用仓库既有 policy 思路），**v1 不接 sidecar**
- 每个动作带**三级降级链**（主选 → 次选 → 兜底重抽），非法目标不得进入决策集
- **零隐藏状态**：AI 的内部状态只保留会影响他人的字段（同时满足预研红线"模型只见公开信息"）
- 手番时长上限：≤3 步即时结算、无收入阶段、无个人版图、只复用本体既有动作图标与动作键
- 超时兜底按 §0.1 裁决后的语义执行；无合法招记 `ai_forfeit`

**Out of Scope（本版故意不做）**
- 模型接入（sidecar、三条红线相关的一切）
- 让 AI 在认证/山议里**说话**（自由文本发言层）
- 半桌（1–3 真人）与全 AI 局
- 为 AI 座位做单独的视觉体系（沿用 14 屏既有语言）

**验收标准（Given / When / Then）**
- Given 6 人局且 seat 5 标记为 `controlledBy:'ai'`，When 轮到 seat 5，Then 该局在不出现任何系统行的前提下推进到下一座位，且 `getLegalActions(state,5)` 非空 ⇒ 日志出现一条 `ai_action_committed` 且 `legal == true`
- Given 轮到 AI 座位，When 桌上**没有任何人触碰控件**，Then 该手番完成且 `human_takeover_click` 计数为 0 —— **这是本 Story 的硬底线，任意一次 > 0 即判负并暂停平衡讨论**
- Given 构造极端局（全部合法目标已被占/已死/已放逐），When AI 必须行动，Then 它仍能通过降级链产出动作，且不提前结束游戏（对齐 BGA 文档"不得提前结束游戏"）
- Given AI 手番，When 从轮转到该座位起计时，Then `ai_turn_duration_ms` 中位数 ≤ 同局人类手番中位数 × 1.0，且绝对值 ≤ 3000ms
- Given 超时（阈值见 §0 G3 裁决），When AI 未能产出动作，Then 执行保守动作并记 `ai_forfeit{reason:'timeout'}`；一局内 `reason=='timeout'` 占比 ≤ 15%，连续两局 > 25% 判该档不可用
- 边缘情况：AI 座位被放逐后 —— 沿用主链"出局仍有参与动作"的既有设计意图（`stories.json` story-3），v1 只保留投票类参与，不保留操作类参与
- 空状态：某轮 `getLegalActions` 返回空集 —— 不得静默跳过（会触发"隐形座位"误判），必须记 `ai_forfeit{reason:'no_legal'}` 并在日志行显式可见

**设计触点（推导，未经 Stories 评审）**
- 涉及屏：座位面板（补位标识）、AI 手番进行态、`ai_forfeit` 可见化行、日志页
- 涉及组件：座位控制器标记、手番计时器（现 `missing_spark_components` 已列"答题倒计时计时器"未实现，可同批补）
- 涉及状态：`seat_filled_by_ai`（新）、`waiting_for_ai`（新）、`ai_forfeit`（新）

**关联 Sitemap 页面**
- `page-host-setup`（`/#setup` 牌局控制：主题/人数/模式/新开/存档/导出…）— 补位开关与 seed 入口的既有归属位，`status: refactor`
- `page-host-seats`（`/#seats` 席位·活人席计分）— AI 座位是否计入席位，取决于 Ask 1
- `page-host-log`（`/#log`）— `ai_*` 事件的可见化出口

**已生成的设计资产**：**待生成**（本节全部）。可参照的既有实现语言：`creativemountain-host/src/flows/flow1-host-dashboard/flow1-host-dashboard.tsx`（座位与看板布局）、`web/main.ts` + `web/ui/log.ts`（真引擎接线端，落地首选）。

**待澄清问题**：① §0 G3 状态机两档命名与超时阈值；② AI 座位被放逐后是否保留投票权（涉及 D3）；③ `degrade_level` 是否需要暴露给玩家看到（暴露可能反而提示"它在勉强"）。

### Story S2 — 全桌都知道那个位子不是人，且没人因此被塞进来（P0）

**Persona**：5 位会玩的人（打分人）
**Job**：知道现在是机器在打 → 不必猜 → 也不觉得被背叛

**功能描述**：把补位做成一个**公开、不可关闭、全员一致**的事实，并把"要不要让 AI 入座"的**决定权交给在场的人**；同时规定补位局里那位缺席本人的成绩归属，切断"不如让 AI 替我打"的套利。

**In Scope**
- 补位标识：开局配置屏 + 座位面板 + 日志行三处一致呈现；**不得仅靠颜色或星号传达**（`check.findings[0]` accessibility minor 未修：「待认证仍以星号 + 颜色为主传达」——同一缺陷不得在补位标识上重演）
- 授权流程：在场者确认后方可入座；不确认则维持"缺人"状态（对齐王者的在场者三选弹窗范式）
- 成绩归属：补位局不给缺席本人记分（对齐 BGA zombie `results no longer count toward statistics`）
- 可 ban 开关（行业标配，`bench.takeaway-15`）

**Out of Scope**
- 伪装成真人 / 不告知模式（**明确禁止**，见 §7 风险 R2）
- 多端账号体系（主链 `platform_notes`：会话制房间码，非登录）

**验收标准**
- Given 补位座位在局，When 任一玩家查看座位面板/日志/开局屏任一处，Then 三处对"该座位由程序控制"的表述一致且无需悬停揭示
- Given 标识仅用颜色区分，When 走查，Then **判不合格**（必须同时有文本/图形冗余）
- Given 在场者未点"同意 AI 入座"，When 有人点开始，Then 不开局，并提示当前可选方案（等待 / 按 5 人档开局 / 同意补位）—— **注意：必须把"按 5 人档开局"作为显式选项呈现，它是对照组，不是备胎**
- Given 一位缺席本人，When 该局结算，Then 其成绩标记为补位局且不归属本人，规则书口径一致
- 边缘情况：全桌 5 人都同意但只有 1 人反对 → v1 裁定为**任一在场者可否决**（低成本且直接规避"被塞 AI"的愤怒）
- 空状态：座位数为 0 真人（全 AI）→ 明确拒绝并提示属 v2 之后的另一模式

**设计触点**：开局配置屏（`page-host-setup`）、座位面板标识、结算页归属标记、日志行前缀
**关联 Sitemap**：`page-host-setup`、`page-host-rank`（排名公示）、`page-host-log`
**已生成的设计资产**：**待生成**；标识语义 **lean-in**（跟行业：天凤掉线标红 / Charterstone 具名实体 / BGA 独立面板）
**待澄清问题**：补位座位在规则书里**叫什么**（Bot？机器人？替身上山？行道者？）——它必须进主题词体系并受 B79/B80 句子层门禁约束，不能写死中文词，否则会撞上 `SENTENCE_WHITELIST 必须恒为空集` 的纪律。

### Story S3 — 程序座位把局推向认证，而不是绕过它（P0，⭐依赖 Ask 1）

**Persona**：大林 + 5 位打分人
**Job**：6 人档多出来的那两格强度（签印门槛 4、seatWeight 20）真的兑现，否则 B 组就够

**功能描述**：让程序座位参与关隘、山议与认证流程——**参与的程度由 Ask 1 裁定**，故本节按分支写。

**In Scope（两分支共用）**
- AI 座位可被选为目标（真人可对它质疑/作证/投票）—— 与 Ask 1 无关，必须做，否则座位不存在于社交图里
- `cert_event` 事件落账（含 `ai_participated`）
- 若 AI 参与签印或持席：**必须显式申报重基线**并同步规格 §8（禁止悄悄过门⑨）

**分支 A（无签印权 / 计入 N 之外）**
- AI 不得出现在签印计数 N 的分子里；`threshold` 按 6 人档不变，但因可用签印人数只剩 5，**须重跑平衡回归确认 4/5 的门槛在 5 真人下仍落在 `TRIAL_PASS_RANGES` 与极差区间内**
- 规则书写清"机器的同意不算人的同意"——这句话是本分支的主题防御，不写就等于把反讽留给了沉默

**分支 B（有签印权但不计入 N）**
- AI 的签印落账但标记为 `non-counting`；UI 可见"它签了，但它不是活人"
- 需要新增日志可见性，否则 D3 指标不可核

**分支 C（计入 N）** —— **本 PRD 不建议，理由写进文档以免下次被反复重提**：机器人替"这是活人"作保，等于让核心命题空转；且极差与席位供给会被 `seatWeight`（6 人档 20）凭空放大，`scales.ts:44-50` 已警告过席位权重越界的后果。

**Out of Scope（全部分支）**
- AI 产出自由文本的认证答案（v2）
- 让模型替 AI 判定"谁该被验"

**验收标准**
- Given Ask 1 已拍板（G1），When 跑 `release:check`，Then 与所申报基线逐组全等；未申报的重基线判红
- Given 一局，When 结算 `cert_event`，Then AI 参与次数 ≥ 1.0/局；连续 < 1 判"隐形座位"，本 Story 不算完成
- Given 分支 A，When 真人在认证里把 AI 当签印者点击，Then 该操作被拒绝并给出机制原因（不得静默无效——静默会让桌上误判为 bug）
- Given 分支 B，When 查看签印进度，Then 能一眼区分"计入 N 的签印"与"AI 的 non-counting 签印"
- 边缘情况：真人对 AI 座位出题质疑 —— 答题者变成程序时，题面与判定流程不得依赖真人语义判断（`certifyAnswer` 现依赖真人），v1 需明确该路径走哪条兜底（**这是 Ask 1 之外最大的未验证机制点**）
- 空状态：AI 是唯一可被质疑对象时 —— 不允许"无靶子"死锁

**设计触点**：签印面板（`page-phone-sign` / `/#cert/progress`）、质疑出题屏、认证证人席（`/#cert/witness`）、复议面板
**关联 Sitemap**：`page-host-cert`、`page-host-cert-progress`、`page-host-cert-witness`、`page-host-seats`
**已生成的设计资产**：主链已有认证相关屏的设计语言（`flow2-certification-climax.tsx` 4 屏、`/#cert*` 4 页），但**均不含程序座位**，属"需扩展"而非"已存在"
**待澄清问题**：`certifyAnswer` 在 AI 被质疑时的机制替代（上面边缘情况）；AI 能否被"作证"；非计数签印的视觉重量。

### Story S4 — 那位朋友迟到了 20 分钟，座位要体面地下桌（P1）

**Job**：现实中"差一个人"常常是迟到，不是缺席；不能交还 = 制造更难看的第二个问题

**In Scope**
- 中途交还：真人在场后把座位从 `ai` 切回 `human`，切换事件落账
- 交还后的成绩归属口径沿用 S2（补位期间不归属本人）
- 交还时刻的桌友告知（同 S2 的公开性要求）

**Out of Scope**
- 交还时撤销 AI 在补位期间造成的历史事件（**明确不做**：认证/对峙/山议/投票都是不可回退的历史事件，这是天凤"托管出牌不可撤销"与王者"本人照罚"共同的行业答案）

**验收标准**
- Given AI 已替该座位做出 N 个动作，When 真人入座，Then 第 N+1 个动作起由真人操作，且前 N 个动作不被回退
- Given 交还发生在认证进行中，When 该座位正被质疑，Then v1 策略 = **等本流程结束再交还**（不得中途换人答题），并明确告知在场者剩余步骤数
- 边缘情况：交还后真人要求"刚才那段不算" → 拒绝，规则书写明理由（不可回退），并给出"下一局归属"的出口
- 空状态：全程无人交还 → 该局按补位局归档，D5 组局兑现率计数有效

**设计触点**：座位面板交还入口、切换确认文案、日志交排行
**已生成的设计资产**：**待生成**
**待澄清问题**：交还是否需要在场者再次确认（S2 是入座要确认，交还呢？）；迟到等待是否有上限。

## §7 Constraints & Risks

**技术约束**（来自 `brief.constraints` + `frame-ai-seat.pressure_test.conditions`）
1. **保留现有引擎与门禁体系**；核心命题「登顶≠胜利」不改。
2. **发布包零增量**：`tools/laya-sidecar/*` 与 `tools/laya-probe/*` 不得进 esbuild/构建链（`docs/预研/2026-11-08-laya-sidecar.md:410`）⇒ 稳座档**刻意不碰模型**，本 PRD 实现物全部落在引擎 + web 侧。
3. **确定性**：固定 seed 复现路径上不得出现模型调用 ⇒ 补位决策器必须是确定性启发式，且 seed 可指定（G4）。
4. **门⑨ 逐字节 + release 100 组逐组全等**：改数值必须显式申报重基线并同步规格 §8；**不重基线、不放宽任何锁、不改判定参数**（B80 纪律原话）。
5. **句子层门禁**：补位座位的称呼必须走 `{leaf}` 占位符 + `termExpander`，不得硬编码中文词；`SENTENCE_WHITELIST 必须恒为空集`——加白名单的顺序是"先改规格写明理由，再改这里"。
6. **tests/ 不得被 web/engine 引用** ⇒ `FacePolicy`（现覆盖 3/7 决策面）不能直接提产品，须在新位置重写等价物。
7. **`advanceAuto` 不可复用**：它替玩家决策，文件头自述"人类玩家不该用这个"，与补位语义相反。
8. **工作量口径**：规格 `:1055` 理由 2「五决策面 ≈ 半个 B3」**仍然有效**，本 PRD 按此立项，不按"加个小功能"排期。

**设计约束（不可妥协）**

**数据与隐私**
- 不引入任何外部分析 SDK；数据只在浏览器 `localStorage` 与用户主动导出的 JSON 内。

## §8 Release Approach

**推荐顺序（先假设测试，不是先完整度）**

1. **S1 的"哑 AI 最小可玩切片"**（P0，⭐）——只做到"能自己把 6 人局跑完、无人代操作"，**不做标识、不做交还、不做认证参与**。理由：S1 是唯一能一次回答两个决定性问题的载体——① 补位到底救不救得了局（Value）② "AI 不够聪明"到底是不是问题。若启发式哑 AI 就够用，整个技术路线缩到引擎侧，sidecar 三条红线这辈子不用重开。
2. **S5 的最小埋点集**（P0，与 S1 同批）——只需 4 项：`game_start`(seed+aiSeat) / `seat_control_assigned` / `human_takeover_click` / `导出扩字段`。**没有这 4 项，第 3 步的实拍局测不出东西**。
3. **B 组对照跑法**（P0）——"按 5 人档开局"作为开局屏显式选项存在（S2 的 AC），因为它是对照组，不是备胎。
4. **S2 标识与授权**（P0）——在实拍局**之前**完成，因为"被塞一个 AI"会直接污染社会半边的观测。
5. **S3 认证参与**（P0，依赖 G1）——拍板后做，做前不写。
6. **S4 交还**（P1）——真实场景第二常见，但不阻塞假设验证。

**MVP 定义**（能交付价值 + 能验核心假设的最小集）：`S1 哑 AI 切片 + S5 最小埋点 + B 组选项 + S2 标识授权`。**能验证核心假设吗？能**——这套组合恰好就是"5 真人 + 1 启发式程序座位"那场实拍局的运行条件；样本量按 Ask 1=A 的判读规则为 **6 局（3A+3B），若增益 ≤0 追加 2 局 A′ ⇒ 最多 8 局**。

**Phase 2（本版故意不做）**：`点名/有戏`（发言层，前置=恩怨计数地基）、半桌与全 AI 局、Host 多端与引擎接线、sidecar 接入。

> **批次编号更正（覆盖我先前写错的句子）**：编号法已定 **B81=棋盘正文、B82=模型批（certify 接入）、B83=调平衡**，三者**均已分配**；补位批次**不挤占 B82**，而是另取顺延号（B84+，由签字人定）。并且因为 Ask 2=yes（稳座不碰模型），补位与 B82 **互不依赖、可并行**。本批的**发现类**产出（守卫前提依赖源行尾等）按规矩登记为 **`L-B80-n（收口后补登）`** 进 B80 执行记录 §14.2，**不得借用在编批次号**。


**上线考虑**

- **上线前须通知谁**：唯一签字人本人——**Ask 3（规格 §7 `:1055` 与 Brief `out_of_scope` 第 4 条的口径改写）必须在开工前完成**，否则规则书与规格会说谎，`doc-sync` 门禁判红。无客服/法务/团队，但有**那 5 位朋友**：需要他们承诺一晚（Pitch Ask 4）。
- **是否 soft launch**：是，且形态明确——**v1 不发玩家版，只发实拍局版**：B85 独立实拍页已就绪，Ask 4 = `ready_to_schedule`，待用户确定日期与 5 位真人参与者；先在 1–2 场真实缺人局里跑，通过 NSM ≥ +1.0 与 D2 = 0 两条硬线后再考虑随包发布。**实拍页不是生产功能；Ask 5 的生产开关仍未拍板、未实现。** 增益 ≤ 0 即关闭方向。
- **上线后头 2 周监测什么**：① `human_takeover_click` 是否真的为 0（判体验生死）② `ai_forfeit` 超时占比 ≤ 15% ③ AI 认证参与 ≥ 1/局 ④ 每局"桌友指出异常并被归类"≥ 1 次（防"黑箱式零代操作"）⑤ 门⑨ 与 release 100 组一致性（若动了数值则查是否已申报重基线）。
- **作废条件（不是"没达标"，是"结论不可信"）**：导出缺 seed 或缺 log ⇒ 该局作废；Ask 1 未拍而写入 `ai_participated` ⇒ A/B 分组失效；用实时面板自动计入同频 ⇒ NSM 作废。

## 三、新增条款正文草案：**§7.5 补位稳座（V1 交付）**

建议插在 §7 末尾（现文 `:1069` 之后、`---` 与「## 8. 规模自适应」之前）。

```
### 7.5 补位稳座（V1 交付 · v2.2 新增）

**定义**：真人在场、仅缺席其中一座时，由**程序座位**顶替该缺席者完整参与对局。它**不是**陪练、**不是**单人模式：判据是"桌上 ≥5 名真人"。

**KPI（唯一验收目标）**：**不塌** = ① 动作永远合法（非法动作率 0）② 不卡轮（不出现"等人"，墙钟耗时 ≤ 同局人类手番中位）③ 不冷场（不得要求任何真人代为抽/选/弃/结算）。**明确不追求强度**，故不接入语言模型。

**硬约束**：

| # | 约束 | 出处 / 依据 |
|---|---|---|
| C1 | **≥5 名真人**方可启用；1–3 真人的半桌与全 AI 局**不在本节范围** | §7 范围裁定理由 1、3（v2.2 处置） |
| C2 | **在场者授权**：入座需在场真人同意，**任一在场者可否决**；能力做成开局**可 ban 开关** | 行业范式（在场者三选弹窗 / Charterstone 可 ban） |
| C3 | **公开、不可关闭、全桌一致**的程序座位标识；**不得仅靠颜色或星号传达** | 静默接管已被证伪；主链走查同类缺陷（待认证以颜色传达）已登记未修，不得重演 |
| C4 | **零隐藏状态**：程序座位的内部状态只保留会影响他人的字段；模型/策略一律**只见公开信息** | 既有预研红线 + 自动机空壳原则 |
| C5 | **手番开销上限**：≤3 步即时结算，无收入阶段、无个人版图、复用本体既有动作图标与动作键；**每个动作带三级降级链（主选→次选→兜底重抽）**，非法目标不得进入决策集 | 消灭"AI 卡住"这一最致命失败态 |
| C6 | **签印权（v2.2 裁定 = A）**：程序座位**不计入认证门槛 N**、**不持有活人席**；真人对其发起签印操作时**必须给出机制原因**（不得静默无效） | 机器人替"这是活人"作保 = 主题空转；且选 A 使 `engine/scales.ts` **不改** ⇒ **无需重基线** |
| C7 | **两态分离**：`seat_offline_temporary`（真人已绑定座位、仅链路未同步 ⇒ **不把缺席当弃权**，代决仅在超时 ≥120s 后开放且须落代操作记录）与 `seat_filled_by_ai`（开局即程序占据 ⇒ 永不索取真人操作，超时 120s 执行保守兜底，无合法招记 `ai_forfeit`）。两态必须由 `Player.controlledBy` 可区分 | 与 §edge 既有「不把缺席当成弃权」条款的关系在此厘清：两者描述不同状态 |
| C8 | **成绩归属**：补位期间的动作与结果**不归属缺席本人**；补位期间产生的认证/山议/对峙/投票属**不可回退历史事件**，交还不撤销 | 切断"不如让 AI 替我打"套利；不可回退是流程性质而非实现选择 |
| C9 | **确定性与发布包不受影响**：决策器为确定性启发式，**零模型调用** ⇒ 固定 seed 复现路径不变、门⑨ 冒烟与 release 基线**原样有效**、离线单 HTML 包零增量成立 | §7 范围裁定理由 2 的成本口径 + sidecar 三条红线 |
| C10 | **不承担教学职责**（归 §6.6），**不引入新规则**：程序座位只能使用真人在同一局面下可枚举的动作集（「AI 能做的玩家都能做」，§7 首条） | 与 §7 接口契约同源，避免第二套规则 |

**验收判据（v2.2）**：真人代操作次数 = 0（底线，任一 >0 即判体验失败并暂停平衡讨论）；非法动作率 = 0；程序座位每局被真人牵入认证/山议/对峙 ≥1 次（否则为"隐形座位"，本节未达成）；位次极差与试炼通过率**沿用现有阈值不放宽**（8pp / 14pp / RMS 6.5pp / `TRIAL_PASS_RANGES`）。

**开放项（须显式登记，不得默认）**：`certifyAnswer` 的题面依赖真人语义判断 ⇒ **当程序座位成为被质疑者/答题者时的机制替代**尚未定；在替代方案确定前，C6 的"不得静默无效"即为该路径的唯一防线。
```

## P0 ⭐ 优先（关键假设三支柱）

### #2 大林这伙熬过 50 分钟爬山铺垫，没人掏手机干坐

- **Persona**：大林，31 岁，朋友圈的「聚会局长」，常组织 6–8 人面对面聚会，要的是名场面与整活，策略是次要的
- **JTBD**：当聚会进入爬山竞速铺垫时，大林想要整伙人一直有事干、不冷场，从而大家熬得到后面的认证高潮。
- **关联策略维度**：交互设计
- **优先级**：P0
- **关键假设标记**：⭐（关键假设#1）
- **旅程锚点**：stage2 流失风险①

**Story 主体**：

作为大林，
大林想要爬山铺垫阶段每个朋友都持续参与、不掏手机不干坐，
从而整伙人能熬到认证高潮，而不是没玩到精彩就先冷场。

**这个 Story 在用户那一侧长什么样**：

大林开局后最怕的就是前 50 分钟：大家低头爬山、算资源，有人开始刷手机，被放逐的干脆干坐。他希望这段时间里每个人手上都有事做、桌上一直有动静，抬头一看没人掉线，心里踏实——「再爬一会儿就到重头戏了」。

**这个 Story 算完成的标准**（可观察、可验证）：

- 大林能看到铺垫期每个朋友手上都有可做的动作（打牌/试炼/山议），没人长时间干等
- 大林这伙在铺垫期人均掏手机/走神少于 2 次（待真人局观察校准）
- 大林能在铺垫里就感到「认证快要来了」的预热，而不是无穷爬山

**设计触点**（让 Flow Web/Mobile 直接消费）：

- 涉及屏：山道版图 / 关隘试炼面板 / 山议投票面板 / 数字轨状态屏
- 涉及组件：回合进度条 / 行动手牌列表 / 试炼选择 Modal / 状态 Toast
- 涉及状态：初始 / 进行中 / 等待他人 / 被放逐
- 涉及交互模式：form-flow / 回合制状态机 / picker

**测试的假设**：

关键假设#1——聚会整活型玩家愿为 ~10min 高潮忍受 ~60min 铺垫。本 Story 直接测「铺垫是否可熬」。

**我的诚实看法**：

这是整局的命门。铺垫压不轻，后面认证再精彩也救不回冷场的前半局——但「轻」不等于「短」，砍掉策略深度会同时杀掉名场面的重量，平衡点只能靠真人局找。

**参考产品**：

剧本杀用「分幕推进 + 每幕小高潮」控制节奏；本 Story 借鉴「铺垫里埋预热」，但保留策略深度而非纯叙事。

### #4 阿哲登顶被全桌当场验明「是活人」，产出整局名场面

- **Persona**：大林，31 岁，朋友圈的「聚会局长」，常组织 6–8 人面对面聚会，要的是名场面与整活，策略是次要的
- **JTBD**：当阿哲登顶触发认证时，大林想要他被全桌当场验明「是活人」，从而产出一个全桌同频、事后反复回味的名场面。
- **关联策略维度**：情感化设计
- **优先级**：P0
- **关键假设标记**：⭐（关键假设#1）
- **旅程锚点**：stage4 满意峰值

**Story 主体**：

作为大林，
大林想要登顶的阿哲被全桌当场出题、作证、判定「是不是活人」，
从而整桌注意力 100% 集中在这一个现场表演时刻，产出他这个局长最想要的名场面。

**这个 Story 在用户那一侧长什么样**：

阿哲爬到峰顶那一刻，大林希望全桌「唰」地都看过来——有人出题整他、有人作证、他现场接招答题。这几分钟里没人看手机，全桌笑成一片或屏息判定。大林要的就是这个「这瞬间值了」的时刻。

**这个 Story 算完成的标准**（可观察、可验证）：

- 大林能看到认证开始时全桌视线都转向答题者（全桌投入）
- 大林这伙在认证段出现笑/起哄/主动参与（出题/作证/复议）
- 大林事后能说出「这一局最记得的就是认证那段」

**设计触点**（让 Flow Web/Mobile 直接消费）：

- 涉及屏：认证面板 / 质疑出题屏 / 签印面板 / 峰顶待认证标记
- 涉及组件：答题计时器 / 签印按钮 / 作证列表 / 复议投票 Modal
- 涉及状态：待认证 / 答题中 / 签印达标 / 判定成功
- 涉及交互模式：现场表演 / 三方判定 / picker

**测试的假设**：

关键假设#1 的高潮侧——~10min 现场认证是否真的产出值得等待的名场面。

**我的诚实看法**：

名场面不能靠规则「保证」，只能靠规则「留出空间」。三方判定（出题/作证/复议）的张力是火花来源，设计能做的是别让流程把它磨平。

**参考产品**：

狼人杀/阿瓦隆的「当众辩护」时刻有强社交张力，但常伴随出局冷场；本 Story 要张力不要冷场。

### #6 贡献最精彩名场面的阿哲赢了整局，不觉得白演

- **Persona**：大林，31 岁，朋友圈的「聚会局长」，常组织 6–8 人面对面聚会，要的是名场面与整活，策略是次要的
- **JTBD**：当认证高潮结束进入结算时，大林想要贡献最精彩名场面的人赢下整局，从而大家觉得「名场面即胜利」，而不是白演了。
- **关联策略维度**：情感化设计
- **优先级**：P0
- **关键假设标记**：⭐（关键假设#4）
- **旅程锚点**：stage5 流失风险②

**Story 主体**：

作为大林，
大林想要刚才表演最精彩的阿哲在结算时赢下整局，
从而全桌觉得「最精彩的人就该赢」，高潮的意义不被终局排名消解。

**这个 Story 在用户那一侧长什么样**：

认证那段阿哲最出彩，大林最怕结算时他反而输了——那阿哲一句「我刚才图啥」就把整局气氛打没。大林希望结算公示时，名场面贡献者站到赢家位置，大家心服口服「这局就该他赢」。

**这个 Story 算完成的标准**（可观察、可验证）：

- 大林能看到结算排名里名场面贡献者排在前列（席位 + 距峰顶综合）
- 大林这伙在结算时出现「虽败犹荣/实至名归」而非「白演了」的反应（待真人局观察）
- 大林能理解「为什么他赢」——席位权重 + 距峰顶格数公示清楚

**设计触点**（让 Flow Web/Mobile 直接消费）：

- 涉及屏：结算面板 / 活人席计分 / 排名公示 / 距峰顶格数
- 涉及组件：排名列表 / 得分明细 Toast / 胜者高亮
- 涉及状态：结算中 / 排名公示 / 平局加判
- 涉及交互模式：计分公示 / reveal

**测试的假设**：

关键假设#4——终局公式须保障名场面即胜利叙事（早期取席者需爬回 11+ 格才赢，否则高潮白演）。

**我的诚实看法**：

这条和引擎平衡死死绑定：seatWeight 必须小于山道长度才不让先到者独占，但太小又会让名场面者赢不了。已有回归测试钉住逐档权重，但「名场面者实际赢不赢」仍要真人局验证，不是公式算出来就算数。

### #1 大林首局把规则讲明白，朋友没开局就冷场

- **Persona**：大林，31 岁，朋友圈的「聚会局长」，常组织 6–8 人面对面聚会，要的是名场面与整活，策略是次要的
- **JTBD**：当第一次带朋友开局时，大林想把规则讲得让人听得进去，从而没人开局就被规则劝退、冷场。
- **关联策略维度**：用户引导
- **优先级**：P1
- **关键假设标记**：—
- **旅程锚点**：stage1 开场

**Story 主体**：

作为大林，
大林想要用渐进的方式把规则教给第一次玩的朋友，
从而大家快速进入状态，而不是开局就被一堆规则劝退。

**这个 Story 在用户那一侧长什么样**：

大林最怕开局摊开规则书讲半小时，朋友眼神已经散了。他希望先玩起来、遇到关隘再学认证、价值前置，朋友边玩边懂「哦原来登顶还需要被验活人」，而不是先啃完说明书。

**这个 Story 算完成的标准**（可观察、可验证）：

- 大林能在首局用「边玩边学」而非「先讲完规则」开局
- 大林的朋友在第一道关隘试炼时就预热到「认证」概念
- 大林首局没有因为规则讲解而出现长时间冷场

**设计触点**（让 Flow Web/Mobile 直接消费）：

- 涉及屏：首局教学页 / 关隘试炼面板 / 规则渐进披露提示
- 涉及组件：教学 Coachmark / 渐进披露 Modal / 新手模式开关
- 涉及状态：首局教学 / 渐进披露 / 新手模式
- 涉及交互模式：onboarding / 渐进披露

**测试的假设**：

n/a（usability 使能项，非关键假设）

**我的诚实看法**：

规则渐进披露说起来容易，做起来要重新编排「什么时候揭示什么」——把认证概念前置到关隘试炼是个好钩子，但别为了前置而剧透了高潮的惊喜。

### #3 被放逐的大刘出局后仍有参与感，不干坐冷场

- **Persona**：大林，31 岁，朋友圈的「聚会局长」，常组织 6–8 人面对面聚会，要的是名场面与整活，策略是次要的
- **JTBD**：当大刘被山议放逐时，大林想要他出局后仍有事干，从而整桌不冷场、自己这个局长不失职。
- **关联策略维度**：交互设计
- **优先级**：P1
- **关键假设标记**：⭐（关键假设#3）
- **旅程锚点**：stage2 出局

**Story 主体**：

作为大林，
大林想要被放逐的大刘出局后还能参与（作证/复议/围观判定），
从而没人干坐冷场，不重演狼人杀「被首杀干坐」的痛点。

**这个 Story 在用户那一侧长什么样**：

大刘被放逐那一刻，大林心里一紧——别又是狼人杀那种「出局就玩手机」的冷场。他希望大刘还能在认证里当证人、参与复议，甚至有个「旁观者」角色的事干，人还在局里。

- 大林这伙没有因为有人出局而出现明显冷场
- 大刘出局后 30+ 分钟仍在看局/参与（待真人局观察）

**设计触点**（让 Flow Web/Mobile 直接消费）：

- 涉及屏：放逐公示 / 认证证人席 / 复议投票面板
- 涉及组件：出局状态标记 / 证人邀请 Toast / 旁观者面板

### #5 小六质疑时全桌都出题/作证/复议，名场面不止 1–2 次

- **Persona**：大林，31 岁，朋友圈的「聚会局长」，常组织 6–8 人面对面聚会，要的是名场面与整活，策略是次要的
- **JTBD**：当小六质疑阿哲时，大林想要全桌都参与出题/作证/复议，从而名场面密度够高、不止集中在 1–2 次质疑。
- **关联策略维度**：情感化设计
- **优先级**：P1
- **关键假设标记**：⭐（关键假设#2）
- **旅程锚点**：stage4 密度

**Story 主体**：

作为大林，
大林想要认证时全桌都抢着出题、作证、复议，
从而一局里出现多个全桌同频的名场面，而不是只有 1–2 次质疑撑场。

**这个 Story 在用户那一侧长什么样**：

大林发现签印门槛 N=4 时多数人觉得「反正不用我签」就没成本地旁观，表演全集中在小六那 1–2 次质疑。他希望门槛降下来、每个人都有参与的理由，整局名场面一个接一个，单局至少 3 次全桌注意力集中。

**这个 Story 算完成的标准**（可观察、可验证）：

- 大林能看到一局里全桌注意力 100% 集中的时刻 ≥ 3 次
- 大林这伙多数人都主动出题/作证/复议，而非只 1–2 人表演
- 大林感到名场面「有重量」，不是闹完就忘

**设计触点**（让 Flow Web/Mobile 直接消费）：

- 涉及屏：认证面板 / 签印门槛公示 / 质疑出题屏 / 复议面板
- 涉及组件：签印进度 / 参与激励 Toast / 出题轮转 picker
- 涉及状态：签印中 / 门槛达标 / 多人参与
- 涉及交互模式：三方判定 / 轮转 picker

**测试的假设**：

关键假设#2——名场面密度（门槛 N=4 致多数人无成本签印，表演集中 1–2 次）。

**我的诚实看法**：

降签印门槛能提密度，但降太多会让认证变成「走过场盖章」，名场面反而贬值。密度和重量是一对张力，得在真人局里找那个「既多人参与、又每次都有戏」的门槛。

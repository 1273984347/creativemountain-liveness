# B9 — 规模与平衡（执行记录）

## 1. 目标与验收

规格 §9.2 / 实施计划 §10.1：1000 局模拟全绿（零异常、无死循环、无非法状态、无局超出全局回合上限）；
兜底触发率 < 15%；各身份/阵营胜率偏离 > 15pp 的项记录在案并讨论。
**验收口径由用户裁定**：4 套主题都跑（每套 3–8 人全档位，每档 1000 局，合计 24000 局）。

## 3. 模拟框架设计

- **确定性**：一切随机取自 state.rng，seed = f(主题 id, 人数, 局号) ⇒ 同参数同结果可复现。
  ⚠️ seed **必须含主题 id**：否则四套主题共用同一条随机轨迹，统计上是「同一条轨迹的 4 份拷贝」（实测数据完全相同）。
- **走真实引擎**：performAction / advanceTurn / 山议投票 / 签印 / 质疑 / 判定 / 复议 / 复议投票，与玩家对局同规则。
- **AI 策略**：行棋 75% · 问天 10% · 行事 15%（行事时选第一张可支付的牌，攻击牌随机选目标）；
  待认证者锁定位移但仍可打非位移牌。
- **异常即红**：死循环、非法状态（体力/资源/位置/护盾/手牌上限）、引擎兜底失效、超过全局回合上限 ⇒ 计入异常。

## 4. 模拟暴露的三个引擎缺陷（B2–B7 全绿，从未被单测覆盖）

### 4.1 `isRoundEnd` 提前一轮结束 ⇒ 每人少一个手番

- `turnIndex` 的语义是「**已行动**的手番数」，而原判据 `turnIndex >= aliveCount - 1` 提前一轮 ⇒
  3 人局每 round 只有 2 人能行动，**第三人永远轮不到**（实测座 2 全程位置 0）⇒ 无人登顶 ⇒ 兜底率 100%。
- 单测没抓到：它直接断言 `isRoundEnd` 的返回值，而没断言「一个 round 内每个存活玩家各行动一次」。

### 4.2 移动到峰顶只设 `pendingCert`，**没进认证流程**

- registry 的 4 个位移算子到达峰顶时只写 `pendingCert = true`，**没有调用 `enterPendingCertification`**
  ⇒ `certification.pending` 始终为空 ⇒ 认证流程永不启动 ⇒ 兜底率 100%。
- 单测没抓到：认证相关单测**直接调 `enterPendingCertification`** 测流程，
  而没有测「移动到峰顶是否真的进入流程」——典型的**集成缺口**（入口未被调用，流程本身却是对的）。

### 4.3 认证轮次时序：登顶当轮就消耗掉第 1 轮

- 待认证者在某个**手番末**登顶；若同一 round 末就判定第 1 轮，认证人还没来得及签印 ⇒
  第 1 轮必然空转 ⇒ 登顶几乎必然失败。
- 修法：`certification.round === 0` 表示「第 1 轮尚未开始」；登顶当轮只**开启**第 1 轮，
  接下来**整轮**供认证人签印。

### 4.4 修完后的效果

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 兜底触发率 | 97.5% | **0.9%** |
| 认证达成局数（24000 局） | 约 960 | **23772** |
| 异常条数 | 111（手牌超上限） | **0** |
| 平均回合数 | 18.4 | 12.5 |

## 5. 顺带修掉的三处一致性问题

| 问题 | 修法 |
|---|---|
| 天机牌发的牌在手番间让手牌短暂超上限 | 发完立即裁牌 |
| 棋盘固定 28 格，与规模表 boardLength（24–36）不一致 | installTheme 按 scales.boardLength 适配棋盘（峰顶恒在末格） |
| 攻击牌的 target: 0 是「座位 0」⇒ 每张攻击牌只能打同一个人 | performAction 支持 payload.target 并递归改写效果树；UI 暂自动选位置最高的对手（B10 改手动点选） |

## 6. 平衡结论

- **验收口径全部达标**：异常 0 · 兜底率 0.9% · 身份/阵营胜率偏离均 ≤ 15pp。
- **四套主题的平衡一致**：兜底率、平均回合、胜率分布几乎重合（< 1pp）——与 §10.1「复用通用卡牌池」的设计一致。
- **但记录一项结构性问题**：身份/阵营按**座位轮转**分配 ⇒ 胜率沿座位顺序**严格单调递减**
（座 0 的 22.4% → 座 7 的 1.7%）⇒ 差异反映的是**座位顺序优势**而非身份/阵营强度。
  单项偏差被摊薄后未触发 15pp 记录线，属阈值与结构性问题之间的盲区，已在报告「分析与讨论」中记录并给出 V1.1 建议。

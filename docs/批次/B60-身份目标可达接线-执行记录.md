## 3. 关键裁定（9 项）

| # | 争议点 | 裁定 | 理由 |
|---|---|---|---|
| 1 | 计数写在哪？ | 与**通过标记**同处落地（`markGatePassed`） | `gate_<index>` 标记全仓**只有两个写入点**（付费通道 `payGate`、统一通过点 `passGate`）⇒ 「写通过标记」与「通过关隘」是同一件事 ⇒ 计数与标记同处 ⇒ 两者不会漂移 |
| 2 | 「通过关隘数」按次数还是按不同关隘数？ | 按**同一口径**：标记幂等 ⇒ 同一关隘只计一次 | §3.5「已通过关隘的格不再触发关隘」⇒ 次数与不同关隘数天然等价；幂等是**兜底**（防将来新增通道重复计） |
| 3 | 目标从哪来？ | 开局分配身份时**派生**到 `player.flags.goal` | State **不持有主题包引用**（§6.2 契约冻结）⇒ 派生是唯一不改契约的路；与既有先例 `flags.passive` 同型；且 `advanceRound` **不清 flags** ⇒ 整局有效 |
| 4 | 判定点放哪？ | 回合末，**山议开启之后、认证之前** | 认证前 ⇒ 本回合达成者**本回合认证就享受**门槛减半 ⇒ 印记不是「下回合才有用」的空头奖励。⚠️ **山议在此只是「开启」**（`openCouncil` ⇒ `council.resolved=false`），**放逐发生在其后** ⇒ 判定时玩家尚未出局 ⇒ 印记作废须由**放逐侧**负责（§5.6，见裁定 #7） |
| 5 | 判定时机怎么定？ | 由 `GOALS[kind].timing` 驱动（**不另立一张表**） | 唯一事实源；`round_end` → 回合末、`terminal` → 终局判定 |
| 6 | `survive_with_hp` 怎么办？ | 按规格**字面**实现（终局判定时发印记），张力**如实登记** | 规格 §6.4 表明写「终局判定时一次性检查」；擅自改成回合末会改语义 ⇒ 按字面执行 + 登记张力（见 §7 T2） |
| 7 | 出局者 / 已持印记者？ | 判定时**已出局者跳过**；**放逐时清 `hasMark`**（§5.6 印记作废）；已持印记者跳过且不重复记日志 | §5.6「被放逐者……其身上的印记作废」**由放逐侧实现**（回合末判定时放逐尚未发生 ⇒ 只有放逐能收掉它）；§4.1「印记不叠加」⇒ 不重复发、不重复记日志（否则日志随回合数无界增长） |
| 8 | 缺目标信息怎么办？ | **跳过判定**（返回 null），不当成「未达成」 | 未装主题的测试局面没有 `flags.goal`；若当成未达成再发印记 ⇒ **凭空造出奖励** |
| 9 | 「目标达成」怎么统计？ | 由**引擎判定器直判**（`isGoalAchieved`），「持有印记」**单列** | 「达成过」是**历史事实**（不该被之后的放逐抹掉）⇒ 两个口径分开列；判定器与引擎**同源**（单一事实源），不另写一份判据 |

## 6. 复盘与经验沉淀

- **「判定器存在」≠「判定被调用」**：G-c 把不可达归因于「计数器无写入方」，而实测**还有两环缺失**（判定无调用点、印记无写方）⇒ 只补写入方等于没修。⇒ 登记机制不可达必须**顺着整条链逐环核实**（E108）。
- **变异自证的文本判据会被 reporter 格式骗**：测试内 spawn 的子进程自动切 TAP reporter ⇒ 失败消息不在输出里（E109）；且**副本必须含被 mutant 影响的测试文件及其 import 依赖**，否则 mutant 静默无效 ⇒ 变异自证变成**恒绿的假证明**。
- **派生数据要有明确归属**：身份目标是「本局派生量」而非「玩家临时标记」⇒ 落进 `flags` 之前先看既有断言怎么读它（E110）。
- **跨项目通用结论已写入**：`docs/沉淀/经验教训索引.md` **E108 / E109 / E110**；Agent Memory 同批沉淀 3 条。
- **行尾是逐文件不一样的**（`core.autocrlf=true` 且无 `.gitattributes`）：本批实测 `engine/core/turn-runner.ts` 是 **CRLF**、而 `gate.ts`/`setup.ts`/`victory.ts` 是 **LF** ⇒ 编辑前**逐文件探测行尾**、`old_string` 按该文件的行尾给 ⇒ 否则要么匹配失败，要么整文件行尾漂移（巨型 diff）。提交后工作树会被 git 转成 CRLF ⇒ **下一批开工须重新探测**。
- **「缺陷登记的归因」是待核实的假设，不是事实**：G-c 把「目标不可达」归因于「计数器无写入方」，实测**还有两环缺失**（判定器在生产零调用点、奖励的写方不存在）⇒ 只补写入方等于没修 ⇒ 登记里的因果链必须**逐环查证**（E108）。
- **盲审抓到了「我自己的论证前提失实」**：我写「山议之后判定 ⇒ 出局者不发印记」，实测**山议在此只是「开启」**、放逐发生在其后 ⇒ 结论错、但**代码恰好是对的**（判定时若已出局则跳过）⇒ **注释与批次记录里的「理由」也是交付物**，机器判据查不出来（测试全绿）。

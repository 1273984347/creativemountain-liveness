## 3. 实体件术语化（此前全部硬编码仙侠词）

基准仙侠的「灵枢 / 符箓 / 灵力 / 山道 / 峰顶 / 关隘 / 福地 / 险径…」曾被**硬编码**在
实体件模板、规则书表头、IR 指令表里 ⇒ 其余三套主题的实体件会整本串戏。

修法：

1. 主题包的 glossary 补齐**地形与路径词**（plain / boon / hazard / rift / branch / gate / path / player）；
2. 所有模板改为读 glossary（`print-parts.ts` 新增 `term()` 辅助）；
3. 规则书叙述改为**一份模板 + 占位符**，构建时替换 ⇒ 不必维护四份会漂移的叙述。

## 4. 新增门禁判据：跨主题术语串戏

第 ⑧ 门新增 `checkTerminologyLeak`：某套主题的**任何文本**里出现别套主题的术语词 ⇒ 判红。
首跑即抓到两处真串戏（融合主题写「灵枢 / 符箓库」，而它的资源词是「灵能」、牌词是「道箓」），已修。

## 6. 收尾项

### 6.1 出牌目标手动点选（B10 末项，已完成）

**问题**：主题包里攻击牌的目标写成 target: 0 —— 那只是**占位**。
引擎照字面执行 ⇒ 每张攻击牌都只能打「座位 0」（同一个人），本地多人下等于攻击牌作废。

**实现**（三层）：

| 层 | 文件 | 内容 |
|---|---|---|
| 判据（纯函数） | engine/core/targeting.ts | effectNeedsTarget / cardNeedsTarget / targetCandidates / resolveTargetPick |
| 引擎 | engine/core/turn-runner.ts | 已有 retarget（递归改写效果树里的目标）；**新增保护**：需要目标却未指定 target ⇒ **不出牌**（不误伤占位座位 0） |
| UI | web/main.ts + web/ui/hand.ts + styles.css | 点攻击牌 ⇒ 进入选目标模式（提示 + 卡片高亮 + 玩家行高亮可点）⇒ 点一名对手出牌；点自己或再次点该牌取消 |

**回归测试**（tests/engine/targeting.test.ts，13 条）：

- 纯函数：带/不带 target 的效果、嵌套在 sequence / conditional / count 里的识别、可选目标集合、点选解析（合法 / 点自己 / 未选 / 卡不在手牌）
- 引擎集成：performAction 带 target ⇒ 伤害落到**该座位**（不是占位座位 0）；同一张牌打不同目标 ⇒ 伤害落到不同的人
- 回归防线：需要目标却未指定 ⇒ **不出牌、无人掉血**；四套主题的所有攻击牌都能被 cardNeedsTarget 识别

**浏览器实跑**：点「蚀骨」⇒ 出现「选择目标」提示 ⇒ 点座 1 ⇒ 座 1 体力 8/8 → 7/8 且带 poison 1，
座 2 / 座 3 未受影响 ⇒ 目标点选真实生效。


`node tools/gate.mjs` → **9 门全绿**；parity-check 对 4 套主题各做四级比对全部通过。

### 6.2 extra_vote / extra_roll 的读取逻辑（B10 末项，已完成）

**问题**：两个算子**只写不读**——

- extra_vote 写 flags.extraVotes，但山议计票硬编码 identityId === 'arbiter' ? 2 : 1 ⇒
  任何**其他**拿到 extra_vote 的玩家都无效；
- extra_roll 写 State.extraRolls，但行棋从不读它 ⇒ 掷骰机会等于不存在。

**规格自身的矛盾**：卡面写「本回合额外获得 1 次掷骰机会」，而规格 §3.1 步骤 2 写
「每人每回合**仅一次行动**」⇒ 机会在同一回合内无处可用。**B10 裁定**：
「额外掷骰机会」= **下次行棋时多掷一次移动骰，取最高点**，机会在行棋时消费、用完即清零；
卡面文案与规格 §3.1 同步改述。

**实现**：

| 层 | 文件 | 内容 |
|---|---|---|
| 常驻型被动 | engine/core/passives.ts（新） | grantedFlags：识别被动里的 extra_vote（含 sequence / conditional / count 嵌套） |
| 授予 | engine/core/setup.ts | 分配身份时授予 flags.extraVotes；**并修正顺序**（先重置局面、再分配身份，否则授予的 flags 会被重置抹掉） |
| 读取 | engine/core/council.ts | voteWeight = 1 + flags.extraVotes（替换硬编码 arbiter） |
| 读取 | engine/ops/registry.ts | move_by_dice：extraRolls > 0 时多掷一次移动骰、**取最高点**，机会用完清零 |

**回归测试**（tests/engine/passives.test.ts，9 条）：grantedFlags 识别（含嵌套）· 仲裁者获授 / 普通人没有 ·
voteWeight 权重 · 山议计票读 extra_vote 且**权重能逆转并列结果** · extra_roll 写入 extraRolls ·
行棋消费机会并清零（日志含「取最高」）· 无机会时只掷一次 · 同 seed 下有机会时前进距离 ≥ 无机会时。

**机制等价**：仲裁者仍是山议 2 票（原硬编码也是 2 票）⇒ 行为不变；
但现在**任何**拿到 extra_vote 的玩家都生效，山议计票从硬编码变为数据驱动。

**平衡影响**：extra_roll 生效后推进更快 ⇒ 24000 局重测，兜底触发率 0.9% → **0.8%**，异常 0。

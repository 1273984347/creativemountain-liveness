# B27 · 余量阈值标定 + 「试炼失败掏空余量」复核

> 批次号 B27 · 日期 2026-11-09 · 主题：消 B26 登记的 **T2** —— 试炼失败 ⇒ 改为付费 ⇒ **掏空余量**；AI 的余量决策需复核与标定。

## 1. 复核：问题有多大

| 项 | 数据 |
| --- | --- |
| 试炼失败中「**掏空余量仍过关**」 | **99.9%**（6000 局：失败 3247 / 仍通过 3243 / 被放行 2） |
| 含义 | 余量规则在**试炼路径上并不保余量** ⇒ 「为保余量而试炼」的结果是「余量照样归零」 |
| 余量 0（= B24 之前的策略） | 试炼每千局 **0.3 次** ⇒ 机制隐形 ⇒ 这正是 B24 要解决的问题 |
| 失败后被放行的比例 | **≈0.1%** ⇒ 「失败 ⇒ 掏空」几乎是唯一结局 |

## 2. 校准：多值扫描（走生产同一条代码路径）

**方法**：把 `GATE_RESOURCE_RESERVE` 改成**可注入**（`advanceAuto(state, mode, { gateReserve })` ⇒ `autoResolveGate(state, seat, reserve)`）
⇒ 扫描不另写模拟器副本；**默认仍是 2**（生产行为不变）。

**命令**：`node tests/sim/run.mjs --scan-reserves 0,1,2,3,4 --games 250`（每取值 6000 局）

## 3. 语义修正 + 可观测

- **引擎常量**写明「选取依据」（命令 + 扫描表 + 取舍理由）⇒ 阈值**可复算**。
- **平衡报告**新增「试炼失败的后果（B27）」小节：失败数 / 失败后仍通过（掏空余量）/ 失败后被放行 ⇒ 把**隐性代价显性化**。
- **门 ⑨** 新增断言「试炼**必须会失败**」⇒ 防挑战型退化为「永远通过」（B26 的老问题复发）。
- **规格 §9.2 / §13.5** 登记：余量阈值的标定依据 + 「余量规则不是省灵枢，而是用试炼博一把」的语义修正。

## 5. 遗留（如实登记）

| # | 现象 | 归属 |
| --- | --- | --- |
| T1 | 余量规则在**试炼路径上不保余量**（99.9% 的失败会掏空） | 若要让余量真正生效，需让「失败 ⇒ 改为付费」在余量不足时改判放行 ⇒ 但那时惩罚更重（失去过关）⇒ 会压低试炼使用率 ⇒ 与 B24 的目标冲突 ⇒ 需单独做设计取舍 |
| T2 | AI 判定逻辑本身**未改** | 在「付得起」区间，失败代价与直接付费相同 ⇒ 试炼是纯增益 ⇒ 现状近似最优；本批只标定阈值并把代价显性化 |
| T3 | 扫描用 6000 局/取值（相对噪声 ~1–2%） | 余量 1 与 2 的差异部分落在噪声内 ⇒ 但两者平衡几乎相同 ⇒ 结论对 1↔3 不敏感 ⇒ 维持 2 稳妥 |

## 6. 复盘

- **把隐性代价显性化**：「余量规则在试炼路径上失效」原本没人能看见 ⇒ 加「失败后果」统计 + 把 99.9% 写进**常量注释**与**规格** ⇒ 以后改策略时不会漏掉这条。
- **扫描要走生产同一条代码路径**：把阈值改成**可注入参数**（默认不变）⇒ 扫描与生产同一份实现 ⇒ 结论可直接落地。
- **校准的结论可以是「维持原值」**：扫描的价值在于**证明**取值合理并留下**可复算依据**（命令 + 数据表 + 取舍理由），而不是必须改值。

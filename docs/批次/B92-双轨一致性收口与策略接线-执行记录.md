## 3. 关键裁定

| # | 争议点 | 裁定 | 理由 |
| --- | --- | --- | --- |
| 1 | 过路费误印改**渲染侧**还是**引擎侧** | 改**渲染侧**（`print-parts.ts` 的判据加 `kind === 'gate'`） | 降级格保留 `gateFee` 是**引擎与 IR 的既有事实**；改引擎会波及 IR / 门 ⑥ / 数字轨 ⇒ 风险外溢。渲染判据改为「与引擎同看 `kind`」⇒ **判据同源**（`engine/core/gate.ts` 亦判 `kind`） |
| 2 | PDF 尺寸目标是多少 | **A3 横向**（不是 A2） | `print-templates.ts` 的 A2 是**SVG 画布**（= A4×4 拼接，可裁 4 张）；**打印页** `PRINT_CSS` 写的是 `@page board { size: A3 landscape }` ⇒ 打印用形态是 A3×1。修法是让 CSS 生效（`preferCSSPageSize: true`），而非改 CSS |
| 3 | certify 策略**接入生产**可行吗 | **原样不可行** ⇒ 本批只做**接线能力**（默认关闭） | B74 测的模型臂依赖**仓外** Laya sidecar（`fetch 127.0.0.1:8711` + 仓外权重，无服务即 SKIP）⇒ CI 上不可能有模型。硬接会把「B74 证明了 Laya 模型有效」偷换成「某个仓内启发式有效」⇒ 结论不能继承 |
| 4 | 「启用策略 + 重标定 ⑨/⑫/⑬」何时做 | 留作后续批次，登记为遗留 | ① 需要仓内可复现的策略或 sidecar 落地；② **重标定会改全部平衡读数** ⇒ 必须与「开拓者削弱」（R8）**分批**做，否则两种效果**不可归因** |
| 5 | README 的过期读数怎么修 | **删掉手抄数值、只指向唯一出处**（`docs/balance-report.md`）⇒ 并加机械守卫 | 根因：报告是入库生成物却**不被任何门读取** ⇒ 重标定后 README 的手抄数字悄悄过期。**手抄就是第二事实源**（E92/E93 同族）⇒ 治本是让数值只有一处 |

## 6. 复盘与经验沉淀

### 6.1 沉淀

- **E153**：**「生成物入库却不被任何门读取」⇒ 它的数值会悄悄过期，而旁边手抄了这些数值的文档会一起过期** —— 本仓 `docs/balance-report.md` 是入库生成物却不被任何一道门读取，于是每次重标定后它更新、而 README「已知限制」段里手抄的 **5+ 处**读数停在旧值（座位极差 1.3pp vs 现 2.8pp 等）⇒ 读者拿到的是过期结论，而**没有任何门会报**。教训：① **同一数值只留一个出处** —— 文档不手抄会漂的读数，改为指向唯一出处；② 手抄读数的文档段配**机械守卫**（断言「不出现 数字+pp/% 形态」，判据**不硬编码旧值**）⇒ 未来任何新的手抄读数都会被抓住；③ 生成物若含会漂的数值，要么**被某道门读取**，要么文档里**只引用不复制**。
- 复用既有教训：**E92 / E93**（同一口径两份实现 / 条数一致≠逐条对应 ⇒ 手抄即第二事实源）· **E139**（回读校验）· **E143**（改完立刻跑）· **E145**（无横向溢出≠没被压扁 ⇒ 本批的目视核对）· **E152**（指针不许空转）。

## 7. 平台侧处置（2026-11-26 推送时）

- **现象**：git push 报 Failed to connect to github.com:443 after 21080 ms；而 api.github.com:443、github.com:80、github.com:22、ssh.github.com:443 **全部连通**，且 hosts 干净、DNS 正常 ⇒ 定位为**该链路 443 的临时阻断**（约 30 分钟后自行恢复）。
- **处置**：改走 GitHub REST 的 git 数据接口等价完成这次 push —— POST /git/blobs → POST /git/trees（带 base_tree）→ POST /git/commits → PATCH /git/refs/heads/main，**逐个重建 3 个台账提交**。
- **正确性取证**：每个提交的 **blob sha 与 tree sha 与本地逐字节一致**（47984e7d / 69d619ce / 8a26c262 / 43db08a4 / b8a89514 / dc209f1e / 7ae5fd1b）⇒ 内容正确**可证**；远端 main 的 tree 与本地 tree 相同 ⇒ 整个仓库内容逐字节一致。
- **副作用与消解**：REST 生成的 commit 对象与本地 git 的**不是同一个**（GitHub 规范化了日期偏移与 message 末尾换行，差异项无法完全枚举 ⇒ 穷举 4 种组合均未复现本地 hash）⇒ 远端 commit hash 与本地不同 ⇒ 本地显示 ahead 3、下次 push 会报 non-fast-forward。**消解**：通道恢复后 git fetch origin && git reset --hard origin/main ⇒ 本地**对齐到平台那个 commit 对象**（工作树内容 sha 不变 ⇒ 安全）⇒ 两边**同一 hash**、历史完整（227a88b / 88de023 / 5eca4dc）。
- **沉淀**：**E154**（通道不可用时的等价 push 手法 + commit 哈希差异的消解）。
- **遗留**：已生成备用 SSH key（~/.ssh/id_ed25519_gh_creativemountain，**尚未加入 GitHub 账号 ⇒ 未生效**）⇒ 若 443 再被阻断，可一次性授权把公钥加到账号（属**账号权限变更**，须点名授权）⇒ 之后 push/fetch 走 SSH，不再受 443 阻断影响。

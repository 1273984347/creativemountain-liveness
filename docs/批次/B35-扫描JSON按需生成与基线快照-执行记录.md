## 3. 为什么这样拆

- **生成物不入库**：扫描 JSON 是**每次重扫都会变**的产物 ⇒ 入库只会制造无意义的 diff 与合并冲突 ⇒ 忽略它。
- **基线要入库**：复核必须有一份**固定**的可复现依据 ⇒ 否则「判定不变」这句话无从对照 ⇒ 快照入库。
- **两者分离** ⇒ 门禁读基线（稳定、毫秒级）⇒ 重扫产出物只用于「与基线对照」的**流程**（不进库）。

## 4. 遗留（如实登记）

| # | 现象 | 归属 |

| T1 | 基线快照是**某一次扫描**的结果 ⇒ 策略改动后它会「过时」 | 这是**有意**的：基线的作用是「判定不变」的对照点；更新基线必须**显式**（更新快照 + 批次记录留痕 + 同步 B31/B34 引用） |

## 5. 复盘

- **生成物与基线要分家**：前者每次变、后者必须固定 ⇒ 混在一处就会出现「要么入库制造 diff，要么不入库失去基线」的两难。
- **门禁读基线、流程读生成物** ⇒ 门禁稳定且毫秒级；重扫时用 `--scan=<path>` 与基线对照，**变更才显式提交**。

# B19-c · 关隘比对的 UI 入口（两段交互）

> 批次号 B19-c · 日期 2026-11-08 · 主题：把 B19 实现的 `COMPARE` 通道**接到玩家手上**（此前引擎、粗筛、UI 判据都就绪，但没有入口 ⇒ 玩家点不到）。

## 1. 实现

| 环节 | 实现 |
| --- | --- |
| 关隘面板 | 新增**「与座N 比牌」按钮**（每个存活对手一个）；**本关已转为付费**时不提供该通道 |
| 第二段 | 选定对手后面板内**渲染手牌**（与对峙面板同款）⇒ 点一张牌即完成比对；另给「取消比对」 |
| 提交路径 | `submitCompare(cardId, target)`：**先过 `uiAllows` 闸** ⇒ 被拒时写 `uiBlockNotice` 的拒因（拒绝不沉默） |
| 状态 | 新增 `ui.pendingCompareTarget`（座位号或 null）；换座 / 开新局 / 提交后均清零 |

## 2. 守护

- 新增**接线用例 R-3**（`legal-probe.test.ts`）：按 `// 门禁:` 锚点取比牌提交区域，断言其含 `uiAllows(` 与 `uiBlockNotice(` ⇒ 将来有人摘掉闸检查**必红**（沿用 R-1/R-2 的锚点法）。
- 门禁 **10/10 全绿**。

## 3. 复盘

- **引擎就绪 ≠ 玩家能用**：B19 交付了 `COMPARE` 的全部机制，但缺入口 ⇒ 功能等于半成品。⇒ 「接线」类任务要单独成批，别混在机制批里（否则容易只做一半）。
- 两段交互的**取消路径**要显式给（文案承诺了可取消，就必须有按钮）⇒ 顺带把「承诺与实现不符」也堵上。

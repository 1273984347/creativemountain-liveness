# B21 · 关隘数与规模表一致（主题包按人数提供多版棋盘数据）

> 批次号 B21 · 日期 2026-11-08 · 主题：修 B20 登记的 **L1** —— 主题包固定 2 座关隘，而规模表 `gateCount` 是 2–4 座。

## 1. 方案

| 环节 | 做法 |
| --- | --- |
| **主题包数据** | 棋盘从 28 格扩到 **36 格**，关隘置于 **6 / 14 / 22 / 30**（间隔 8）⇒ 裁到 24/28/32/36 格时**天然保留前 N 座** |
| **关隘命名** | 三套主题沿用既有关隘名族（科幻「安全闸·壹/贰」、都市「封锁线·壹/贰」、混合「阵门·壹/贰」）⇒ 新增「·叁/·肆」；仙侠用独立地名（朝元关 / 镇岳关） |
| **引擎适配** | `fitBoard` 按**规模表 `gateCount`** 收口：只保留前 N 座关隘，其余**降级为普通格**（名字中性化）⇒ 24/28/32/36 格分别对应 **2/3/3/4 座** |
| **中性名** | 「第 N 段」——⚠️ **不得含任何主题术语**（原用「山道 N」，而「山道」是 hybrid 的术语 ⇒ 门⑧ 判科幻/都市**串戏**） |

## 2. 实测数据

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 主题包棋盘 | 28 格 / **2 座**关隘 | 36 格 / **4 座**关隘（6/14/22/30） |
| 各档实际关隘数 | 恒 2 座（**与规模表不符**） | **2 / 3 / 3 / 4**（与 §8 `gateCount` 一致） |
| 回归测试 | 3 条 | **4 条**（新增「每档关隘数 == 规模表 gateCount」） |
| 门禁 | 10/10 | **10/10** |

## 5. 复盘

- **「数据要给够，引擎再按档位取」**：与其让引擎凭空造关隘（名字/试炼池无来源），不如让主题包**提供足够的关隘**、引擎按 `gateCount` 取前 N 座 ⇒ 数据层保持主导权，规则层只做编排。
- **关隘位置按间隔排（6/14/22/30）**，使「裁到目标格数」天然保留前 N 座 ⇒ 适配规则简单到一行预算，无需按人数分支。
- **中性名也是内容**：中性格会进实体件 ⇒ 含任何主题术语都会被门⑧ 判串戏 ⇒ 中性名必须**完全中性**（「第 N 段」）。

# B26 · 条件型试炼判定加难（`has_card_count`）

> 批次号 B26 · 日期 2026-11-09 · 主题：消 B24 登记的 **T1** —— 非骰子型试炼通过率 **73%–100%** ⇒ 挑战性名存实亡。

## 1. 诊断：根因在谓词表达力

| 观察 | 结论 |
| --- | --- |
| `has_card` 只能判「有没有 ≥1 张」 | 手上有 5–7 张牌、牌池 48 张时**几乎必然命中** |
| 10 张条件型试炼实测通过率 73%–100% | 试炼通道对 AI 而言「风险很低」⇒ 挑战性形同虚设 |
| 引擎只有**单谓词** `conditional` | 连「同色两张」这类条件都**表达不出来** |

⇒ 不是「牌没设计好」，而是**能力缺失**：先补谓词，再改数据。

## 2. 方案

| 环节 | 做法 |
| --- | --- |
| **引擎** | 新增谓词 **`has_card_count{filter, count}`**（「手牌里至少 N 张匹配牌」）⇒ 引擎实现 + 校验器 + 规格谓词清单（doc-sync **C4 双向核对**）三处同步 |
| **主题包** | 10 张条件型试炼按**匹配条件**分档（文本级替换脚本 `docs/沉淀/theme-trial-harden.mjs`）：单色两张 ≈95% / 单类型两张 ≈55% / 类型+颜色两张 ≈20%；`t_wind` / `t_star` **保持骰子型**（保留玩法多样性 + 有解析理论期望） |
| **判据** | 每张牌的**目标通过率区间**登记在 `engine/core/balance.ts`（`TRIAL_PASS_RANGES`，**单一事实源**） |
| **门禁** | 门 ⑪ 从「只测骰子型」升级为「**覆盖全部 12 张**」：骰子型比**解析理论期望**（≤ 10pp），条件型比**目标区间** |

## 5. 遗留（如实登记）

| # | 现象 | 归属 |
| --- | --- | --- |
| T1 | 6 号关的两张单色牌仍达 93–97% ⇒ 该关试炼近乎稳过 | 难度递进的起点；若要更严需提高 count（实测 count=3 的单类型仅 ~10–20% ⇒ 过低）⇒ 留待后续 |
| T2 | 试炼失败 ⇒ 改为付费 ⇒ **掏空余量**，现在更常见 ⇒ AI 的余量决策需复核 | 后续批次可把余量与试炼通过率联动（如「余量够才试炼」） |
| T3 | 新增谓词牵动**纪律测试里的硬编码数量**（15 → 16） | 与 doc-sync C4 的规格清单同步 ⇒ 三处一起改（本批已改） |

## 6. 复盘

- **挑战性受限于谓词表达力**：不是数据没设计好，而是「有 ≥1 张」根本表达不出「要两张」⇒ 先补能力，再改数据。
- **设计判据要与实测对账**：我最初按「6 号 60–90%」拍区间，实测「单色两张」= 97% ⇒ 改按**三档难度**（单色 / 单类型 / 类型+颜色）重新设计匹配条件与区间 ⇒ **区间即难度设计表**。
- **新增引擎能力会牵动纪律测试里的硬编码数量**（谓词数、派生器断言）⇒ 连带 doc-sync C4 的规格清单 ⇒ 三处一起改，别等门禁报错才发现。
- **依赖「某张牌必过 / 必败」的断言必须显式构造手牌**：判定升级为数量型后，靠随机手牌 ⇒ flaky（本批修了两处旧断言）。

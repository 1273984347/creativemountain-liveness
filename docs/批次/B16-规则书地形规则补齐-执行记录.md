# B16 · 规则书地形规则补齐（福地 / 险径 / 裂隙 / 关隘）

> 批次号 B16 · 日期 2026-11-08 · 主题：把规格 §3.4/§3.5 的四类地形规则补进**实体件规则书**，并让「漏没漏」可被机器查出来。

## 1. 目标与范围

- **目标**：规则书覆盖规格 §3.4 的全部地形（福地 / 险径 / 裂隙 / 关隘 + 峰顶），且**章节与要点逐条可校验**。
- **触发**：B13 收口时登记的缺口 ——「规则书缺地形规则」（规格 §3.4 有、实体件叙述里完全没有；回合结构第 3 步只写了「结算落点的地形效果」）。

**本批不做**（显式排除）：

| 项 | 归属 | 理由 |
| --- | --- | --- |
| 关隘 / 裂隙的**引擎接线** | **B14** | 并行会话的 sidecar 续作计划已明确「本批不做关隘接线（B14）」；`payGate`/`drawTrial` 全仓零引用 |
| 险径黑牌的「**失去本回合剩余行动**」 | **B14** | 引擎只扣体力；实现需加 `State` 字段（规格 §6.2 契约冻结 ⇒ 先改规格），与并行会话改 `state.ts` 有冲突风险 |
| 主题包全量差异化 / 实体棋盘按人数多版 | V1.1 其余项 | 另批 |

## 2. 关键裁定（4 项）

| # | 争议点 | 裁定 | 理由 |
| --- | --- | --- | --- |
| 1 | 规则书写「引擎尚未实现」的效果（关隘 / 裂隙 / 失去行动）会不会误导玩家？ | **按规格写全**，差距用**覆盖边界**如实登记 | 规则书是实体轨规则文本，实体玩法本就该完整；数字轨的欠实现是引擎的债。用「覆盖边界」登记 ⇒ 绿灯不掩盖盲区（§9.3 纪律） |
| 2 | 地形规则要点怎么被机器校验？ | **契约清单 + C10**（`tools/rules-book-contract.mjs`） | 自由文本无法逐字比对；改为「章节 + 要点关键词」的结构性覆盖，改漏立刻判红 |
| 3 | 契约放哪？会不会变成第二事实源？ | 契约是**单一来源**，规则书与校验都引用它 | 契约与规则书各写一份 = 两处事实源；改一处漏一处 = 假红 |
| 4 | 规则书写了 `### {{rift}}` 等占位符，谁保证成品不残留？ | 占位符 map **补齐地形词** + 一条常驻测试 | 渲染器 map 少一个键 ⇒ 成品字面印出 `{{rift}}`，而所有门禁都是绿的 |

## 4. 验收

- 门禁 **10/10 全绿**（门③ doc-sync 10/10：新增 C10 通过；C8 覆盖边界 9 条一致）。
- `npm run print` 四套主题实体件正常产出；成品规则书**无占位符 / Markdown 残留**。
- 干净副本（隔离临时目录）门禁 **10/10 全绿**。
- 负样本自证：删掉裂隙小节 ⇒ C10 判红；删掉「停 1 回合」要点 ⇒ 判红；规格加新地形未登记 ⇒ 判红；副本里删小节 ⇒ **真门禁 `node tools/doc-sync.mjs` exit 1**。

## 5. 复盘与经验沉淀

- **「补规则」不只是补文字，还要看渲染器认不认那种 Markdown** —— 原渲染器只认 `#`/`##`，`###`、表格、`**` 一律当普通段落 ⇒ 成品字面印出 Markdown。**内容侧的「写好了」≠ 成品侧的「看得懂」**。
- **`git ls-files` 对非 ASCII 路径会转义**（默认 `core.quotePath=true`）⇒ 按输出拼路径**根本不存在** ⇒ 副本静默漏文件、门禁报 ENOENT。
- **只复制已入库文件会让「未入库的新模块」缺失** ⇒ 副本假红（不是真缺陷）。副本语义应是**工作树快照**（`--cached --others --exclude-standard`）。
- **负样本的 `replace` 只替换第一处** ⇒ 同一要点出现两次时（表格 + 小节）负样本静默失效 ⇒ 必须 `replaceAll`。

## 3. 关键裁定（5 项）

| # | 争议点 | 裁定 | 理由 |
| --- | --- | --- | --- |
| 1 | 选牌动作的可见性边界？ | 候选**只发给对峙参与者**，且**只含他自己手牌**的牌 | 亮牌**对对手不可见**（§3.3 + 预研红线 3）⇒ 拿到对方手牌 id 就等于提前看到对方出什么牌 ⇒ **候选源必须是「自己手牌」**（引擎 `submitDuelCard` 的守卫同款：非参与者拒 / 手牌中无此牌拒） |
| 2 | 对峙期还要不要行动面候选？ | **不要** —— 对峙面**取代**行动面 | 对峙是**回合阻塞**（该手番已行动）⇒ 与关隘面 / 裂隙面同款结构 |
| 3 | 已锁定者还有候选吗？ | **没有**（等对方） | 引擎会拒「你已锁定亮牌」⇒ 发了就是**死选项** |
| 4 | 非参与者呢？ | **没有** | 他们此刻确实没有可做的动作 ⇒ 与「可分桶」标记（`noLegalActions`）并存 |
| 5 | 要不要改 UI 的对峙面板？ | **不改** | 真人早已能选（点手牌）⇒ 本批只补枚举/契约/探针三层 |

## 7. 复盘与经验沉淀

- **「机制可达」要逐层数，而每层都要问「谁在用」**：对峙选牌在引擎与 UI 都齐备，唯独**枚举层**把它整表清零 ⇒ 真人能玩、AI 不能 ⇒ 只有把四层逐层数才发现。⇒ 与 B67 的 E120 同族，但更隐蔽：**UI 能做 ≠ 模型能选**。
- **给「隐藏信息」机制建动作成员时，候选源必须是「自己可见的那份」**：把 `cardId` 的来源钉死为**自己手牌**（不是「全部玩家的牌」）⇒ 才不会因新增动作成员而**引入新的信息泄露路径**（预研红线 3）。
- **变异自证的判据不能要求「层标记与 AssertionError 同行」**：mutant 输出里断言消息可能**换行** ⇒ 同行匹配**恒假**（本批实测踩过：mutant 明明让测试红了，判据却报绿）⇒ 改为「输出里同时出现层标记与该层专属措辞」，且**断言消息本身要带层标记**。
- 已写入 `docs/沉淀/经验教训索引.md` **E121**（隐藏信息机制补动作成员时的候选源边界；变异判据不要求同行）；Agent Memory 同批沉淀 1 条。

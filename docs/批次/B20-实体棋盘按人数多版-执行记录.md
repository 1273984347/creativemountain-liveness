# B20 · 实体棋盘按人数多版（V1.1 收尾）

> 批次号 B20 · 日期 2026-11-08 · 主题：让实体件的棋盘**按人数出多版**，与数字轨用同一份适配逻辑。

## 1. 问题

- 主题包棋盘**固定 28 格**（4 人局），而规模表按人数给出 **24 / 28 / 32 / 32 / 36 / 36**（§8 `boardLength`）。
- 数字轨靠 `fitBoard` 缩放（引擎内私有）⇒ 3 人局实际爬 24 格 ✔；
- **实体件却只有一版**（主题原版 28 格）⇒ 3 人局玩家拿到的棋盘与规则书、与实际对局**都不一致**。

## 2. 实现

| 项 | 做法 |
| --- | --- |
| **单一适配逻辑** | `fitBoard` 从 `engine/core/setup.ts` 抽到 **`engine/core/board-fit.ts`**，数字轨与实体件构建**共用同一份** |
| **版本清单** | `BOARD_VERSIONS` 由**规模表派生**（`SCALES` ⇒ 去重升序 ⇒ 24/28/32/36 + 对应人数档 3 / 4 / 5–6 / 7–8） |
| **实体件产物** | 每主题出 **4 张棋盘 SVG**：`棋盘-A2-24格-3.svg` / `-28格-4` / `-32格-5人6` / `-36格-7人8`（旧的单版 `棋盘-A2.svg` 已取代，避免玩家不知用哪张） |
| **实体件打印页** | `partsHtml` 每版一页 A2，页首标明**适用人数与格数** |
| **规格** | §6.7 实体规格表补「按人数出多版」；§13.5 登记 B20 裁定 |

⚠️ **行为不变**：`fitBoard` 的缩放规则逐字搬迁 ⇒ 数字轨对局**完全不变** ⇒ 平衡无需重跑（门② 的平衡回归即验证）。

## 3. 实测数据

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 实体件棋盘版本 | **1 版**（28 格） | **4 版**（24/28/32/36 格），4 套主题共 **16 张** |
| 适配逻辑副本数 | 引擎私有 1 份 | **共用 1 份**（`engine/core/board-fit.ts`） |
| 版本清单来源 | 无 | **规模表派生**（不手抄） |
| 回归测试 | — | **3 条**（版本清单 / 每版格数与关键格位 / 构建接线） |
| 门禁 | 10/10 | **10/10** |

## 4. 遗留（如实登记）

| # | 现象 | 说明 | 归属 |
| --- | --- | --- | --- |
| L1 | 主题包固定 **2 座关隘**，而规模表 `gateCount` 为 **2–4 座** | 多版棋盘会把它带到实体件：24 格版 2 座、36 格版 3 座（第 3 座是缩放产生的**重复副本**，格名被中性化）⇒ **实体棋盘上的关隘数与规模表不一致** | **B21**：主题包按人数提供多版棋盘数据（关隘/裂隙按档位编排） |

## 5. 复盘

- **同一件事只能有一份实现**：数字轨缩放与实体件缩放若各写一份，实体件迟早印出与对局不一致的棋盘。⇒ 抽出 `board-fit.ts` 后两边共用，是结构性防漂移。
- **版本清单要从源头派生**：`BOARD_VERSIONS` 由规模表生成 ⇒ 规模表改了格数，实体件版本自动跟着变（不手抄 ⇒ 不会漏）。

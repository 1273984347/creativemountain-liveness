# B52 · 覆盖边界的**逐条对应**（C8 由「条数一致」升级为「逐条对应」）

> 批次号 B52 · 日期 2026-11-09 · 主题：把 B51 的遗留 **T7** 落地 —— 给规格 §9.3 覆盖边界表加 `id` 列，让 doc-sync **C8** 由「条数一致」升级为「逐条对应」。
> 前置：B51 的独立盲审（`1f4ad8a`）留下遗留 **T7**（C8 只比条数、不比对逐条对应）。

## 1. 起因：**条数一致 ≠ 逐条对应**（旧口径有确凿漏检）

| # | 缺口 | 证据 |
| --- | --- | --- |
| A | **C8 只比条数** —— 规格 §9.3 覆盖边界表与 `tools/coverage-boundaries.mjs` 机器清单**条数相同但内容错位**时，旧检查照样绿灯 | 对照实验（逐字复刻旧实现 `HEAD:tools/doc-sync-lib.mjs` 的 `checkCoverageBoundaries`）：把两条边界的 id 互换 ⇒ 规格表仍 **12** 条 vs 机器清单 **12** 条 ⇒ 旧口径 `ok=true`（**漏检**） |
| B | **规格表没有稳定标识** —— 表格只有「覆盖 / 不覆盖」两列，机器清单的 `id` 在规格里**根本不出现** ⇒ 机器无法判断「这行说的是不是同一条边界」 | 改前规格 §9.3 表头为 `| 覆盖 | 不覆盖 |`（无 id 列） |
| C | **同一口径两份实现** —— C8 在 `doc-sync-lib.mjs` 里数行数，`tests/gates/discipline.test.ts` 里**又自写了一套**表格解析 ⇒ 改表结构时必有一处漏改 | 加 id 列后两份解析同时受影响（`discipline.test.ts` 的表头过滤 `\| 覆盖 \| 不覆盖 \|` 会失配） |

## 2. 关键裁定（先定规则，再施工）

| # | 争议点 | 裁定 | 理由 | 落地位置 |
| --- | --- | --- | --- | --- |
| 1 | 判定口径用什么？ | **逐条配对**：第 i 行规格 id == 第 i 条机器清单 id（**同序**） | 「条数一致」被误当成「每条都对得上」；错位（含顺序错位）也是漂移 | `checkCoverageBoundaries` |
| 2 | 判据要不要拆多层？ | 拆**四层**，每层职责单一：① 结构层（首列必须是 `id`、3 列）② 顺序层（第 i 行 == 第 i 条，**最先判**）③ 集合层（双向点名缺失）④ 唯一层（两侧 id 不得重复） | 缺 `id` 列时若只报「某 id 未登记」，会把**结构问题**误导成**登记问题**（E42 教训：报错必须点名具体差异） | 同上 |
| 3 | 表格解析放哪？ | 抽成**共享函数** `parseSpecCoverageRows` / `checkSpecCoverageTableStructure`，放 `tools/coverage-boundaries.mjs` | 同一口径只能有一处实现（E92）；C8 与测试断言共用 | `tools/coverage-boundaries.mjs` |
| 4 | 顺序要不要纳入判据？ | **纳入**（错位即红，并点名是第几条） | 覆盖边界表是有序清单；顺序错位意味着「登记次序」与机器清单漂移 | 同上 |
| 5 | id 列的写法 | 规格表用**反引号包裹**（`\`pdf-text-layer\``），解析时剥掉 | 规格文档里代码标识符一律带反引号（既有惯例） | `parseSpecCoverageRows` |

## 3. 做法

1. **规格 §9.3 覆盖边界表加首列 `id`** —— 12 行逐条填机器清单 id，并在表头下写明「同序一一对应」的登记要求。
2. **共享解析**：新增 `parseSpecCoverageRows(spec)`（取逐行 id 与单元格）与 `checkSpecCoverageTableStructure(spec)`（判首列是不是 `id`、列数是不是 3）。
3. **C8 升级**：四层判据（结构 / 集合 / 顺序 / 唯一），报错**点名具体 id 与第几条**。
4. **消除第二份解析**：`discipline.test.ts` 的 A5 用例改为 import 共享解析，断言从「条数一致」升级为 `deepEqual(parsed.ids, codeIds)`（逐条同序）。
5. **负样本常驻**：
   - **单元级** `tests/gates/doc-sync-c8-negative.test.ts`（**11 例**，直接 import 生产实现，篡改只发生在**内存字符串**上 ⇒ 共享工作树全程只读）：正样本 1 + 负样本 10（id 互换 / 少登记 / 多登记 / 缺 id 列 / id 重复 / 缺小节 / 「缺列不得被误报成未登记」/「顺序层可达」回归锁 / **CRLF 行尾稳健性**回归锁 / **集合层可达**回归锁）。
   - **集成级** `tests/gates/mutation-samples.test.ts` 新增 **2 例**：① 隔离副本里改规格 id ⇒ 真跑 `tools/doc-sync.mjs` 必红 ⇒ 恢复必绿；② 隔离副本里把规格转成 **CRLF** ⇒ doc-sync 必须**判绿**（不得误报假红）。
6. **级联**：规格 §13.5 裁定行、门禁清单（门 3 负样本锚点 + 失败排查行）、经验教训索引 **E93–E97**、沉淀 README 批次范围、根 README 门 ③ 描述（顺手修正 B51 遗留的「C1–C9」漂移 → C1–C10）、门禁条目模板的登记要求。

### 对照实验的方法学（留证，便于复算）

「旧口径漏检」这条结论**不能靠推理**，必须实测：

1. 取**改前**的规格：`git show HEAD:docs/superpowers/specs/2026-11-07-creative-mountain-liveness-design.md`（旧表 2 列）。
2. 逐字复刻**旧实现**的 `checkCoverageBoundaries`（取自 `git show HEAD:tools/doc-sync-lib.mjs`），**不改一行**。
3. 场景 A（未篡改）⇒ 旧口径 `ok=true`（绿）。
4. 场景 B（把两条边界的 id 互换 ⇒ **条数不变**）⇒ 旧口径 `ok=true`（**绿 = 漏检**）。
5. 新实现对同一输入 ⇒ `ok=false`，且 detail 为「第 1 条错位：规格表为 pdf-raw-bytes，机器清单为 pdf-text-layer」。

> ⚠️ **复算时的坑**：用 `git show` 取出的内容在 Windows 上可能被转成 **CRLF**
> ⇒ 旧实现用 `spec.indexOf('\n\n**')` 界定小节 ⇒ CRLF 下匹配不到 ⇒ 兜底吃进全文表格
> ⇒ 旧口径会**假红**（数到 140 条）⇒ **对照实验会得出错误结论**。
> ⇒ 复算前须确认行尾（`git show ... | Measure-Object -Character` 或直接查字节），
>    或如本批做法：把规格**规范化为 LF** 后再喂给旧实现。

## 6. 复盘与经验沉淀

- **「条数一致」是最容易伪装成「已覆盖」的口径**（E93）：N 对 N 不代表逐条对应 ⇒ 清单类校验必须给文档表加**稳定 id 列**并按 id 配对。
- **判据的顺序会让某层变成不可达**（E95，本批自查抓到的确凿缺陷）：判据按「唯一层 → 集合层 → 顺序层」排列时，两条 id 互换会先命中前两层 ⇒ **顺序层永不触发**（「第 N 条错位」这条最具体的定位从不出现）⇒ 判据不只是「有哪些」，还要「**谁先判**」⇒ 顺序层**最先判**，并用回归锁钉住其可达性。
- **文档解析不能用「换行符序列」界定小节**（E96，自查 + 独立盲审共同抓到）：仓库 `core.autocrlf=true` 且**无 `.gitattributes`** ⇒ 全新克隆后规格是 **CRLF** ⇒ `spec.indexOf('\n\n**')` 匹配不到 ⇒ 兜底把**后续章节的表格行**也吃进来（实测 12 条 → **140 条**）⇒ C8 误报 ⇒ **门禁假红** ⇒ 解析改为**纯行级**定位（第一个连续表格块），并加「转 CRLF 后结果一致」的回归锁。
- **同一口径两份实现必然漂移**（E94）：本批加 id 列时，C8 与 `discipline.test.ts` 两份解析**同时**受影响 ⇒ 直接印证 ⇒ 解析抽成共享函数。
- **报错要指向真正的层**：缺 `id` 列时若只报「某 id 未登记」，会把结构问题误导成登记问题 ⇒ 结构层单独判（E42 同款）。
- **负样本要测被测实现**：单元级负样本直接 import `checkCoverageBoundaries`（生产实现），不是复刻一份近似实现。
- **调试踩坑（值得记）**：定位「小节起点行」时按 `offset >= markerIdx` 找会**跳过含 marker 的那一行**（marker 落在行内部）⇒ 起点行变成下一行（说明段）⇒ 再下一行是空行 ⇒ 「遇空行即停」的表格扫描**在表格出现前就退出** ⇒ 表现为「未找到数据行」。正确做法：先扫出**连续表格行块**，再在块内数数据行。

# B17 · 地形差距收敛（裁定失真子句 + 写定关隘/裂隙施工方案 + 根治门禁 flake）

> 批次号 B17 · 日期 2026-11-08 · 主题：B16 把规则书写全之后，**数字轨还欠什么**、以及**欠的部分该怎么写**。

## 1. 目标与范围

- **目标一**：把「规则书已写、引擎未实现」的差距逐条查证，**该实现的实现、该裁定的裁定**。
- **目标二**：为尚不能实现的两处（关隘 / 裂隙）写出**可直接施工的规格条款**，不留模糊。
- **目标三**：修掉施工过程中暴露的**门禁 flake 根因**。

**本批不做**：关隘 / 裂隙的引擎接线（要扩展 Action 契约与主题包数据，与并行会话的 Action 契约工作相邻 ⇒ 并行会冲突），明确列为 **B18**。

## 2. 关键裁定（4 项）

| # | 争议点 | 裁定 | 理由 |
| --- | --- | --- | --- |
| 1 | 险径黑牌「**失去本回合剩余行动**」该实现还是该删？ | **删除该子句**，不加状态字段 | 查证：地形在**手番末**结算（`resolveTile` 只在 `finishTurn` 调用）⇒ 结算时玩家本回合**唯一的一次行动已经用完**；且每回合仅一次行动（§3.1 行动三选一）⇒ **不存在「剩余行动」可丧失**。该子句是 v1.4 旧节奏（回合内多次行动）的遗留。加一个永不触发的字段 = 死机制 |
| 2 | 裂隙「持有者经过时需判定」的歧义 | **该格任何玩家经过都判定**（含放置者本人）；判定**沿用险径判色**（红=通过 / 黑=被拦 ⇒ `skip_turn` +1） | 若只拦别人，放置者畅通无阻 ⇒「花 2 灵枢买断裂隙」的博弈不成立；沿用判色复用既有机制，不新增判定维度 |
| 3 | 关隘接线缺什么？ | 三处缺口写死于规格 §3.5：`COMPARE` **至今无行为语义**（候选 A/B，须评审定案）、付费通道**缺动作入口**（`payGate`/`drawTrial` 全仓零引用）、试炼牌**缺结构化判据**（主题包要加 `requirement`） | 规格有缺口就不能凭空实现。`COMPARE` 带 `cardId`+`target` 说明原设计有未写下的意图 ⇒ 列出候选而非定案 |
| 4 | 门禁② 偶发红（门② 报「规格必须含『门禁覆盖边界』小节」，单跑却全绿） | **根因是 `mutation-samples.test.ts` 就地改写共享工作树的规格/state.ts** ⇒ 改为**隔离副本** | 它只解决了「负样本之间」的并发（集中在同文件），没解决**与其它测试文件**的冲突 ⇒ 并行读的 `discipline.test.ts` 读到中间态 |

## 4. 验收

- 门禁 **10/10 全绿**，**连跑 3 次稳定绿**（flake 判据：连跑 3 次全绿才算通过）。
- `npm run print` 四套主题实体件正常产出；成品规则书的地形表与小节口径一致（无 `{{`/`###`/`**` 残留）。
- 负样本自证：缺小节 ⇒ C10 红；缺要点 ⇒ 红；规格新增地形未登记 ⇒ 红；**副本里跑真门禁 ⇒ exit 1**；已删除子句「复活」⇒ 防复活断言红。

## 5. 复盘与经验沉淀

- **纸面规则必须与实际节奏对账**：一条规则「写在规格里」不等于「有语义」。本批查证后发现一条规则**在任何路径下都不可能触发** ⇒ 正确处置是**裁定删除**，不是加字段、加断言、加状态。
- **规格缺口要写清候选而不是凭空定案**：`COMPARE` 的行为在规格里缺失 ⇒ 写两个候选 + 倾向 + 「须评审确认」，比直接编一个实现更安全。
- **负样本必须隔离副本**（这是第二次栽在同一类问题上：上一轮是「引擎负样本改共享树」，这一轮是「文档负样本改共享树」）⇒ 已在 `docs/沉淀/负样本自证范式.md` 增补纪律，并抽出共享复制器 `tools/repo-copy.mjs` 作单一事实源。
- 上述 3 条已写入 `docs/沉淀/经验教训索引.md`（E23–E25）。

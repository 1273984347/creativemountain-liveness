## 1. 立项与范围

三个源头合成一批：

1. **五个空转的状态算子**：`poison` / `slow` / `silence` / `skip_turn` / `immunity` 五个算子自 B2 注册进
   `ops/registry.ts` 起**只有写入点、没有任何读取点** ⇒ 中毒不扣血、减速不减格、封口不禁言、
   停手番不跳回合、免疫不拦截。主题包数据共 **56 处发放点**（每套 14 处 = `poison` 2 / `slow` 1 /
   `silence` 1 / `skip_turn` 1 / `immunity` 9，分布在卡牌、天机牌、关隘试炼奖励与指令骰面），另有引擎侧两条惩罚写入
   （裂隙判色 ⇒ `skip_turn`、关隘失败 ⇒ `silence`）⇒ 全部空转。取证方式：`grep -n "statuses\." engine/` 只命中写入侧（`registry.ts` 的 `+=`），
   消费点为零 ⇒ 与 B12 的「7 个身份被动零消费点」同判据（E1 / E125）。
2. **试炼题面与判定矛盾**：B22 成对编写题面与判定（当时一致）；**B26 加难只换了 `pred`**，
   没有回头重写题面 ⇒ 四套各 9–10/12 条「牌面写的条件 ≠ 引擎判的条件」；而实体试炼牌的 IR
   **只搬运 `text`**（`build-ir.mjs:138`）⇒ 印刷链路看不见判定，玩家手里的牌是假话。
   生成器还把 `theme-data` 里手抄的文本抄进派生主题 ⇒ 一份错扩成三倍。
3. **`PASS` 是未接线的契约成员**：key 编解码 / 探针 / UI 闸门 / 描述四处都有它，
   但 `legal.ts` 从不发放、`performAction` 没有分支 ⇒ 登记在规格里的「结束手番」是个空壳。

范围外（用户裁定留给后续批次）：B78 主题内容（含题面叙事润色）、B79 模型、R8 开拓者强度削弱。

## 2. 关键裁定表（含被推翻的两条）

| 编号 | 裁定 | 结论与落点 |
|---|---|---|
| 层数语义 | `poison` / `slow` 的 `amount` = **当回合强度**；`silence` / `skip_turn` = **接下来 N 个完整手番**（r5 定稿，见 §4.3） | §6.4 算子注；`applyStatus` 一律**累加**，无设层语义（r2 红4 把既成事实规格化） |
| 位移罚 | `slow` 并入 B76 力竭那一行，**单一 penalty**：`max(1, roll − (力竭1 + slow层)) + moveBonus` | `registry.ts` 的 `move_by_dice`；下限 1 全仓只出现一次（E94） |
| 封口 | 写入那一刻弃 **手牌首位 1 张**（复用 `discard_self`）+ N 手番不能出牌/被动；被免疫则**连弃牌一起免**；零 rng、零交互 | `statuses.ts` 的 `applyStatus`。⚠️ 本条被**我自己写反过一次**（见 §3.1） |
| skip | 跳过整个行动面但**回合末结算照做**；豁免族动作消耗手番，**对峙提交除外**（全局阻塞） | `legal.ts` skip 短路 + `turn-runner.ts` 的 `case 'pass'` |
| immunity | **持续窗、预防不解药**，继续寄居 `flags`（不迁容器） | `grantImmunity` + 家族 B ⑥ 段 |
| 优先级 | `skip > silence > 力竭`，且**拒因文案的优先级同属三层同判**；豁免族（`GATE_RESOLVE`/`COMPARE`/`BARRIER_RESOLVE`/`DUEL_SUBMIT_CARD`/`PASS`/`VOTE`/`COUNCIL_VETO`/`CERTIFY_*`）**永远发放** | `statuses.ts` 的 `isActionBlocked` / `blockedNotice`——把它们封掉造出的是**死锁**而非惩罚（D6 补） |
| **r3（推翻 r2）** | 状态族递减锚点从 **round 末** 改为 **该玩家自己手番末** + 新增 `turn.statusGrantedThisTurn` 豁免授予当回合 | 见 §4.1，本批的方法产出 |
| **r5（推翻 r3.1 的实现形状）** | 豁免位从「无条件置位」收窄为「仅当授予发生在受害者自己手番内」⇒ **「N 个手番」= 接下来 N 个完整手番** | 见 §4.3；`tests/engine/status-duration.test.ts` |
| 排期 | 先 B75.2 小批、再 B76（力竭）、本批 B77；复活永久搁置 | 主规格 §13.3 新增一行登记 |

## 3. 施工中发现的计划缺口与文档缺陷（逐条当场处理）

### 3.1 我把评审原话改错了方向（用户是对的）
`silence` 弃哪张：评审原话「**最左**」；我在 r2.1 依据 `discardDownToLimit`（超上限裁牌保留 `slice(0, limit)`）
判定现行口径是「弃末位」，据此把规格改成「弃末位」。**该推理的前提抓错了函数**：封口属「弃 N 张」族，
唯一实现 `discard_self` 用的是 `hand.slice(0, count)` = **首位**。r3.3 撤销偏离、回到评审原话，
并直接复用 `discard_self`（自动获得弃牌堆簿记与日志，不再写第三份）。

### 3.2 登记一处既有 wart（本批**不**统一）
仓里两套「不得不弃」的方向**本来就相反**：`discard_self`（出牌类 / 封口）弃**首位**，
`discardDownToLimit`（超上限裁牌）弃**尾部**。统一它要动 B75.2 已定稿的裁牌轨迹（门 ⑨ 额外扰动），
⇒ 本批只在两处各加注释互相指认，并在规格 §3.3 登记。**遗留项 L-B77-1**。

### 3.3 C9 覆盖不到嵌套字段（规格纪律的盲区）
`parseStateFields` 只解析 `export interface State` 的顶层字段 ⇒ `PlayerTurnState` 的新键
`statusGrantedThisTurn`（以及 B76 的 `Player.exhaustedRounds`）**不在 C9 覆盖内**，「规格先行」
在这类字段上没有任何门禁兜着。对策不是扩 C9（解析器改造），而是补一条**常驻用例**：
从事实源 `EMPTY_TURN` 派生键清单，逐键核对主规格 §6.2 是否登记（`tests/engine/state-contract.test.ts`）
⇒ 清单不手抄，所以它不会变成第二事实源。

### 3.4 由 3.3 立刻抓到一个真 bug：`clearTurnStates` 的手写清零清单
B75.2 为了保留 `moveBonus`，把清零从「整体替换 `EMPTY_TURN`」改成**手写清单** ⇒ 与本文件自己写的
「避免逐字段漏清」相反；B77 新增的键在清单里**静默不被清**（跨 round 残留）。修复 = 恢复从
`EMPTY_TURN` 展开 + `{ ...EMPTY_TURN, moveBonus: t.moveBonus }`。这是「同一口径两份实现必漂移」（E94）
的又一次实证，也是本批新增用例第一次跑就抓到的。

### 3.5 对峙负样本被 B77 变绿（前提失效，不是判据失效）
门 ⑩ 的负样本 A 原本只切断 `startDuel` 的一条出口；`silence` 的写入时弃牌抬高了空手相遇率 ⇒
空手自动落败路径（`autoLose` → `logDuel`）也会写 `kind:'duel'` 日志 ⇒ 门 ⑨ 的可达性判据被骗过、
负样本**假绿**。最小实验证实：只切出口① ⇒ EXIT=0；两条都切 ⇒ `FAIL 对峙在真实对局中从未发生`。
⇒ 修的是**破坏点覆盖**（补第二条出口 + 两条各自断言可破坏），**不是把判据放宽**。
登记一条认识：判据本身没错（空手自动落败确实是一次按规则结算的对峙）。

### 3.6 规格 §5 清单里把「关隘」写成 §5.4
B77 规格 §5 的同步清单写「主规格 §3.4 裂隙 / **§5.4 关隘**」，而主规格的关隘实际是 **§3.5**
（§5.4 是「题目来源」）。⇒ 施工按 §3.5 落笔，此处如实登记，避免下一个人照抄错编号。

### 3.7 三条旧 `PASS` 判据被本批推翻（已改写口径，保留其知识）
旧用例证明的是「PASS 不改变状态 / UI 无入口」；现在 PASS 是有语义的动作。三条改写为：
skip 期间 PASS 必须生效、未被封时 PASS 必须被引擎引用相等拒绝、枚举只在 skip 时发 PASS。
**没有删除任何一条**，因为它们各自编码了一条历史认识（探针的空集陷阱 E87、UI 与引擎同判 E94）。

## 4. 本批的三条「设计发现」

### 4.1 r2 → r3：结算锚点推翻（方法产出，已进经验索引 E129）
r2 把家族 B 与力竭统一到 **round 末**，理由是「整齐、单一出处」。落地后跑读数：
**六个计数器全部恒为 0**。根因链：五件状态的写入点全在**受影响玩家自己的手番内**
（撞印判色 / 关隘失败 / 他自己出牌 / 试炼奖励），而 round 末发生在他下一次行动**之前** ⇒
「封口 1 回合」授予即被同一拍吃成 0 ⇒ 受害者一次也没被真正封过；`t_oath` 一类免疫奖励因此
**结构性不可达**。甲案（状态族挂该玩家 `finishTurn`、力竭留 `endRound`，两家族两锚点，
仍各自单一出处）+ `statusGrantedThisTurn` 豁免后，六个计数器全部出现读数。

反证用例 `tests/engine/status-anchor.test.ts` 写成**三连断言**（授予 ⇒ 下一手番内仍在 ⇒
下下手番末才清）——单向用例抓不到「早清一拍」，而这正是 r2 的错误形状。
把锚点搬回 round 末的变异：5 条用例同时红（墓碑反证，见 §6）。

### 4.2 `silence_applied` 不能有日志前缀（规格 §9 的一行被实现约束推翻）
引擎拦下被封动作的信号是**引用相等**（`turn-runner.ts` 的 `if (isActionBlocked(...)) return state;`），
那是探针 `byRef` 判「这步非法」的依据，也是「绕开 UI 直接打引擎也拦得住」的那道。
在拦截点写日志 ⇒ 状态引用变了 ⇒ 探针把非法动作当合法 ⇒ 三层合法性口径作废。
⇒ 用户裁定「甲：接受反事实」：同一局面**摘掉 `silence`** 后引擎 `getLegalActions` 会多发几个
`PLAY_CARD`/`ABILITY`，>0 记 1 **手番人次**（`tests/sim/policy.mjs` 的 `silenceCost`）。
判据仍是引擎自己的枚举 ⇒ 模拟器不复制封锁集（E94）；探针在隔离副本试跑 ⇒ 零 rng 扰动、两臂同口径。

⚠️ 单位必须是**手番人次**：候选动作数正比于手牌张数（一手番 8 张就是 8），实测口径差一个数量级
（1.38/局 vs 封口授予 0.21/局）⇒ `tests/gates/status-report.test.ts` 加了**单位钉子**，
退回候选口径当场红（已实测：退回后报「每局 1.38 ⇒ 应 < 1」）。

### 4.3 r5（T12 阶段发现）：豁免位过宽 ⇒「N 个手番」实际吃掉 N+1
T11 落地六计数器后做账时对不平：**失手 1192 > 授予 996**（封口），停手番 3806 > 授予 3272，
而所有 `amount` 都是 1 ⇒ 一部分授予影响了两个手番。确定性探针（`mk(4,7)` + 受害者手里放满 0 费牌，
分别测「在自己手番内授予」与「在别人手番内授予」）给出确凿结果：

| 授予时机 | r5 前 | r5 后 |
|---|---|---|
| 受害者**自己手番内**（如他自己关隘试炼失败） | 当前剩余 + 下一手番 = 2 | 当前剩余（不耗额度）+ **1 个完整手番** |
| **别人手番内**（如被别人牌封住） | **2 个完整手番** | **1 个完整手番** |

**根因**：`markGranted` 无条件把 `statusGrantedThisTurn` 打在受害者身上。r3.1 造这个标记是为了救
「免疫 1 回合在授予它的同一手番末被吃成 0」（`t_oath` 一类奖励恒为 0）——那需要它；但同一句话
顺手把 `silence` / `skip_turn` 的递减也豁免了一拍 ⇒ 写进主规格 §6.4 和规则书的「N 个手番」成了假话。
**这正是本批立项要治的那类病**（说的和判的不是同一件事），所以不能只改措辞。

**修法**（用户裁定乙案）：`markGranted` 只在 `turnOrder[turnIndex] === 受害者`（= 授予发生在该玩家
自己手番内）时置位；读 `turnOrder` 而非 import `currentPlayer`，免得把 legal/turn-runner → statuses
的依赖方向绕成环。**定稿口径**：**N = 受害者接下来 N 个完整手番**；自己手番内授予时当前剩余同样被封
（状态 >0 ⇒ 引擎与枚举同判），但不消耗额度。

**常驻用例**：`tests/engine/status-duration.test.ts` 六例（r5 前先跑：**4 红 2 绿**，红的正是"别人手番内"
那一族）；`tests/engine/statuses-tick.test.ts` 里「豁免标记真实置位」那条改的是 **fixture**（把授予挪进
受害者自己的手番）——断言意图一字未放宽，它原本只是靠旧行为才成立。

**代价如实登记**：行为再次改变 ⇒ 基线与报告在 r5 之后**重扫重发一次**（§7），敏感度带也按 r5 复跑（§5.3）。

## 7. 重标定与发布链

### 7.1 门 ⑨ 逐字等价为何不成立（如实登记，不谎称等价）

### 7.2 基线换代
- 重扫：`--scan-reserves 0,1,2,3,4 --scan-seeds <20 组> --games 125 --scan-json …` ⇒ **100 组 / 30 万局**。
- 新基线：`docs/baselines/trial-reserve-scan-B77.json`（B76 / B75.2 / B75.1 / B75 / B74 / B34 快照全部保留）。

  **0/100 一致**（漂移有方向：各组**无人封顶率 +1~2pp**、**平均席位 1.63 → 1.55**，即状态惩罚让登顶变难）

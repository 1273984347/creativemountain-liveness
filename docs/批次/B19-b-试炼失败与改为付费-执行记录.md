# B19-b · 试炼失败机制 + 「失败改为付费」算子 + 主题包改造

> 批次号 B19-b · 日期 2026-11-08 · 主题：让关隘试炼**能失败**，并把「失败 ⇒ 本关改为付费」做成**主题包数据可表达**的机制。

## 1. 目标

- 规格 §3.5 的试炼示例「**灵枢 ≥ 4**——失败则本关改为付费」此前**无法实现**：试炼通道**总是通过**（`drawTrial` 直接写 `gate_<index>` 通过标记），失败与否在效果树里无法表达。

## 2. 关键裁定（5 项）

| # | 争议点 | 裁定 | 理由 |
| --- | --- | --- | --- |
| 1 | 「失败」怎么表达？ | 新增算子 **`gate_fallback_pay`**（试炼失败 ⇒ 本关改为付费） | 「改为付费」是一个**后果**，与其它后果（退格 / 封口 / 改判）同一层 ⇒ 用算子表达最一致 |
| 2 | 状态落在哪？ | **使用者自己的 `flags`**（`gate_pay_<格号>`） | 语义是「玩家 × 这座关隘」⇒ **无需改 Tile / IR 契约**（§6.2、§6.7.1 都不动），牵动面最小 |
| 3 | 算子的 `tileIndex` 要不要必填？ | **可缺省**（= 使用者当前所在格） | 同一张试炼牌可能被**多座关隘**引用 ⇒ 写死格号会把主题包绑死在某张棋盘上 |
| 4 | 「本关改为付费」后玩家还能试炼吗？ | **不能**，只剩付费通道 | 否则可能反复抽到同一张失败牌 ⇒ 死循环 |
| 5 | 转为付费后**仍付不起**怎么办？ | **判「未通过并放行」**（退 1 格 + 被封口 + 写 `gate_fail_<格号>`） | 「无出路即死循环」—— 阻塞型机制必须永远留一条出路 |

## 3. 实测数据

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 算子总数 | 57 | **58**（新增 `gate_fallback_pay`） |
| 试炼通道 | **总是通过**（失败无法表达） | **按效果树结果**判定通过与否 |
| 主题包「失败改为付费」类试炼 | **0 张** | **4 套各 1 张**（`t_toll`） |
| 主题包牌数 / 规模表 | 48 / 40–80 | **不变**（替换而非新增 ⇒ 牌库与平衡不动） |
| 关隘回归测试 | 8 条 | **9 条**（新增试炼失败链） |
| 平衡 24000 局 | 异常 0 | **异常 0**（兜底率 8.0% / 席位 1.40 / 回合 14.5，未变） |
| 门禁 | 10/10 | **10/10** |

## 4. 主题包改造

- 原「回答在场任意一人的 1 个问题」牌（`t_riddle`，**引擎无法判定** ⇒ 效果只是 `draw_cards`）被**替换**为 `t_toll`「出示 4 枚资源（不足则本关改为付费）」：
  `conditional(resource_at_least 4) ⇒ then 抽 1 张牌 / else gate_fallback_pay`。
- **替换而非新增** ⇒ `counts.trialTotal`、`scales.trialTotal`、规格 §8 表**全部不动**；牌库组成不变 ⇒ 平衡不受结构性影响。
- 四套主题的该张牌**逐字相同**（§10.1 允许「事件池与试炼结构」复用）⇒ 用脚本批量替换（`docs/沉淀/theme-trial-swap.mjs`，带**替换次数断言**，改不到就报错）。

## 5. 复盘与经验沉淀

- **机制要能表达「失败」**：此前试炼只有「通过」一条路 ⇒ 数据层根本写不出失败。⇒ 设计机制时先问「**这条规则的两种结果，数据能不能都表达**」。
- **状态放在语义正确的层**：「本关改为付费」是「玩家 × 这座关隘」的状态 ⇒ 放 `player.flags` 即够，**不必**改 Tile / IR 契约（否则牵动 3 个门禁 + 双轨校验）。
- **阻塞型机制必须永远留出路**：转为付费后仍付不起 ⇒ 必须有「判未通过并放行」的兜底，否则玩家永远卡在那座关隘上。

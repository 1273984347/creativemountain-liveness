# B38 · 发布检查的**漂移失败路径测试**（非零即阻断构建）

> 批次号 B38 · 日期 2026-11-09 · 主题：给 B37 的发布闸门补**失败路径**的负样本 ⇒ 确认「漂移 ⇒ 非零 ⇒ 阻断构建」不是纸面承诺。

## 1. 问题

B37 的发布检查「漂移即失败」只有**正例**（全绿时通过）被验证过 ⇒ 若断言写法有误或退出码逻辑失效，它可能**永远绿** ⇒ 闸门形同虚设。

## 2. 改动与验证

| 项 | 做法 |
| --- | --- |
| **参数化** | `tools/release-check.mjs` 新增 `--scan=` / `--baseline=`（注入路径）与 `--skip-gate` / `--skip-rescan`（**仅供自检/负样本测试**；生产 `npm run release:check` 不带任何参数 ⇒ 全量执行） |
| **负样本 1** | 在**隔离临时目录**造一份**篡改**的扫描产物（改动某组一个指标）⇒ 跑逐组比对 ⇒ 断言**返回非零**且输出含「FAIL」与逐组比对结论 |
| **负样本 2** | 同一篡改产物 ⇒ 跑 `release-check` ⇒ 断言**返回非零**且输出含「发布前检查失败」⇒ **不进入后续步骤** |
| **负样本 3** | 读 `package.json` ⇒ 断言 `release` 以 `npm run release:check &&` 起头、且检查与构建之间是 `&&`（**短路**）⇒ 非零即**阻断构建** |

**测试结果**：3 条全绿（耗时 0.36s）⇒ 闸门的失败路径**确实会红**。

⚠️ 负样本纪律：篡改数据写在**临时目录**，**仓库侧全程只读**（基线快照与脚本都不改）⇒ 不污染并行的门禁。

## 3. 遗留（如实登记）

| # | 现象 | 归属 |
| --- | --- | --- |
| T1 | `--skip-gate` / `--skip-rescan` 是**绕过闸门**的开关 | 标注「仅供自检/负样本测试」；生产 `release:check` 不带任何参数 ⇒ 全量执行；若日后担心被误用，可再加「仅当环境变量允许时生效」 |
| T2 | 负样本只覆盖「数据漂移」这一条失败路径 | 门禁失败、重扫失败、产物缺失等路径未各写负样本 ⇒ 后续可按需补 |

## 4. 复盘

- **每个「失败即拦住」的检查都要有失败路径测试**：只测正例 ⇒ 闸门可能永远绿 ⇒ 断言写法有误也无人发现。
- **负样本的篡改对象要隔离**：改仓库文件会污染并行的门禁 ⇒ 改「临时目录里的副本」⇒ 仓库侧只读。
- **阻断要验到「调用链」**：断言 release 脚本用 `&&` 短路，比只看检查脚本自身的退出码更贴近真实发布路径。

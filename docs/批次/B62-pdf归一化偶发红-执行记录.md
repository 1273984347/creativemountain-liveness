## 3. 关键裁定（3 项）

| # | 争议点 | 裁定 | 理由 |
| --- | --- | --- | --- |
| 1 | 要不要改 `tools/pdf-normalize.mjs`？ | **不改** | 复现 50+ 次全部落空 ⇒ **无任何证据**表明归一化器有缺陷 ⇒ 此时改生产代码就是**凭猜测改** ⇒ 反而可能引入真 bug |
| 2 | 渲染那条断言怎么处理？ | **有限重试（最多 3 组）+ 失败时打印差异区段** | 单次比较会偶发红（误报）⇒ 重试把「偶发一次就红」变成「连续 3 组都异常才红」；而**失败时给出差异区段**（首个差异偏移 + 前后文本）⇒ 下次真偶发能**直接定位**，不再只给两个哈希 |
| 3 | 核心命题怎么守护？ | **新增不依赖 Edge 的确定性用例**（对**同一份字节**注入两个不同时间戳 ⇒ 归一化后逐字相同） | 「构建时刻不污染产物比对」是**归一化器**的性质；而「两次渲染逐字一致」是 **Chromium** 的性质（外部、且偶发不可靠）⇒ 核心命题改由**确定性**用例守护，渲染那条只作**端到端旁证** |

## 6. 复盘与经验沉淀

- **「沿用旧诊断」不等于「已知根因」**：上一批把偶发红归因为「pdf-normalize 的跨秒时序」，那是从 B54 抄来的；本批独立复现 **50+ 次全部落空** ⇒ 该归因不成立。⇒ **登记缺陷时「根因」那一栏必须有本批的复现证据，否则只能写「未确定」。**
- **把「外部且偶发的性质」从「自己该保证的性质」里拆出来**：归一化器该保证「抹掉时间戳」；「Chromium 两次渲染逐字一致」不是它的职责 ⇒ 核心命题用**确定性**用例守护，渲染那条只作旁证 ⇒ 既不误报，又保住门禁效力。
- **失败信息要能定位**：只给两个哈希 ⇒ 复现了也不知道差在哪 ⇒ 失败时打印**差异区段**（偏移 + 上下文）⇒ 下次偶发直接可见根因。
- 已写入 `docs/沉淀/经验教训索引.md` **E114 / E115**；Agent Memory 同批沉淀 2 条。

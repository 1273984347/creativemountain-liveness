# B32 · Welch t 临界值精确化 + 用 B31 的 20 组数据复核「余量 0 vs 2」

> 批次号 B32 · 日期 2026-11-09 · 主题：① 把 t 临界值从「表 + 取最近较小 df（保守）」改为**精确计算**；② 用 B31 的 **20 组数据**验证「余量 0 vs 2」判定不变。

## 1. 实现：精确 t 分布分位数

| 环节 | 做法 |
| --- | --- |
| **logΓ** | **递推到 z ≥ 8 + Stirling 高阶修正**（1/12z − 1/360z³ + 1/1260z⁵）⇒ 精度 ~1e-12；⚠️ 原先用 Lanczos 实现**有 bug**（CDF(1,18) 曾算出 1.21 ⇒ 二分求根静默发散） |
| **不完全 β** | 连分数展开（Numerical Recipes 的 betacf）；⚠️ **对称分支必须用 `I_{1−x}(b, a)` 自己的 beta 项** ⇒ 改为递归调用最不易错；连分数终止阈值取 1e-12（3e-16 过紧 ⇒ 不收敛） |
| **临界值** | 二分求 `T(t, df) = 0.975` ⇒ `tCritical05(df)`；**df 不取整**（保留 Welch–Satterthwaite 的小数自由度） |
| **自检** | 单测对**权威表值**逐点核对（df = 1 / 5 / 10 / 18 / 30 / 38 / 60 / 120，±0.001）+ CDF 对称/单调/临界处恰为 0.975 |

**与权威表值逐位吻合**：df=1 ⇒ **12.7062**（表 12.706）· df=10 ⇒ **2.2281**（表 2.228）· df=18 ⇒ **2.1009**（表 2.101）。

## 3. 实现过程中的一次真实翻车（留痕）

- **首版精确实现算出的临界值是 0.6227**（应 ≈2.10）⇒ 而「判定显著与否」的二分会跟着错 ⇒ 若不核对权威表值，这个错误会**静默污染**后续判定。
- 根因两层：① 不完全 β 的**对称分支张冠李戴**（用了 `I_x(a,b)` 的 beta 项）；② **Lanczos logΓ 实现有 bug**。
- 修复：对称分支改递归、logΓ 改「递推 + Stirling」⇒ 逐点吻合权威表值。
- ⇒ 教训：自写「精确」数值函数后**必须用已知权威值逐点核对** ⇒ 错误要在**自检**里当场暴露，而不是在下游判定里静默出错。

## 4. 汇总数据

| 项 | 改前 | 改后 |

| t 临界值 | 查表 + 取最近较小 df（**偏保守**） | **精确分位数**（任意 df） |

## 6. 复盘

- **手写数值函数的正确性要靠权威值自检**：本批首版精确实现静默出错（CDF 越界 ⇒ 二分发散）⇒ 若无「对 8 个 df 逐点核对表值」的测试，错误会一路污染判定结论。
- **「精确」与「保守」要分清**：查表近似是**偏保守**（偏保守会漏掉真实差异）⇒ 精确计算不是锦上添花，而是判据可信的前提。
- **复核不必重跑**��已发布数据 + 可复算脚本 ⇒ 结论复核成本从 7 分钟降到毫秒级 ⇒ 值得沉淀成工具。

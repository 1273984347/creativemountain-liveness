# B71 · 锁定回合枚举对齐引擎（B70 遗留 I-3 的根因修复）

## 1. 目标与范围

B70 的 play 面注入有**两处**出牌点：普通分支与「待认证锁定」分支。锁定分支在 B70 全程是
**no-op**（`askPolicy` 只能计 `emptyCandidates`、模型从未被问到），根因是 §7 粗筛在
`p.pendingCert` 时把**整个行动面**关掉。B70 把它登记为 parked（披露 + 留后续批次）。

本批修根因，范围**只限**「锁定者能做什么」这一条口径：

- `engine/core/legal.ts`：锁定者**只发非位移** `PLAY_CARD`（位移判定 `cardHasMovement`，与引擎同源）。
- `web/legal-gate.ts`：`uiCandidates` 同步发这些候选；`uiBlockNotice` 对非位移牌放行、对位移牌与
  位移族（MOVE / ROLL_WHEEL / ABILITY）保持拒绝；锁定的拒因文案改为「非位移牌仍可打出」。
- `web/main.ts`：行动面板的锁定提示同步改文案（面板本身仍只渲染 MOVE/ROLL_WHEEL/ABILITY，故锁定时空）。
- 测试与规格 §7 的「粗筛窄于引擎」登记表。

## 2. 关键裁定

| # | 裁定 | 理由 |
|---|---|---|
| 1 | 位移判定用 `cardHasMovement`，**不用** `card.type !== 'motion'` | B66 的 `pending-cert-lock.test.ts` 已证明：位移可藏在 `utility` 类型与 `sequence/conditional/count` 嵌套效果里；只按 type 判会与引擎分叉 |
| 2 | 锁定者**不发** MOVE / ROLL_WHEEL / ABILITY | 规格 §5.1「不能主动移动」；`actionWindowOpen` 对锁定者保持 false |
| 3 | 锁定分支仍受 `phase === '行动'` 与 `!isRoundEnd` 两条判据 | 与其它座位共用同一对口径（`actionWindowOpenExceptLock`），不手写第二份镜像 |
| 4 | **不改** sim 基线启发式的 `type !== 'motion'` 过滤 | 改了会移动门⑨ 基线报告（`docs/balance-report.md` 必须逐字不变）⇒ 属另一次 re-baseline 批次；本批只在报告里登记这个两臂差异 |
| 5 | UI 与引擎**各自独立写**一份候选形状 | 本仓既定设计（`legal-gate.ts` 不 import 枚举）；集合相等由漂移守卫钉住 |

## 7. 遗留 / 已知差异（如实登记）

1. **两臂在锁定回合的一个已登记差异**：基线启发式仍按 `type !== 'motion'` 选牌 ⇒ 极少数 utility 位移牌会被它尝试、
   被引擎拒（G-b）⇒ 该回合空耗；模型臂从枚举拿到的**都是合法牌**。修这个差异要改基线 ⇒ 会移动门⑨ 报告 ⇒
   属 re-baseline 批次（与门⑫/⑬ 基线一起重生成）。
2. **锁定回合仍不能 MOVE/ROLL_WHEEL/ABILITY**（规格 §5.1）——面板只显示提示，按钮为空是**预期**。
3. `actionWindowOpen` 仍对锁定者返回 false（语义 = 位移族窗口）；调用方若要判断「有无任何动作」应看
   `getLegalActions`，不要看它。

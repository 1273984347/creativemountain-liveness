## 3. 关键裁定

| # | 争议点 | 裁定 | 理由 |
| --- | --- | --- | --- |
| 1 | flow3 窄屏怎么减列 | 保留「座 / 身份 / **明细**」三列（去掉名次/活人席/距峰顶/综合分） | 「明细」是**功能入口**（进屏 3）⇒ 不可隐藏；名次可由行序读出 |
| 2 | 触控口径只管宽度还是也管高度 | **只卡宽度（44px）**，高度维持 26px | 44×44 是触控目标的**下限**；本页头按钮实测 66×26，把高度钉到 44 会**恒红** ⇒ 那是误判不是守卫（已在守卫里写明理由） |
| 3 | L-B87-4 怎么修 | 在**副本里** `git init` + 索引，**不改** `repo-copy.mjs` 的复制语义 | `repo-copy.mjs` 同时服务门 ② 的隔离副本，是核心复制逻辑；改它风险高。给副本补 git 元数据是最小且不改生产的做法 |
| 4 | 副本索引要不要含 node_modules | **排除** | 副本里它是 **junction（符号链接）** ⇒ `git add -A` 会把链接收录 ⇒ 后续隔离副本会跟着复制几百 MB ⇒ 门禁慢到不可用（实测踩到：后台跑了 15 分钟未完） |
| 5 | 跨浏览器怎么做 | 走查脚本支持 `HOST_WALKTHROUGH_BROWSER`，**实跑** firefox / webkit | 断点行为是否跨引擎一致，只能实测；先前的"未验"是因为**二进制版本错配**（库要 firefox-1522、本机装的是 1543）⇒ 实跑直接报 "Executable doesn't exist" |

### 6.2 沉淀

- **E146**：**「未跟踪且未忽略」的本地目录会被 clean-room 副本整包复制** —— `copyTracked` 的清单含「未跟踪但未忽略」的文件 ⇒ `.tmp/` 的 2274 个历史工件被带进副本 ⇒ 门禁慢到 15 分钟未完、且副本守卫因这些文件假红 ⇒ 修复：本地工地/工具产物目录必须进 `.gitignore`（本批加了 `.tmp/` 与 `.qoder/`），副本文件数 **2274 → 750**。
- **E147**：**连续修同一个门禁时，每轮都要确认「红因真的换了」** —— 本批门 ② 连红三次、每次红因不同（release 生成物缺失 → 副本无 `.git` → 副本索引把 `.qoder/` 当已入库）⇒ 前两次的"修法"都只解决了症状；**红因换了才说明修对了**，否则只是把红推到下一层。
- 复用既有教训：E139（回读校验）、E142（守卫要比对真正被使用的常量）、E143（改完立刻跑）—— 本批三处自伤（`control:/flowflow1` 笔误、`height` TDZ、`Buffer.concat` 误用展开）**全部由"改完立刻跑"当场抓出**。

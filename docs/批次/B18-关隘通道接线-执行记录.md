# B18 · 关隘通道接线（付费 / 试炼）

> 批次号 B18 · 日期 2026-11-08 · 主题：把规格 §3.5 的关隘**从「引擎里没有」变成「玩家能玩」**。
>
> ⚠️ **B18 拆分**：本批 = **B18-a 关隘两条通道**（付费 / 试炼）；
> **B18-b = 裂隙经过判定 + 封路印放置**（需「选格机制」与「牌库总量连锁」，另批）。
> 两者规格已在 §3.4 / §3.5 / §13.5 定案，拆批不影响可施工性。

## 1. 目标与范围

- **目标**：关隘接进引擎 —— 到达关隘 ⇒ 手番暂停 ⇒ 玩家在**付费 / 试炼**两条通道间选择 ⇒ 通过。
- **触发**：B16 把规则书写全后留下的最大数字轨缺口（`payGate` / `drawTrial` **全仓零引用**）。

**本批不做**：

| 项 | 归属 | 理由 |
| --- | --- | --- |
| 关隘**出牌比对**通道（`COMPARE`） | **B19** | 动作已定案（候选 A）但实现另排，避免与并行会话的 Action 契约工作相邻 |
| 裂隙经过判定 + 封路印放置 | **B18-b** | 需要「选格」动作参数与牌库总量连锁（主题包加卡 ⇒ `deckTotal` ⇒ 规格 §8 ⇒ 平衡重测） |
| 主题包数据结构 | **无需改动** | 关隘的标价与试炼池**早已结构化**（`board.tiles[].gate.fee` / `trialIds`；`trials[].effects` + 谓词）⇒ 引擎可直接执行 |

## 2. 关键裁定（6 项）

| # | 争议点 | 裁定 | 理由 |
| --- | --- | --- | --- |
| 1 | 通道选择发生在哪个阶段？ | **结算阶段**（到达关隘后手番暂停），不是行动阶段 | 行动三选一已被移动占用；结算阶段的二选一与「到达即结算」一致 |
| 2 | 要不要新增 State 字段（待过闸）？ | **不新增** —— 由「玩家位置在未通过的关隘格上」推导 | §6.2 契约冻结不必变更；状态可推导就不该存第二份 |
| 3 | 试炼的判定规则写在哪？ | **主题包数据**（`trials[].effects` + 谓词），引擎**不硬编码任何试炼文案** | 引擎只掷一次 20 面骰（供 `dice_is_at_least` 取值）并执行效果树 ⇒ 换主题即换规则 |
| 4 | 玩家能不能绕过关隘？ | **不能**：引擎层 `performAction` 在待过闸时拒绝一切行动 | 引擎层才是正确性保证；UI 的候选限制只是辅助（实测：AI 会在关隘格上反复行棋直到离开 ⇒ **免费穿关**） |
| 5 | 自动驱动的调用方怎么处理阻塞？ | 引擎层提供**统一出口** `advanceAuto`（对峙 + 关隘闭环） | 复制闭环逻辑 ⇒ 迟早漏一处 ⇒ 机制静默失效（B13 对峙的同款教训） |
| 6 | UI 判据怎么写？ | `web/legal-gate.ts` **独立再写一份**关隘判据 | 该文件的价值就是「与引擎枚举各自独立实现、再做集合相等比对」；借道引擎判据会让漂移守卫退化成恒等式 |

## 4. 验收

- 门禁 **10/10 全绿**（含门② 350+ 用例、门⑨ 模拟器冒烟、门⑩ 浏览器 E2E）。
- 关隘回归测试 **6/6 全绿**（`tests/engine/gate.test.ts`）。
- 平衡重跑：24000 局、无人封顶兜底率 8.5%、平均席位数 1.37、**异常 2 条**（裁牌修复后 7200 局复测为 0，但 24000 局仍残留 2 条 ⇒ 见 §5 R1，**如实登记不掩盖**）。
- 漂移守卫（`legal-probe.test.ts`）：引擎枚举 ⇔ UI 候选**集合相等**，新增动作类型两侧同步。

## 6. 复盘与经验沉淀

- **「引擎里有函数」不等于「机制接上了」**：`payGate` / `drawTrial` 一直存在、却**全仓零引用** ⇒ 规格 §3.5 在数字轨里是一句空话。⇒ 判据：机制要落地，必须有一条**从玩家动作到引擎入口**的完整链路（动作 → 粗筛 → 探针 → 引擎 → 状态）。
- **阻塞型机制必须给所有调用方统一出口**：关隘让 `advanceTurn` 提前返回 ⇒ 模拟器 / 测试 / 教学演示各自复制闭环逻辑，迟早漏一处 ⇒ 引擎层新增 `advanceAuto`。
- **正确性保证必须在引擎层，不在 UI 层**：只在 UI 隐藏按钮，绕过 UI 直调引擎仍能免费穿关 ⇒ `performAction` 入口硬拒。
- **「异常 0」会骗人**：模拟器曾报「异常 0 条」却让玩家免费穿过关隘 —— 因为「免费穿关」不违反任何状态合法性判据。⇒ 机制类改动要同时看**可达性**与**不可绕过性**。
- **既有缺陷会被新机制放大**：本批的 4 条「手牌超上限」不是关隘的错，而是**放逐不清手牌 + 裁牌只裁活人** 这个既存缺陷被新时序推到了可观测频率。⇒ 遇到「新改动后出现的老症状」，先查**根因是不是老问题**，再决定改哪里。

# B63 · G-g 复议裁定接线（投票窗口关闭 + 轮末裁定）

> 批次号 B63 · 日期 2026-11-09 · 主题：把「复议裁定在数字轨**无人调用**」（G-g）**真正接上生产路径** ⇒ 复议票不再写进一个没人关闭的窗口。
> 前置：B62（`cf60781`）已提交；**B62 的提交哈希回填并入本批首个提交**（按「回填永不单独开提交」口径）。

## 1. 目标与范围

- **做**：① 把 `resolveAppeals` 接进**生产路径**（轮末结算 `advanceCertificationRound`）⇒ **投票窗口必关闭**；② 复议裁定后**清掉** `appealed` ⇒ 窗口不会**重复裁定**；③ 补常驻用例 + 专属变异自证；④ 同步两处「零调用方」旧注释与 README G-g。
- **不做**：AI 强度结论、AI 驱动对局、sidecar 进发布包、出牌费用语义裁定（G-a）、引擎 `act` 分支的 `pendingCert` 加固（G-b）——沿 B59 §2.4 的明令排除。
- **不改规格**：§5.3.2 第 3 条（第三方裁定）+ §4.1「成功质疑」定义**本来就是对的** ⇒ 本批只补实现，规格零改动。

## 2. 取证与诊断更正（本批最重要的产出）

**发现比 G-g 登记更严重**：G-g 登记的是「复议票写入一个没人关闭的窗口」；实际后果是 —— `advanceCertificationRound` 的轮末结算**主动跳过**已申请复议的座位（「由 resolveAppeals 处理」）⇒ **生产路径下待认证者一旦申请复议，就永远不会被结算**（卡在峰顶：不后退、不签印、不进入下一轮）。

| 步骤 | 做法 | 结果 |
| --- | --- | --- |
| ① 确认零调用 | `grep -rn "resolveAppeals"` | 生产路径（`engine/**`、`web/**`）**零调用方**；仅 `tests/sim/run.mjs` 调它 ⇒ **数字轨无裁定方** |
| ② 查轮末结算 | 读 `advanceCertificationRound` | 轮末循环**跳过** `c.appealed` 中的座位 ⇒ 不是「窗口不关」，而是**主体永不被结算** |
| ③ 实测场景 A | 5 人局：座 1 判不通过 → 座 0 申请复议 → 轮末 | **位置 32 → 31（峰顶 32）** ⇒ 待认证者被结算，不再卡住 |
| ④ 实测场景 B | 5 人局：座 1 判**通过** → 座 0 申请复议 → 轮末 | 窗口**已关闭**（`appealed=[]`）但位置仍在峰顶 ⇒ 判通过本就不该后退 ⇒ 行为正确（非缺陷） |
| ⑤ **A/B 对照**（关键） | HEAD 代码副本 vs 工作树代码，同一探针 | **HEAD**：裁定后 `appealed=[0]`（窗口仍开着）；**工作树**：`appealed=[]`（已关闭）⇒ **可观测的行为改变** |
| ⑥ 平衡报告定性 | HEAD 副本重跑 24000 局 vs 工作树重跑 | HEAD **22303** 席制结算 / 工作树 **22300**；且**工作树重跑与工作树文件逐字全等**（16 544 字节）⇒ **确定性**行为改变 |

> ⚠️ **更正上一会话的误判**：上一轮把「席位制结算 22303 → 22300 的 ±3」判为「**采样级差异 ⇒ 基线不动**」——**不成立**。模拟是**固定 seed 的确定性重放**（同 seed 同结果），逐字可比；差异 100% 来自 B63 的行为改变（复议窗口现在真的被关闭）⇒ **平衡报告必须随本批更新**，不是「基线不动」。

## 3. 关键裁定

| # | 争议点 | 裁定 | 理由 |
| --- | --- | --- | --- |
| 1 | 投票窗口何时关闭？ | **轮末关闭**（`advanceCertificationRound` 对每个已申请复议的待认证者裁定） | 规格 §5.3.2 第 3 条 + §4.1「该判定在当轮未被复议推翻」⇒ 裁定必须发生在**该轮内**；轮末是唯一「该轮已结束」的确定时刻 |
| 2 | 票未收齐怎么办？ | 多数决**必然不通过** ⇒ 视为「维持原判」（扣 1 灵枢 + 后退 1 格） | 窗口**必须**关闭，否则主体卡死；「未收齐 ⇒ 不通过」让关闭成为**确定**行为而非「看运气」 |
| 3 | 第三方不足 2 人怎么办？ | 沿用既有掷 6 面骰（4–6 算成功） | 规格 §5.3.2 已定案 ⇒ 不另立规则 |
| 4 | 裁定后要不要清 `appealed`？ | **要清** | 不清 ⇒ 轮末**再裁定一次** ⇒ 重复扣灵枢 / 重复后退。⚠️ A/B 实测证实：HEAD 上裁定后 `appealed` 仍为 `[0]` |
| 5 | 会不会重复执行「判不通过 ⇒ 后退」？ | 不会 | 轮末循环用 `c.appealed`（**裁定前**的快照）跳过复议座位 ⇒ 复议座位只由 `resolveAppeals` 结算一次 |

## 6. 复盘与经验沉淀

- **「零调用方」类缺陷要顺着**跳过分支**查，不只查调用方**：G-g 登记写的是「窗口没人关」，实测发现更严重的是「轮末**主动跳过**该座位 ⇒ 主体永不被结算」⇒ 归因只覆盖了表层。
- **注释与行为要有一份可比的证据**：B63 的行为改变用 **A/B 探针**（同一局面在 HEAD 与工作树各跑一次）坐实 ⇒ 不靠「读代码觉得对」。
- **确定性重放里，数字差异就是行为差异**：固定 seed ⇒ 逐字可比 ⇒ 报告数字变了**必须**归因到行为，**不能**冠以「采样级差异」。
- 已写入 `docs/沉淀/经验教训索引.md` **E116**（A/B 对照坐实行为改变 + 「跳过分支」比「调用方」更深的归因）；Agent Memory 同批沉淀 1 条。

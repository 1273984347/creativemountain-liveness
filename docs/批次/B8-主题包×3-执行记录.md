### 「换场景不是换措辞」怎么机械化

每套主题自带**专属名词表** domainWords（如科幻：终端 / 指令 / 算力 / 奇点 / 协议 / 日志）。
校验要求**每张认证题必须命中至少一个本主题名词** ⇒ 通用题无法蒙混过关。
首跑即抓出 hybrid 照抄仙侠的 glossary、三套各 2 张认证题与基准逐字相同、三套之间 3 张题重复。

## 5. 过程中发现并修复的三个真缺陷

### 5.1 phase_is 读错字段 ⇒ 天机牌昼夜机制整体失效（引擎缺陷）

- **现象**：B8 的标志卡要写「若本回合为夜」，实测昼夜两态结果完全相同。
- **根因**：engine/predicates.ts 的 phase_is 读 ctx.state.phase（回合阶段枚举 Phase = 天机/行动/山议/认证/终局），而 set_phase 写的是 state.phaseValue（night/day，规格 §6.2）。两者永不相等 ⇒ 规格 §6.2 定义的「全局阶段值」**没有任何谓词能读到**，天机牌「本回合为夜/昼」对任何主题包都无效。
- **为何 B2–B7 全绿**：此前**没有任何主题包用过 phase_is** ⇒ 缺陷被绿灯掩盖，直到 B8 第一次真正使用它才暴露。
- **修复**：PredicateMap.phase_is.value 改为 night/day 联合；实现改读 state.phaseValue；规格 §6.4 补参数白名单与修正记录；tests/engine/predicates.test.ts 常驻回归。
- **顺带补盲区**：theme-validate 原先只校验谓词**名**合法 —— 参数越界会让条件永不成立、卡牌静默失效。现补「谓词**参数取值**白名单」（phase_is / card_type_is / 比较运算符 / filter 五字段 / 数值非负等），判据从类型定义派生。

### 5.2 数字轨从未使用主题卡池（B5 遗留）

- **现象**：web/main.ts 只把 theme.counts.deckTotal 当作 B1 骨架的 deckSize 参数用，实际牌库是「测试牌N」；主题棋盘也未装载。
- **修复**：新增 engine/core/setup.ts 的 installTheme(state, theme)，把牌池 / 棋盘 / 天机 / 试炼 / 认证题 / 造物整套装进 State；**web 与对局测试共用同一条装配链**，避免「测试装配 ≠ 生产装配」。

### 5.3 天机牌文案承诺了效果里没有的事

- 基准仙侠 h_dusk 文案「本回合为夜：所有玩家的封口持续回合数 +1。」但 effects 只有 set_phase night；h_dawn 文案承诺「本回合为昼」但 effects 里没有 set_phase day。
- **修复**：h_dusk 文案改为「本回合为夜。」；h_dawn 补 set_phase day；三套新主题的对应文案同步对齐。

## 6. 踩坑

1. **.mjs 里写 TS 的 export interface** ⇒ SyntaxError: Unexpected token 'export'。改用 JSDoc typedef。（同一个坑踩了两次，要形成肌肉记忆）
2. **stripComments 会把字符串字面量替换成空串** ⇒ 谓词取值白名单派生出空数组 ⇒ 非法 phase_is 取值不判红（由常驻负样本当场抓到）。补 stripCommentsOnly（只去注释、保留字面量）。
3. **同文件分批 write 会静默覆盖** ⇒ 每个主题的数据拆成独立文件 build/theme-data/<id>.mjs，天然规避。
4. **门禁判红的价值**：第 ⑧ 门首跑即抓出 glossary 照抄与认证题重复 —— 人眼核对极易漏。

# B36 · 按需重扫 + 与 B34 基线逐组比对（可复现性实证）

> 批次号 B36 · 日期 2026-11-09 · 主题：证明「判定不变」不只是**看起来**没变，而是**逐组完全一致**的可复现结果；并确认门 ⑬ 判定不变。

## 1. 方法

- **按需重扫**：`node tests/sim/run.mjs --scan-reserves 0,1,2,3,4 --scan-seeds <20 个> --games 125 --scan-json docs/trial-reserve-scan.json`（5 取值 × 20 组 × 3000 局 = 100 个分组 · 约 9 分钟）⇒ 产物**不入库**（`.gitignore`）。
- **逐组比对**：新增工具 `docs/沉淀/compare-scan-baseline.mjs` ⇒ 以「余量@seedBase」为键，逐组比对**全部 7 个原始指标**（perK / failed / passedAfterFail / fallback / seats / rounds / anomalies），容差 1e-9；**任一不一致即红**。
- **门 ⑬ 复核**：读**基线快照**重算 ⇒ 与重扫产物互不干扰。

## 2. 验证结果

| 项 | 结果 |
| --- | --- |
| 逐组一致 | **100 / 100**（零漂移） |
| 每组局数 | 基线 3000 = 新扫描 3000 |
| 门 ⑬ 判定 | **不变**：余量 0 vs 2 ⇒ 兜底率 t = 2.860（临界 2.0246）、席位 t = 3.379（临界 2.0244）⇒ 均显著 |
| 与 B31 发布值之差 | 0.000 / 0.001 |
| 重扫的对比结论 | 与 B34 逐字一致（余量 3 席位 t = 2.16 显著、余量 4 兜底率 t = 3.58 / 席位 t = 8.30 显著） |

⇒ **结果可复现**：同样的 seed + 同样的局数 ⇒ 逐组完全一致 ⇒ 「判定不变」有了可执行的证据，而非仅凭汇总数字相近。

## 3. 为什么值得单独做这一批

- **汇总数字会掩盖组间漂移**：若只看总均值，个别组的差异可能被平均掉 ⇒ 「看起来没变」≠「没变」⇒ 必须**逐组**比。
- **基线的价值要靠实证兑现**：B35 把快照入库是为了「可复现基线」⇒ 本批证明它**确实**能重现同一结果（100/100）⇒ 基线不是死数据，而是**可对照的锚点**。
- **工具要可复用**：比对脚本入库 ⇒ 将来任何一次重扫都能立刻回答「与基线差在哪」。

## 4. 遗留（如实登记）

## 5. 复盘

- **可复现性要靠「逐组一致」的实证，而不是「汇总看起来没变」**：均值会掩盖个别组的漂移。
- **基线必须被真正用过一次**才知其有效 ⇒ 本批用「重扫 ⇒ 逐组对账」兑现了 B35 留下的基线。

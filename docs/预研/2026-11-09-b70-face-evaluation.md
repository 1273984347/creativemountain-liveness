## 结论（2026-11-11 重跑 · 全部取自 `docs/预研/data/b70-face-arms.json`，无手填估计值）

> 本轮是「合并前修复波」的**重跑**：play 面的注入点按终审 C1 下沉到出牌分支（两臂只差「选哪张牌 + 打谁」），
> 三面读数来自同一次运行。**修复前的 play 面读数（χ²=15.00625、31.0%→18.5%）作废**，原因见下。

### play 面

1. **判定**：「未检出改善」（χ²=0.072581 ≤ 临界 3.841；规格 §6 禁止把它写成「模型无用」）。
2. **配对计数**：b=64、c=60、χ²=0.072581 —— 差异不显著。
3. **座0 胜率**：基线 31.0% → 模型 30.0%（−1.0pp，噪声量级）。
4. **胜者变化率**：31.0%（b+c=124/400 局 —— 换掉的牌确实改变了约三成对局的胜者）。
5. **decide 调用**：666 次（`decide` 调用次数，不是 HTTP 调用次数；`fallbacks=0` 时两者相等）；延迟 p50=47ms / p95=61ms。
6. **回落 0 次 / 空候选 1327 次**。⚠️ 空候选 = **未问出口的到达数**（含站点≠面 / 面未登记 / 该面确无候选 / 收窄后为空），
   **不是**「该面无候选的时刻」：其中 1034 次是「站点≠面」的跨站点到达（认证/山议站点被 play 面的策略到达），
   293 次是「该面在本局面确无候选」—— 后者同时含 **待认证锁定回合**的到达与「`roll ≥ 0.85` 但付得起牌为 0」的到达（同口径合并）。
   ⚠️ **锁定回合的覆盖口径（终审 I1）**：play 面的「待认证锁定分支」注入点对模型臂**恒为 no-op** ——
   引擎的 §7 粗筛在 `p.pendingCert` 时 `actionWindowOpen` 直接早退（`engine/core/legal.ts:66`），
   `getLegalActions` 因此不发行棋/问天/出牌候选 ⇒ `askPolicy` 只能计 `emptyCandidates` 后回落。
   ⇒ **模型臂只覆盖非锁定回合**；锁定回合里基线照样按 `pickPlayableCard` 出牌，模型从未被问到。
   本批**不改**这个枚举口径（§7 粗筛属引擎可见性/枚举层，改动会越出 B70「不接入生产、零行为变更」的红线），
   只把覆盖范围如实写在这里与批次记录 §4；根因修复留后续批次。
7. **兜底局数**（终局走距峰顶格数结算）：基线 28 → 模型 38；**平均回合** 13 → 13。
8. **anomalies = 0**。

**读法**：C1 修复后本面只测「**选哪张牌 + 打谁**」——0.16/0.75/0.85 三段行动分段由同一个 `s.rng.next()` 决定，
两臂完全相同 ⇒ 出牌频率、身份被动、行棋/问天比例不再被臂替换。结果**未检出改善**：模型逐次选牌与启发式
（按效果强度 + 平价优先的 `pickPlayableCard`，目标取位置最高者）在本样本量下统计等价。**保持贪心，不接入。**
⚠️ 修复前的形状里模型臂「命中即整块决策跳过」⇒ 同时改掉了出牌频率/被动/行棋问天比例，那次读数
（χ²=15.00625、18.5%）是**双变量对比**，**不得**再被引作「模型选牌更差」的证据（终审 C1）。

### council 面

1. **判定**：「未检出改善」。
2. **配对计数**：b=74、c=71、χ²=0.027586 —— 差异不显著。
3. **座0 胜率**：基线 31.0% → 模型 30.3%（−0.7pp，噪声量级）。
4. **胜者变化率**：36.3%（改票改的是「谁被流放」，传导长 ⇒ 变化多但方向随机）。
5. **decide 调用**：400 次（= 每局恰 1 次山议投票 × 400 局）；延迟 p50=45ms / p95=59ms。
6. **回落 0 次 / 空候选 1339 次**（= 未问出口的到达数；按成因拆分：**站点≠面 1339**、面未登记 0、该面确无候选 0、收窄后为空 0
   ⇒ 全部是跨站点到达，约 3.3 次/局）。读者可用 `calls=400`（1 次/局）与这 1339 次对照自算：山议站点本身的到达每次都有候选，
   多出来的部分全是手番/认证站点「到达但不该问」的计数（终审 I3）。
7. **兜底局数**：基线 28 → 模型 15；**平均回合** 13 → 13。
8. **anomalies = 0**。

**读法**：山议投票与启发式（投给**位置最高**——距峰顶最近——的对手的 `pickTarget`）基本等价。**保持贪心，不接入。**

### certify 面

1. **判定**：「未检出改善」。
2. **配对计数**：b=25、c=32、χ²=0.631579 —— 差异不显著（b/c 都小 —— 认证动作本身低频）。
3. **座0 胜率**：基线 31.0% → 模型 32.8%（升 1.8pp，但远未过显著线）。
4. **胜者变化率**：14.2%（三面最低 —— 认证动作只在待认证时刻发生）。
5. **decide 调用**：553 次；延迟 p50=38ms / p95=50ms。
6. **回落 0 次 / 空候选 1365 次**（= 未问出口的到达数；按成因拆分全部为「站点≠面」的跨站点到达，约 3.4 次/局）。
7. **兜底局数**：基线 28 → 模型 59（改签印时机改变了终局路径）；**平均回合** 13 → 13。
8. **anomalies = 0**。

**读法**：方向为正但样本不足 —— b+c=57（25:32，c 侧占 56.1%）。按**当前不平衡度**反解
`(|b−c|−1)²/(b+c) > 3.841` 需要约 **271** 个不一致对（≈ 当前的 4.75 倍；按 400 局/臂产出 57 对 ⇒ 约需 **1900 局/臂**）；
「80+ 对就够」只对 ≈62:38 的更强效应成立，本批数据不支持。若未来要复验，应**只对 certify 面扩样**（提高 `B70_SEEDS` 即可，
机制不用动）；在此之前**保持贪心，不接入**。

### 固定声明

1. **只评估不接入**：`policy` 缺省 undefined、sim CLI 无新开关、门 ⑨ 基线未动。三面判定均为「未检出改善」⇒
   **无任何一面触发「该面值得接入，另立批次做门 ⑨ 重校准」的分支**。
2. **臂的定义（终审 C1 后）**：play 面**只**接管「选哪张牌 + 打谁」；0.16/0.75/0.85 三段行动分段由两臂同一个
   `s.rng.next()` 决定，完全相同。`FACE_TYPES` 不变（仍是「面 → 动作类型」的文档），只在 play 站点用候选过滤收窄为 `PLAY_CARD`。
3. **随机流口径（C1 后）**：两臂在每次手番都恰好消耗一次 `roll` ⇒ 分叉起点是「**实际打出的牌不同** ⇒ 之后的状态与
   rng 使用不同」，**不是**「改道命中时跳过了一次 rng」。配对比较仍成立（同 seed 起点相同）。
4. **对峙选牌**：两臂**同为引擎贪心**（`advanceWithDuel → advanceAuto` 的 `onDuelPick`，B70 的三面注入从未触碰它）。
   「对峙选牌保持贪心」的依据是规格 §1.2 的**整局驱动 spike**（b=14/c=4、χ²=4.5 显著变差；44/44 出最强牌的是启发式），
   **不是**本文件的三面读数（终审 I2）。B70 的三面读数只用于「play/council/certify 三面保持贪心」。
5. **服务口径**：`device=cuda`，总就绪 28.18s；评估总耗时约 1.2 分钟（三面 0.54 + 0.31 + 0.36，远低于 30 分钟/面预算）；
   跑完即停，端口 8711/8712 复验均为 `000`（连接被拒，无残留进程）。
6. **复跑命令**：先 `npm run sidecar:laya`（或 `node tools/laya-sidecar/up.mjs --weights D:/<local-libs>/laya-multilingual/model.safetensors`），
   日志里出现 `READY` 后 `npm run eval:faces`；无服务时 `npm run eval:faces` 打印 SKIP 且退出码 0。
   读数写到 `docs/预研/data/b70-face-readings.md` 与 `docs/预研/data/b70-face-arms.json`（**不会**覆写本文）。

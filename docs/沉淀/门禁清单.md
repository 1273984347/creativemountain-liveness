# 门禁清单（十道）

入口：`node tools/gate.mjs`（等价 `npm run gate`）。任一失败即 `exit 1`。
**门数声明 == 实跑门数**（自断言写在 `tools/gate.mjs`：`TOTAL_GATES !== GATES.length` 即红）。

## 十道门

| # | 名称 | 命令 | 职责 | 负样本锚点 | 前置依赖 |
| --- | --- | --- | --- | --- | --- |
| 1 | 语法与类型 | `tsc --noEmit` | 严格类型（strict + noUncheckedIndexedAccess + exactOptionalPropertyTypes） | 类型错 ⇒ 编译红 | 无 |
| 2 | 单元与门禁自检 | `node --test tests/**/*.test.ts` | 引擎单测 + 门禁纪律自检（A4/A5）+ 常驻负样本 | 见「负样本自证范式」 | 无 |
| 3 | 文档口径 | `tools/doc-sync.mjs` | 规格 ↔ 代码 ↔ 文档 双向校验（C1–C9） | C9：代码加字段但规格未登记 ⇒ 红 | 规格文件 |
| 4 | 单文件构建 | `esbuild.config.mjs` | 引擎+UI+主题内联成单 HTML（双击即玩） | 构建失败 ⇒ 红 | 无 |
| 5 | 主题包校验 | `tools/theme-validate.mjs` | 主题包结构 / 引用完整性 | 引用不存在 ⇒ 红 | 无 |
| 6 | IR 契约校验 | `tools/ir-validate.mjs` | `print/<theme>/ir.json` 的字段契约 | 字段错 ⇒ 红 | print 产物（自举） |
| 7 | 双轨一致性 | `tools/parity-check.mjs` | ① ir↔theme ② SVG↔ir ③ 数值溯源 ④ PDF 粗检 | 任一层漂移 ⇒ 红 | print 产物（自举） |
| 8 | 主题差异化核对 | `tools/theme-diff-check.mjs` | 四套主题互不雷同（规格 §10.1） | 主题雷同 ⇒ 红 | 无 |

## 依赖顺序（不可随意调换）

- 门 6/7 需要 `print/<theme>/` 产物 ⇒ 由 `ensurePrintArtifacts()` 缺失才生成（日常零开销）。
- 门 10 需要 `dist/` ⇒ 必须排在门 4 之后。
- 门 2 内含 `tests/gates/duel-negative.test.ts`，其副本自建 bundle 用的是 `esbuild.config.mjs` 的 `CM_BUILD_ROOT` ⇒ 不依赖仓库 dist。

## 产物自举（ensurePrintArtifacts）

`print/*` 在 `.gitignore` 里（实体件是生成物）⇒ 全新 clone / 干净副本里必然缺失。
门禁在跑门前检查：任一主题缺 `print/<id>/ir.json` ⇒ 跑 `build/build-print-all.mjs`（纯 node 脚本，不经 shell）。

## 纪律（A4，写在 `tests/gates/discipline.test.ts`）

1. 门禁脚本不得使用 `shell: true` —— shell 会改变退出码语义。
2. 门禁脚本不得把命令接进管道（`| head`、`| tee`、`| Select-Object`）—— 管道会让退出码变成最后一个命令的。
3. 退出码直取：`spawnSync(...).status` 就是被检查的结果。
4. 门数声明 == 实跑门数（绿洲 gate 的自断言）。

## 失败排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 门 3 红、报 ENOENT specs/... | 副本/干净环境缺规格文件 | 复制清单必须含 docs/（用 `git ls-files` 复制即可） |
| 门 6/7 红、报文件不存在（先跑 npm run build:print） | 产物缺失且自举失败 | 看 `[自举]` 段输出（多为 Playwright/Chromium 缺失） |
| 门 2 红在 discipline.test.ts | 门禁脚本自身违反纪律 | 按 A4 改正被检查的脚本 |
| 门 10 红在 duel-e2e.mjs | 浏览器环境问题 | 确认 dist/ 已构建、Chromium 可用 |
| 门 2 假红（负样本测试失败） | 共享工作树被并发改动 | 用隔离副本改副本，别在共享树改文件 |

## 新增门禁的 checklist

1. 在 `tools/gate.mjs` 的 `GATES` 数组追加条目（自断言会自动校验门数）。
2. 声明前置依赖（是否需要 dist/ 或 print/ ⇒ 调整顺序）。
3. 配一组常驻负样本（见「负样本自证范式」）。
4. 在 `docs/superpowers/specs/` 的验收口径里登记。
5. 更新本文件与 `README.md` 的门数表述。

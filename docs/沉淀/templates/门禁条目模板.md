# 模板：新增一道门禁

## 1. 门禁条目（写进 `tools/gate.mjs` 的 GATES 数组）

```js
{ name: '<门名>', cmd: process.execPath, args: [resolve('<入口脚本>')] },
```

约束：

- **不得** `shell: true`（纪律 A4），**不得**把命令接进管道。
- 退出码直取：`spawnSync(...).status`。
- 依赖 `dist/` 的门 ⇒ 排在 esbuild 门之后；依赖 `print/` 产物 ⇒ 由 `ensurePrintArtifacts()` 兜底。
- 加完自断言会自动校验门数（`TOTAL_GATES !== GATES.length` 即红）⇒ 顺手更新门数表述文档。

## 2. 负样本（见「负样本测试模板」）

| 项 | 内容 |
| --- | --- |
| 负样本 | 破坏<机制> ⇒ 本门必红 |
| 正样本 | 未破坏 ⇒ 本门必绿 |
| 隔离 | 临时目录改副本，finally 清理 |

- [ ] 规格 §9.2 验收口径 / §9.3 负样本要求登记。
- [ ] 负样本常驻测试（`tests/gates/`）。

- [ ] 若新增覆盖边界 ⇒ `tools/coverage-boundaries.mjs` 与规格覆盖边界表**同步**（B52 起：**逐条对应** —— 表内 `id` 列与机器清单**同序一一对应**，不只是条数一致）。

## 4. 验收

```

node --test "tests/**/*.test.ts"
```

两者全绿 + `git status` 前后一致（隔离负样本不得污染工作树）⇒ 可提交。

本索引只列**已在本仓实证过、且已通用化**的结论。每条给出：现象 → 根因 → 通用化 → 落地位置。
原始执行记录在 `docs/批次/`（过程与数据），本索引（方法与规则）。

## 三、规则与边界

| # | 现象 | 根因 | 通用化 | 落地 |
| --- | --- | --- | --- | --- |
| E7 | 4 人局全员并列最高票时一次放逐多人，存活数打到下限以下（24000 局出现 1 次） | 下限判据按「逐个提名者」判断 | 数量上限/下限规则若一次可处理多个对象，必须用**累计口径**；且这类低频边界必须靠单测钉住，不能指望模拟撞出来 | B10 记录 |
| E8 | 「先到者独占」的席位制单独用完全无效（12 组参数扫描全落在 12.0–15.6pp） | 资产是整数且唯一，后来者要拿 2 份才能超越，结构上不可超越 | 遇到「新机制没效果」先问**缺的是哪一维**，再**一维扫描**找有效区间；不要多维乱试 | B11 记录 |
| E9 | 参数扫描副本与生产模拟器读数差 9pp，差点得出反向结论 | 扫描代码是另写的一份实现，漏了一次状态赋值 | 扫描/实验代码必须**复用生产入口**（加临时开关覆盖），不要复制一份实现；临时开关收官前删干净 | B11 记录 |
| E10 | 造物牌 cardId 与普通牌同名，看着像 id 冲突 | 造物牌本就**必须**引用普通牌 id，校验器强制这条 | 看起来该修的重复值/重复 id，先读校验器的判据 —— 它往往编码着设计意图 | B12 记录 |
| E11 | 对峙/新机制引入后，同一函数里的早 return 分支让后续逻辑永不执行 | 多职责共用一个 switch，分支提前 return | 同一函数承担多个职责时，要么分离成两段，要么所有分支走同一条出口（break + 统一收尾） | B13 记录 |
| E12 | 自动落败分支用「未选牌 == undefined」判断「无牌可选」 | 「未完成 / 不存在 / 为空」三个语义复用了同一个 undefined | 状态判据要用各自的语义字段，不能都落到 undefined 上 | B13 记录 |

| # | 现象 | 根因 | 通用化 | 落地 |

## 五、文档与生成链

| # | 现象 | 根因 | 通用化 | 落地 |
| --- | --- | --- | --- | --- |
| E18 | 规则书「补好了」，但成品里字面印着 `### 福地`、`| 福地 | ... |`、`**加粗**` | 叙述渲染器只认 `#` / `##`，其余 Markdown 一律当普通段落 | 「补规则」不只是补文字 —— **必须确认渲染器认不认那种语法**；内容侧的「写好了」≠ 成品侧的「看得懂」。补渲染能力（`###` / 表格 / 行内 `**`）后，成品残留从「大量」降到 0 | B16 记录；`build/narration.ts` |
| E19 | 隔离副本里中文路径的文件**静默缺失**（门禁报 ENOENT，像环境坏了） | `git ls-files` 默认 `core.quotePath=true`，非 ASCII 路径被**转义并加引号** ⇒ 按该字符串拼路径根本不存在 | 凡用 `git ls-files` 的输出拼路径，必须加 `-c core.quotePath=false`；否则中文名文件（规格、规则书叙述、中文文档）全部漏掉 | `tools/repo-copy.mjs` |
| E20 | 副本里报「模块找不到」，但仓库里明明有那个文件 | 副本只复制**已入库**文件（`--cached`），本批**新建**的模块尚未入库 | 副本语义应是**工作树快照**：`--cached --others --exclude-standard`（排除 .gitignore 项）。否则「必须先提交才能自检」的循环依赖 | `tools/repo-copy.mjs` |
| E21 | 负样本「删掉某要点」后门禁仍然绿 | `String.replace` **只替换第一处**；同一要点在表格与正文各出现一次 ⇒ 删了一处另一处还在 | 负样本的破坏点若可能出现多处 ⇒ 一律用 `replaceAll`，或按锚点定位到**唯一**位置；并用 `assert.notEqual` 兜底防静默失效 | `tests/build/rules-book.test.ts` |
| E22 | 契约清单（地形要点）写成了 `export interface` ⇒ `.mjs` 加载直接 SyntaxError | `.mjs` 里写了 TS 语法 | `.mjs` 一律用 JSDoc 表达类型；需要类型提示时另配 `.d.mts`（仓内既有先例：`ir-validate.d.mts`） | `tools/rules-book-contract.mjs` + `.d.mts` |

| E23 | 门禁② 偶发红（报「规格必须含『门禁覆盖边界』小节」），**单跑该测试文件却全绿** | `tests/gates/mutation-samples.test.ts` **就地改写共享工作树**的规格 / state.ts（改→跑→恢复）⇒ 门② 跨文件并发时，并行读的 `discipline.test.ts` 读到了**破坏窗口内的中间态** | 负样本**一律在隔离副本里改副本**。「集中在同一文件内即可互不干扰」只解决了**负样本之间**的冲突，**没解决与其它测试文件的冲突** ⇒ 判据：负样本若对仓库有任何写入，就不是负样本 | `tests/gates/mutation-samples.test.ts`（B17 改造） |
| E24 | 规格里一条规则写着「失去本回合剩余行动」，但**任何路径下都不可能触发** | 地形在**手番末**结算（结算时唯一一次行动已用完）+ 每回合仅一次行动 ⇒ 旧节奏遗留 | 写规则前**先与实际节奏对账**（结算时机 + 行动次数）；无执行语义的条款**裁定删除**，不要加一个永不触发的字段（那等于死机制） | 规格 §3.4 + §13.5（B17 裁定） |
| E25 | 规格缺口（如动作 `COMPARE` 有类型无行为）时，容易「顺手定一个」 | 动作带 `cardId`+`target` 说明原设计有未写下的意图；规格里没有 ⇒ 凭空定案会把猜测写成规则 | 规格缺口**写清候选 + 倾向 + 待评审确认**，而不是直接实现；「倾向 A」比「就是 A」诚实 | 规格 §3.5（B17 写定的 B18 方案） |

| E26 | 规格写明「关隘有两条通过通道」，但引擎里的 `payGate` / `drawTrial` **全仓零引用** ⇒ 数字轨里那是一条空话 | 函数被实现了，但**没有从玩家动作到引擎入口的完整链路**（动作 → 粗筛 → 探针 → 引擎 → 状态） | 「引擎里有函数」≠「机制接上了」。判据：机制落地必须有一条**端到端链路**；可用「零引用检测」当场发现（grep 函数名在仓库里的引用点） | B18 记录；`engine/core/gate.ts` |
| E27 | 关隘让回合推进被阻塞 ⇒ 模拟器 / 测试 / 教学演示**各自复制**闭环逻辑 | 每处调用方各写一遍「解算阻塞再推进」 | 阻塞型机制必须在**引擎层给所有调用方一个统一出口**（本仓：`engine/core/advance.ts` 的 `advanceAuto`）；复制闭环逻辑 ⇒ 迟早漏一处 ⇒ 机制静默失效 | B18 记录；`engine/core/advance.ts` |
| E28 | 只在 UI 隐藏按钮 ⇒ 绕过 UI 直调引擎仍能**免费穿过关隘** | 正确性保证写在了**表现层** | 正确性保证必须在**引擎层**（本仓：`performAction` 入口硬拒）；UI 的候选限制只是辅助层 | B18 记录；`engine/core/turn-runner.ts` |
| E29 | 模拟器报「异常 0 条」，但机制其实**完全失效**（玩家免费穿关） | 「免费穿关」不违反任何**状态合法性**判据（体力/资源/位置/手牌都正常） | 「异常 0」≠ 机制可用。机制类改动要同时看**可达性**（机制发生过吗）与**不可绕过性**（能不能绕过它白拿好处） | B18 记录 |

| E30 | 规则自洽性要在**实现前**复核：一条看似有博弈的设计，可能在实现后变成「没人愿意用」 | 「放置者本人也要判定」⇒ 放印有 50% 概率自伤 ⇒ 机制形同虚设 | 机制设计要问「**最优策略会不会用这个机制**」；若不会 ⇒ 规则自相矛盾。发现后**更正裁定并记录理由**，而不是硬实现 | B18-b 记录；规格 §3.4 |
| E31 | 「加一张卡实现新机制」会牵动一整条链，且新卡可能整局抽不到 | 牌池 +1 ⇒ `counts.deckTotal`（校验强制相等）⇒ 牌库组成与平衡全变；规模档牌库量 ≤ 卡池时新卡**进不了牌库** ⇒ 机制半死 | 加卡前先算连锁面；能用**引擎内建的结算期选择**实现时，优先不加卡 | B18-b 记录；`engine/core/barrier.ts` |

| E32 | 异常只写「座N 手牌超上限」，推演四轮定位不到；加上**手牌/上限/位置/round/turnIndex/phase/各玩家位置**后一眼看出共同特征 | 异常消息的**诊断密度**不足 | 异常必须带**足够定位的上下文**：共同特征往往就藏在某个字段里（如「超限者全部停在关隘格」）⇒ 体检输出要能一眼看出分布 | B18-c 记录；`tests/sim/run.mjs` |
| E33 | 把「回合末流程被吞」当缺陷去修，其实**回合末还没到** | 末位手番的玩家还卡在关隘上选通道 ⇒ 回合末本就该等 | 遇到「某个阶段没跑」先问「**它到了吗**」；把「延后」当「缺陷」会修错地方 | B18-c 记录 |
| E34 | 结算期（手番结算之后）发生的动作产生的牌没人裁 ⇒ 终局时手牌超上限 | 结算期通道选择（关隘试炼）发生在手番末裁牌**之后**，而回合末裁牌被阻塞延后 ⇒ 两处兜底都救不了 | **谁产生谁负责**：结算期产生的副作用当场处理（与「天机牌发的牌立即裁」同款），不要指望别处兜底 | B18-c 记录；`engine/core/gate.ts` |

| E35 | 动作类型在契约里躺了很久，却**从未有过行为语义** ⇒ 引擎无从实现，只能显式判拒 | 动作联合只规定**形状**，不规定**行为** | 动作契约要连同**行为口径**一起定（比什么、怎么比、胜败各如何），否则「有类型」给人「已实现」的错觉 | B19 记录；规格 §3.5 |
| E36 | 给关隘加第三条通道后，**位次胜率极差从 <4pp 反弹到 5.5pp** | AI 若「总是」先走比牌（胜则免灵枢过关）⇒ 资源经济被改写 | **多通道并存时，通道顺序 = 强度**。新通道要么不给 AI 走，要么限定在「旧通道不可用时」才走；每次改通道策略都要重跑平衡回归 | B19 记录；`engine/core/advance.ts` |

| E37 | 「失败 ⇒ 改为付费」这类后果，状态该落棋盘还是落玩家？ | 「本关改为付费」语义是「**玩家 × 这座关隘**」⇒ 落 `player.flags` 即可 | 状态落**语义正确的层** ⇒ 免改 Tile / IR 契约（否则牵动 3 个门禁 + 双轨校验）；且算子的格号参数要**可缺省**（试用者当前格）—— 同一张牌可能被多座关隘引用，写死格号会绑死棋盘 | B19-b 记录 |
| E38 | 机制把玩家「转」到另一条通道后，若那条通道也走不通 ⇒ **永远卡住** | 阻塞型机制只设计了「转换」，没设计「转换后仍不可行」的兜底 | 阻塞型机制**必须永远留一条出路**（本仓：转为付费后仍付不起 ⇒ 判「未通过并放行」并写放行标记） | B19-b 记录 |

| E39 | 同一件事出现两处实现（数字轨缩放棋盘 / 实体件缩放棋盘）⇒ 实体件迟早印出与实际对局不一致的棋盘 | 两边各写一份适配逻辑 | 同一件事只能有**一份实现**：抽到共享模块（如 `engine/core/board-fit.ts`）让两边共用 ⇒ 结构性防漂移；且**版本清单从源头派生**（规模表 ⇒ 实体件版本自动跟随），不手抄 | B20 记录 |

| E41 | **中性名也是内容**：中性格会进实体件 ⇒ 含任何主题术语都会被门⑧ 判「串戏」（实测「山道 N」里的「山道」是 hybrid 的术语 ⇒ 科幻/都市被判串戏） | 中性名是**要印在实体件上**的可见文本 | 中性名必须**完全中性**（「第 N 段」）；造中性内容时也要过主题差异化门 | B21 记录 |
| E42 | 主题包 JSON 是**手工紧凑排版**（部分成员同行）⇒ 整体 JSON.stringify 往返会让**全文变成 diff** | 序列化会展开所有紧凑成员 | 对手工排版的文件做批量改造要**文本级替换**；且脚本要先做「JSON 往返与原文逐字相同」的**格式自检**，不一致就改走文本级 | B21 记录；`docs/沉淀/theme-board-expand.mjs` |

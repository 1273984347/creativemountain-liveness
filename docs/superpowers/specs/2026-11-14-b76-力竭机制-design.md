## 0. 定位与立项更名

B76 在仓内的历史定义是「死亡/复活」（§13.3 延后项、B75 设计头部）。**本批裁定更名为「力竭」**：

> **核心判断（用户裁定）**：不要「死亡」，要「力竭」。放逐下限恒为 3 的设计前提是「放逐是唯一出局通道」——
> 若 HP 归零也出局，场上人数可能因「被打死」降到 2，§5.6 的下限逻辑、§5.2 的签印门槛公式、§5.8 的兜底排名
> 全要重审，**不是 B76 一个批次能收口的改动**。而「力竭」是比放逐更轻、可逆的惩罚：放逐仍是唯一真出局通道，
> 社交分量保留；「打空」从虚的变成实的——攻击牌与险径的代价立刻有分量。

**侦察发现（本规格的证据基础）**：

| # | 现状 | 与规格的关系 |
|---|---|---|
| 1 | `damage` op 在 hp 归零时**已置 `alive: false`**（且无放逐下限保护、无出局簿记——位置/手牌/待认证标记全不清） | 与 §13.3「本作没有死亡机制」**矛盾**的暗杀分支；本批将其替换为力竭触发，矛盾消解 |
| 2 | 险径黑牌扣血是 `Math.max(0, hp - 1)`，**不击杀** | 两条扣血路径行为不一致；力竭统一它们 |
| 3 | `poison` 状态**纯写入、零结算点**（engine/core 无消费方，与 `skip_turn` 同族） | **本批不修**（用户裁定）：poison/slow/silence/skip_turn 四态的死机制归后续「死状态家族」批次；力竭期间「不再触发新力竭」与 poison 是否结算无关 |
| 4 | `handLimitOf = hpMax`（体力上限即手牌上限，§4.2） | 力竭的「上限减半」落点精确：改 `handLimitOf` |
| 5 | `survive_with_hp` 判据 = `p.hp >= p.hpMax`（开局 hp = hpMax ⇒「初始值」≡ hpMax） | 力竭解除时 hp 恢复到 `ceil(hpMax/2)` < hpMax ⇒ 该目标在力竭历史后需靠 `heal` 补回，**这是设计意图**（力竭有持久代价），不是 bug |
| 6 | `ActionType` = 19 成员（B75 收口值） | 新增 `RECUPERATE` ⇒ 20 |

## 1. 目标 / 非目标 / 反目标

**目标**：
1. HP 归零产生**真实且有界的竞争代价**（手牌上限减半、移动 -1、主动被动封锁、不可质疑），激活攻击牌与险径的决策分量；
2. 放逐的社交设计**原样保留**——§5 全章（下限 3 / 签印门槛 / 兜底排名 / 凭证 / 否决）零改动；
3. 三条恢复路径让「救与不救」成为真实的社会互动（自恢 / 自然恢复 / 他人救援）。

**非目标**：
- 不引入死亡、复活、第三种出局通道（`alive: false` 仅放逐可置——本批收口 damage 的暗杀分支后）；
- 不修 poison / slow / silence / skip_turn 的死机制（已登记，归后续批次）；
- 不做主题差异化（「力竭」是通用机制词，四主题 glossary 不动）；
- 不动 §8 规模表、§11 平衡公式本体。

**反目标**（做错了就算失败）：
- 力竭成为**事实上的出局**（代价重到没人打攻击牌前先权衡逃跑）——「可逆且有界」是硬约束；
- 力竭-恢复变成**免费回血循环**（解除时 hp 只回 `ceil(hpMax/2)`，不是满血）；
- 复现 B75 刚修完的「只写不读」——力竭的每个效果都必须有**真实消费点**（上限/移动/被动/质疑四处全在引擎消费路径上）；
- `survive_with_hp`（守夜人目标）因力竭**永远不可达成**（解除 + heal 回补的路径必须存在且可达）。

## 2. 力竭状态定义

**触发**：任一 hp 扣减路径使 `hp === 0`（damage op / 险径黑牌）⇒ 置 `exhaustedRounds = 2`，**hp 保持 0**。
  ⚠️ **实际持续时长（评审 r1.2 落定）**：置 2 且触发**当轮末照减** ⇒ 覆盖「触发当轮剩余 + 完整 1 轮」（约 1.5 round），
  不是满 2 轮。理由：实现最简（无需记触发轮）；与反目标「力竭不成事实出局」相性最好；被打到 0 的当下损失
  （hp=0 ⇒ 上限减半立即影响下一轮裁牌）已自带一部分惩罚。用户评审未及裁定此点，按推荐落定、可推翻
  （若要满 2 轮 ⇒ 置 3，实现同样简单；读数与验收不受影响）。
**不触发**：已力竭者（`exhaustedRounds > 0`）再次归零**不再刷新**（不叠加、不清零重计）。
**解除**：`exhaustedRounds` 归零（见 §3）⇒ 状态解除，**hp = max(当前 hp, `ceil(hpMax / 2)`)**——「至少半血」的**保底**而非硬置：力竭期间被 `heal` 抠回来的血不白给（解除瞬间倒扣会惩罚救力竭者，与 §1 目标 3 的社交激励相性差）；同时守住反目标（不是满血、无免费回血循环）。
  ⚠️ 本条为 builder-check 遗留项，用户未及裁定，按 **max 保底**落定（标记为本规格的裁定，可在阅读时推翻——若改硬置，三处实现点与 survive_with_hp 读数要同步重估）。

**力竭期间的效果（四处消费点，全在引擎路径上）**：

| # | 效果 | 引擎落点 |
|---|---|---|
| 1 | 手牌上限 = `ceil(hpMax / 2)`（7→4、8→4） | `handLimitOf`（裁牌处自动生效） |
| 2 | 移动骰结果 -1（下限 1 格）——**先减后加**：步数 = `max(1, 骰面 - 1) + moveBonus`（力竭的惩罚作用在骰面本身，`moveBonus` 是外挂加成、在此之后叠加，不受力竭扣减） | `move_by_dice`（仅骰移；卡牌位移不动） |
| 3 | 主动被动封锁（观星者 / 窃火者 / 织梦者 / 匠师的「行事发动」） | `abilityAvailability` 前置拦截 |
| 4 | 不可发起质疑（作为认证人）；**签印 / 弃权 / 复议申请照常** | `certifyChallenge` + 枚举层 + UI 门禁三层同判 |

**明确不变**：`alive` 保持 `true`；`hasMark` 不清；认证资格、认证印、投票权（山议 2 票 / 匿名投票）照常；
「每场 1 次」计数器不消耗；印记不因力竭失效；**出牌（`PLAY_CARD`）照常**——力竭封锁的是主动被动与质疑，不是出牌（手牌上限减半是间接惩罚）。

**被质疑权（评审 r1.1 ②）**：力竭者作为**待认证者**时，**仍可被他人质疑**——力竭不提供质疑豁免。
与「力竭者作为认证人不可发起质疑」的不对称是**刻意的**：力竭削弱的是「主动施压」的能力，不是「被检验」的资格。

**与负面四态的关系**：力竭是**机制状态**、不是负面状态——**不入 `NegativeStatus` 枚举**（免疫算子对它无效，
这是刻意的：`exhaustedRounds` 是独立字段，不在四态的免疫通道上）。力竭期间再中 poison：poison 照常写入
（它本就无结算点，见侦察 #3）；hp 归零不触发新力竭（已在力竭中）。

**与待认证叠加**：合法。待认证锁定只禁**位移**（§5.1）；力竭只禁**主动被动与质疑**。叠加时：签印 / 弃权 /
复议申请 / RECUPERATE 自恢照常，质疑不可。力竭解除发生在认证轮内也合法（不干扰认证轮次）。
**待认证者救援他人（评审 r1.3 ③）**：玩家 A 待认证（不力竭）、玩家 B 力竭 ⇒ A **可以**花 1 灵枢 + 手番 `RECUPERATE` 救援 B——救援不是位移，不触发 §5.1 待认证锁定；救援不消耗认证轮次、不影响 `certification` 字段（与 R-B76-4 同组钉死）。

**裁牌时点（评审 r1.1 ⑥）**：力竭触发**不立即裁牌**——手牌上限变化在该玩家**下一次回合末裁牌**时生效
（与 `handLimitOf` 的常规调用点一致）。理由：触发可能发生在别人回合（damage），立即裁会让攻击者「顺带帮目标弃牌」，手感突兀。

**与护盾的交互（评审 r1.1 ⑧）**：`damage` 先扣盾再扣 HP ⇒ 护盾**延迟**力竭（盾耗尽且 HP 归零才触发），
本身不改变触发条件（HP = 0）。力竭机制下**护盾价值整体上升**——来源包括守夜人的回合末被动（B12 定案）与卡牌 `shield`。

## 3. 恢复路径（三条）

| 路径 | 代价 | 语义 |
|---|---|---|
| **自然恢复** | 无 | 每 round 末全体 `exhaustedRounds - 1`（全局 round 口径）；归零即解除并回血 `ceil(hpMax/2)` |
| **自恢** | **2 灵枢 + 1 手番行动** | 动作 `RECUPERATE`（不带 target）；力竭者本人发动，**不受力竭封锁**（恢复动作是元动作）；灵枢不足 ⇒ 引擎拒绝（§3.5 同款「资源不足即拒绝」） |
| **救援** | **1 灵枢 + 1 手番行动** | 动作 `RECUPERATE`（带 target）；救援者**不能力竭**、必须存活；目标必须是**已力竭的存活者**；**任意距离**（用户裁定：救援是社交行为，与签印/放逐同族，不看位置） |

**恢复时点**：自恢 / 救援即时生效（hp 立即抬到 `max(当前 hp, ceil(hpMax/2))`、`exhaustedRounds` 清 0）；自然恢复在 round 末（同一保底口径）。
**救援交互**：救援者付出行动（手番被占用）；同一 round 内同一目标被救一次即解除（`exhaustedRounds` 已清 0 ⇒
后续救援动作非法——「目标必须已力竭」前置天然防重复）。

## 4. 用户裁定的三项实施决策（2026-11-14）

| # | 裁定 | 理由 |
|---|---|---|
| 1 | **单动作 `RECUPERATE { actor, target? }`**：自恢（无 target，2 灵枢）与救援（有 target，1 灵枢）共用成员 | 镜像 `PLAY_CARD` 的 `target?` 形状；契约 19→20、key 样本 +2、三层同判与 §6.3 全套同步是**一次**工作量（两个成员会翻倍） |
| 2 | **poison 不在本批修** | 死状态家族（poison/slow/silence/skip_turn）归后续批次；本批顺手补 poison 会打开「四态怎么办」的口子且扩大重标定面 |
| 3 | **救援任意距离** | 救援是对话与资源行为，与山议投票 / 认证签印同族（都不看距离）；实现最简、社交互动最强 |

## 7. 平衡与重标定（B35 流程）

- 力竭激活攻击牌 ⇒ AI 出牌带与身份胜率都会变 ⇒ **全量重标定**（24000 局报告）+ 发布基线 **B76** 重扫（B75.2 快照保留）；
- 锁现值复核：身份极差 < 15pp（R8 注记顺带复核——开拓者读数应不受力竭影响）、位次极差 < 5.5pp（力竭的 -1 移动对先手的影响要读数）、门 ⑨⑪⑫ 冒烟；
- **护盾价值上升**（守夜人的回合末被动 + 卡牌 `shield` 两个来源都在「先扣盾后扣血」路径上延迟力竭）是预期结果；另一面是 `survive_with_hp`（守夜人目标）在力竭历史后更难达成，守夜人作为存活型身份的相对优势也上升——两股力方向相反，读数说话。若身份锁破口，先查护盾分布与守夜人目标达成率再议（B75.1 遗留 2 的纪律）；
  ⚠️ 评审 r1.1 曾提出「守夜人被动与护盾无关」，经引擎（`turn-runner.ts:428` 的 `[被动:shield]` 分支）、主题包（`passiveText: 回合结束获得 1 点护盾`）与规格 §4.1（B12 定案）三处核对，**现行守夜人被动就是回合末护盾**——评审该条前提不成立，已按合并口径落定；
- `survive_with_hp` 达成率会下降（力竭历史 + hp 只回半血）——它是守夜人的目标，读数需 > 0；若归零，登记后单独处置（不静默放宽阈值）。

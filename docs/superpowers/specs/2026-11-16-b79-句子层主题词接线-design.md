## §0 立项

### §0.1 一句话

引擎与 UI 产出的中文句子里住着基准仙侠的词（「灵枢 / 关隘 / 山道 / 峰顶 / 灵力」），而牌面与规则书按主题印「算力 / 异能点 / 灵能」「安全闸 / 封锁线 / 阵门」——**非仙侠主题的对局界面通篇说别人的话**。本批把句子层的取词接到主题词表上，并把取词层从两份合成一份。

## §1 红线：本批是零行为批次

主张：**游戏行为一字不改**——只改中文句子的取词来源，与（Q4 带来的）指令骰 face 15 一句措辞。

判据链（本轮实测，非推理）：

1. **门⑪⑫⑬ 与 policy 的计数键只认机制前缀**：`力竭：`、`（自恢）`、`（救援）`、`（自然）` + `STATUS_LOG_PREFIX` 五串（`poison_tick 中毒扣血：` 等，`engine/core/statuses.ts:36-42`）⇒ 无一含主题叶词。
2. **门⑪ 的失败标记判定读 flags 与结构化字段**，不读文案：`run.mjs:300` `flags['gate_pay_' + gateIndex]`、`run.mjs:302-305` `entry.trialId / entry.trialPassed`、`run.mjs:354` `fallbackWrites !== times - passes`。
3. **门⑨ 冒烟默认跑四套**（`run.mjs:28 THEME_IDS`，`--check` 不改默认），但 stdout 里唯一可能带 note 文本的是异常样本（`run.mjs:673` ← `summary.anomalySamples`），而异常串只有机制文案（`policy.mjs:620/822/823`：死循环 / 未分出胜负 / 超出全局回合上限），且 `--check` 断言**异常 = 0** ⇒ 一行都不打。
4. `--record-decisions` **默认关闭**（开了才把含 log 的全量 `stateToJson` 落盘），「报告逐字不变」已由 `tests/gates/sim-record.test.ts` 锁。
5. `docs/baselines/*.json` 与 release 逐组比对的判据是**数值**（实测无 note 文本、无主题词）。

⇒ **验收口径**：门 ⑨ `run.mjs --games 30 --check` stdout 逐字节相同；`npm run release` 的 100 组重扫逐组比对 ≡ `docs/baselines/trial-reserve-scan-B77.json`。
**漂移处置**：按 E116——固定 seed 的确定性重放里数字差异**就是**行为差异 ⇒ **停下归因**，不重基线、不放宽任何锁（含 5.5pp 位次极差参考线）。

**例外须单列**：face 15 措辞会改 `print/*/ir.json`、`svg`、规则书**文本**（不碰 `pred` 与数值）；`docs/balance-report.md` 会因 §2.3 的标签改词重生成 1 行。这两类是**生成物文字变化**，不许混进「零行为」主张，须在提交信息里逐条点名。

## §3 词表归一（数据改动，**先于**接线落地）

「界 = `TERM_LEAVES` 闭合枚举」这句话要成立，得先把 `path/peak` 放进枚举——否则 `expandThemeWords` 遇到 `{path}` 要么抛错打断正常文案，要么静默印出 `{path}`。

**主题词分两类**：
> - **地点/资源类（本批处理）**：`resource / gate / path / peak / hp`（`deck` 见 §4.4 排除）。它们出现在引擎/UI 的中文句子里 ⇒ 改占位符。
> - **卡面/题面取词类（B78 已接线，本批不动）**：`types.{4} / colors.{2} / statuses.{3}`。走 `termWord` 查表，不经句子层。
> 两类都必须在 `TERM_LEAVES` 里；本批只把第一类的前五个接进句子层。

### §3.3 门⑤ 补 R6 欠的等值守卫

`terms.{hp,resource,gate,path,peak}` ≡ `glossary.{HP,resource,gate,path,peak}` 逐字判等，负样本「只改 `glossary.gate` ⇒ 判红」（正是 B78 验收 12 写好却没人实现的那条）。`deck` 继续豁免并写明理由——**实测四套全部不等**（`符箓`/`道箓`/`指令`/`异能牌` vs `符箓库`/`道箓库`/`指令库`/`异能库`），因为牌库名 ≠ 单张牌名。

### §3.4 界面四处改读 `terms`（硬依赖边）

`web/main.ts:490`、`web/main.ts:527`、`web/ui/cert.ts:171`、`web/ui/hand.ts:55` 现在读 `theme.glossary.resource`，而 `web/ui/log.ts` 的 `instructionText` 读 `theme.terms`——同一个 `{resource}` 两个来源。**施工顺序是硬依赖，不是备注**：§3.3 的等值守卫**先落或同提交**，再改这四处，保证两表不一致时当场红，而不是「悄悄换了另一套来源」。

### §3.5 `glossary` 退回印刷层 + 注释改真实归属

`glossary` 保留为**印刷层专用对照表**（`hand / seal / plain / boon / hazard / rift / branch / player` 只有 `build-print` 读），句子层唯一取词 = `ThemeTerms`，由 §3.3 钉住两边不许分叉。`tools/ir-validate.mjs:42` 的注释改成真实归属，**交叉引用到函数名**：「与 terms 的五键判等在门⑤ `checkTrialTruth`（B79 §3.3）」。

### §3.6 hybrid `path` 改词 + 门⑧ 扩表

`path` 升格为必填叶后进门⑧ 必须差异化 ⇒ 现状 `hybrid.path = 山道 ≡ 基准` 会当场红。改词落点实测 **1 个键 × 2 张表**：`themes/hybrid/theme.json` 的 `glossary.path`（现值「山道」，主题正文别处无引用）与 §3.1 新增的 `terms.path` 必须同时改——§3.3 的五键判等会抓住「只改一张」。

- 建议词：**「栈道」**（备选「云阶」「索桥」）——融合套的门/顶/资源是「阵门 / 道顶 / 灵能」，「栈道」同时接得住山岳地貌与工程结构，且与其余三套不撞。
- 门⑧ ② 从「glossary 四核心术语」扩成「四核心术语 + `terms` 五叶」，并按**跨套两两不同**判（现口径只比基准）。实测改词后五叶四套全不同 ⇒ 新守卫不会自红。

## §4 占位符与展开层

### §4.1 新文件 `engine/core/theme-text.ts`

/** 把 {resource} 一类占位符换成主题词；缺叶抛错，绝不静默留 `{path}`。 */
export function expandThemeWords(raw: string, terms: ThemeTerms): string;

### §4.2 `instructionText` 复用同一实现

### §4.3 展开出口（实测收敛到四类位置）

| 出口 | 位置 | 处理 |
|---|---|---|
| 日志 | `web/ui/log.ts:13 logLineText` | 唯一日志出口，就地展开 |
| notice | `web/main.ts:600`（`ui.notice` 的唯一渲染点） | 展开 |

**不改签名**：`uiBlockNotice(state, seat, action)` 拿不到 `terms`（这正是它硬编码「灵枢」的原因），但 `uiAllows` 的判据是 `=== null`——文案是副产品。加 `terms` 参数要改 40 个调用点并把「说的」重新耦合到「判的」；占位符只多一个纯函数。

**已接受的代价**：`state.log[].message` 与导出存档里存的是 `{resource}` 原文，裸读 JSON 的可读性下降；换来的是引擎零主题词。历史日志**不迁移**（旧行保持当时的文本，本批不碰存档信封版本）。

### §4.4 `deck` 不进句子层：同形词

`scifi-ai.terms.deck = '指令'`，而「问天**指令**骰」「第 N 条**指令**」是四套共用的**规则词**（无叶）。把 `指令` 放进 R1 禁字表会把合规实现判红。⇒ 本批禁字表 = 五叶 19 词，`deck` 四值（符箓/道箓/指令/异能牌）不进；实测 `engine/web` 句子里 `deck` 取值 0 处，不接线不亏。

**跨套重词的处理**：实测只有 `path`（山道 = 基准 ≡ hybrid）重词。它不影响 R1（源码只许写 `{path}`，谁的字面量都不行），但决定 **R3 必须按当前主题取词**——全局并集会把 hybrid 局里合法的「山道」判成基准泄漏。

## 0. 定位与立项

引擎里有**五个**状态类算子只写不读：`poison` / `slow` / `silence` / `skip_turn` 写入 `Player.statuses`（`engine/ops/registry.ts:415-458`），`immunity` 写入 `Player.flags.immunity_<status>`（`engine/ops/registry.ts:459`）。**全仓唯一读取 `statuses` 的地方是 UI 徽章**（`web/ui/hand.ts:71`），`immunity_*` 连徽章都不读。

后果是这些规则**已经印在实体件上、却一条都不发生**：

- 卡面：蚀骨「使其中毒 1 层」、缚灵「减速 1 层」、断送「跳过 1 个回合」、封口「使一名对手封口 1 回合」、凝神「免疫封口 2 回合」；
- 规格：§3.4「（裂隙被拦）失败则**停 1 回合**」、§5.4「败或平局 ⇒ 退 1 格并**被封口**」、§2 术语映射「封口＝**弃牌＋禁言一回合**」。

同时，12 张关隘试炼牌里 **9–10 张的题面与引擎判定谓词矛盾**（§2.4），而实体试炼牌的 IR **只带题面文本**（`build/build-ir.mjs:138`）⇒ 玩家手上的牌写着条件 A，引擎判的是条件 B。

两件事必须同批：12 张试炼里有 3 张的奖励**就是 `immunity`**（`t_oath` 免疫封口 / `t_silent` 免疫减速 / `t_vital` 免疫中毒）⇒ 单独回正题面只会得到「题面正确地描述了一件不存在的事」。

## 1. 目标 / 非目标 / 反目标

**目标**

1. 五个算子各有**消费点**，且消费点复用 B76 已建的入口（§7 清单），不新建平行机制；
2. 结算锚点与顺序**规格化**：两家族各单一出处（力竭 = round 末不迁移 / 状态族 = 该玩家手番末），见 §4；
3. `skip_turn` 有合法兑现手段：`PASS` 端到端接线（§2.3）；
4. 试炼题面从 `pred`/`then` **派生**，加常驻「题面 == 派生」守卫，并钉住「`fallback` 条目数 == 0」（§6）；
5. 重标定与发布基线换代（§9）。

**非目标**：不改攻击牌强度、不改 HP 基准、不动 `shouldVeto`(0.15) / 自恢(0.5) / 救援(0.10) 三个占位概率（B76 §6 已集中登记，归调平衡批次）；不引入死亡/出局新通道（放逐是 `alive:false` 唯一通道，B76 已收口为常驻断言）。

**反目标**：❌ 不让 `silence` 影响山议投票与认证流程（§3.6）——封口惩罚的是「用牌与发动能力」，夺走社交判决通道会让一次封口变成双重出局；❌ 不做「免疫即解状态」（§3.5）。

### 2.2 ⚠️ 读数更正：本批的设计输入换了一批数字

上一轮讨论引用的写入频次来自 **B75.2 回合末清零接线之前**的引擎，接线改变了资源流动与关隘路径频次，**排序整体翻转**。现行 6000 局（4 主题 × 1500，8 人；探针 monkey-patch `OPS` 计数，脚本留在会话临时目录、未入仓）：

| 算子 | 旧口径（B75.1 引擎） | **现行 HEAD** | 激活后的可见性预期 |
|---|---|---|---|
| `poison` | 0.72/局 | **1.290/局** | **主力**（唯一通往 HP 的路径，见 §3.1） |
| `skip_turn` | 0.48 | **0.823** | 次主力（0.82 次/局手番被跳过） |
| `slow` | 1.06 | **0.233** | 接线 + 可取证，**不承诺读数变化** |
| `silence` | **2.88** | **0.227** | 同上；旧数字的「主力」判断作废 |
| `immunity` | — | 0.725（其中针对 silence 0.554） | ⚠️ 空转高危，见 §11 R2 |
| `damage` | 3.90 | 2.712 | 参照 |

`silence` 掉一个数量级的机制原因：B75.2 恢复回合收入 ⇒ AI 更常**付费**过隘，而 `silence` 的两个写入点都在关隘失败侧（`gate.ts:317` 比牌未胜、`gate.ts:345` 未通过放行）。

⇒ 本批判据只能写「**五件全部有消费点、生效可取证、poison 路径抬升力竭触发**」，**不**写「silence 成为可见压制」。力竭触发基线 = **4 人次 / 每百局 0.02**（`docs/balance-report.md:20`），poison 是它唯一的新增来源。

## 3. 五件语义（裁定落地）

> 通用形状：**层数 = 当回合强度，每 round 末衰减 1 层**（poison / slow）；**回合数 = 持续时间**（silence / skip_turn / immunity）。二者不混用。
>
> **累加语义（r2 红4）**：五算子一律 `+= amount`，**不存在「设层」**——`poison`/`slow` 加层、`silence`/`skip_turn`/`immunity` 加回合。这不是改动而是把既成事实写进规格：现行五处写入本来就都是 `(x ?? 0) + p.amount`（`registry.ts:415-464`）。理由：卡面「使其中毒 1 层」的「使其」是累加语气；若改成覆盖，连续中毒的第二发毫无意义，且 `t_vital`「免疫中毒」这类防御牌的价值会被凭空抹掉。**常驻断言**：五处写入路径不得出现 `statuses.<k> = amount` 形式的赋值。

### 3.1 `poison` 中毒 N 层

**该玩家自己的手番末**结算（`finishTurn` 尾部，§4 甲案）：**先按层数扣体力，再衰减一层**（2 层 ⇒ 本手番扣 2 点、下手番扣 1 点）。扣血致 `hp === 0` ⇒ 调 `triggerExhaustion`（B76 的**第三个**调用点，前两个是 damage op 与险径黑牌）。已力竭者不刷新（沿用 `exhaustion.ts:24`）。

⚠️ **两条触发路径的力竭时长必须等长（r3 取代 r2 红2）**：锚点分裂后，`damage`/险径（手番内触发）与 `poison`（手番末触发）都会被**同一 round 末的 ① 力竭递减**接手——2→1（本 round 末）→ 0（下 round 末），即都覆盖**恰好 1 个后续手番 ≈ 1.5 round**。r2 红2 预言的「poison 触发多一轮」是 round 末锚点下的产物，甲案下不成立。

**钉子用例**：两条路径各一条，断言触发 round 末 `exhaustedRounds === 1`（不是 2、不是 0）、下一个手番力竭效果在位、再下一个 round 末 `解除力竭：…（自然）`——**两条用例的期望值必须逐字相同**（防将来有人"顺手"给 poison 加一档）。

### 3.2 `slow` 减速 N 层

位移罚**并入 B76 既有表达式**（`engine/ops/registry.ts:351`），不新开第二处「下限 1」：

```ts
const penalty = ((pl.exhaustedRounds ?? 0) > 0 ? 1 : 0) + (pl.statuses.slow ?? 0);
const effective = Math.max(1, roll - penalty) + pl.turn.moveBonus;   // 先减后加，moveBonus 不变
```

层数即「本 round 减 N 格」，与 poison 的「本 round 扣 N 血」同构；round 末衰减一层。力竭与 slow 并存时**可叠加到 −2 及以上**，这是设计意图。

### 3.3 `silence` 封口 N 回合

- **禁言**（**N 个手番**：受害者接下来 N 个完整手番，每个自己的手番末 −1，r5 定稿）：`PLAY_CARD` 与 `ABILITY` 被封；`MOVE` / `ROLL_WHEEL` / `EQUIP_CARD` / `RECUPERATE` 照做；豁免族见 §3.6。装备不视为「发言」（B75 设计：装备不产生效果、不产生位移）。
- **弃牌**（一次性，**只在写入那一刻**弃 1 张）：`silence` 的弃牌是「被封口」这个动作的即时代价，不随持续时间重复 ⇒ 「封口 2 回合」＝弃 1 张 + 禁言 2 回合。手牌为空则不弃、不报错。
- **弃哪张 = 复用 `discard_self`，即弃手牌首位**（r3.3 撤销 r2.1 的「末位」偏离——**评审原话「最左」是对的**）：`applyStatus` 是 ops 层纯函数，拿不到玩家输入 ⇒「自选」在写入点**不可实现**（方案 A）；而「弃 N 张」在仓里已有唯一实现 `discard_self`（`registry.ts`：`dropped = hand.slice(0, count)` → 进 `decks.discard`），复用它就自动获得弃牌堆簿记与日志，不必新写第三份。方案 B（`pendingSilenceDiscard` 延迟到下得手番开头）会改「写入时」语义、多一个 State 字段、还要重审 D4——三样代价换一点能动性，不值。
- ⚠️ **登记一处既有 wart（本批不统一）**：仓里两套「不得不弃」的方向**本来就相反**——`discard_self`（出牌类弃牌）弃**首位**，`discardDownToLimit`（超上限裁牌）弃**尾部**（保留 `slice(0,limit)`）。封口属前者 ⇒ 跟随首位。统一它要动 B75.2 已定稿的裁牌轨迹（门 ⑨ 额外扰动），本批只在此登记，并在这两处各加一行注释互相指认。
- **零 `rng` 消耗、零交互**：位置确定 ⇒ 不抽签，UI 无需新增选牌模式（R1 风险随之消解，见 §11）。
- **被免疫时不弃牌**：拦截发生在写入之前 ⇒ 免疫挡下的是一整套「被封口」事件（弃牌 + 禁言），不是只挡状态。这条是把弃牌写进 `applyStatus` 的直接好处（§7 #4）。
- 现行量级：0.227 次写入/局 ⇒ 约 0.23 张弃牌/局，不会与力竭的减半上限（`hand.ts:10`）叠加成「手牌几乎清空」。

### 3.4 `skip_turn` 停 N 个回合

跳过**整个行动面**，但**回合末结算照做**（地形 / 收入 / 守夜人护盾 / 裁牌）——惩罚是「少一次行动」，不是「被抹掉一回合」。
**「N 个手番」的含义（r5 定稿）**：受害者接下来 **N 个完整手番**；若授予发生在受害者自己手番内，当前手番的剩余部分同样被封（状态 >0 ⇒ 引擎与枚举同判），但**不消耗额度**——豁免位只在「授予发生在该玩家自己手番内」时置位。实现手段：行动面候选**只发 `PASS`**，`PASS` 走 `finishTurn` → 推进的正常路径（§2.3、§7）。

与 silence 的相互作用（对上一轮 D4 的补注落地）：**弃牌在写入时已发生，skip 不吸收弃牌**；skip 期间 silence 的禁言被 skip 吸收（skip 的封锁集 ⊃ silence），但 **silence 的层数照常衰减**（否则被 skip 的那回合会把封口悬空一回合）。

**豁免族动作与手番归属（r2 红3）**：skip 期间执行**一个**豁免族动作 ⇒ **本手番立即结束**（正常行动面已封锁，豁免族是「解阻塞」而非「正常行动」；不消耗手番会让被停手番者白得多个动作，与「惩罚＝少一次行动」相悖）。同一手番内不得连续执行两个豁免族动作。

⚠️ **唯一例外：对峙面（`DUEL_SUBMIT_CARD`）不计额度、也不因其执行而结束手番**（r2.2）。证据：`advanceTurn` 第一行就是 `if (state.duel !== null) { return state; }`（`turn-runner.ts:447`）——对峙是**全局阻塞的双方状态机**，双方提交都在**同一次被阻塞的推进闭环内**完成（B13/B68）；若「提交即结束手番」，另一方将永远等不到亮牌 ⇒ 全场死锁。故对峙的提交视为**未决流程的继续**，不属于本手番的动作。

**钉子用例**：① skip + 停在关隘 ⇒ 提交 `GATE_RESOLVE` 后手番结束、`skip_turn` 层数在 round 末才减；② skip + 对峙 ⇒ 双方各提交一次，对峙结算完才推进，中途无任何一方「被结束手番」。

### 3.5 `immunity` 免疫 N 回合 = **持续窗**，不是抵扣

`flags.immunity_<status> > 0` 期间，该状态的**写入被拒**并写一条日志（`被免疫：<座位> 的 <状态>`）；窗口的「N 回合」= 受害者接下来 N 个完整手番（r5，与自己手番内授予的豁免位配合，`t_oath` 的免疫 1 回合恰好保护下一个完整手番）；**不清除已有层数**——免疫是预防不是解药，已中的 poison 照常扣血、照常衰减。⚠️ 施工者不得「顺手」在授予免疫时解状态。

`immunity_*` 继续寄居 `flags`（不迁容器：`set_flag` / `clear_flag` 也写 flags，迁移要动存档与 IR 契约），但**由 §4 的统一递减块一并处理**，并在函数注释里写明「两处容器、一个递减点」。

### 3.6 判据顺序与**豁免族**（对上轮 D6 的技术性修正）

上轮顺序 `skip_turn > silence > 力竭封锁` 成立，但**漏了一类**：结算期的解阻塞动作。若被封者停在未通过的关隘上而 `GATE_RESOLVE` 也被禁，他就**永远出不去**（门 ⑨ 死循环）。故完整优先级：

```
① 结算期解阻塞与社交/认证流程（**永远发放**，不参与封锁）
   GATE_RESOLVE · COMPARE(关隘第三条通道) · BARRIER_RESOLVE · DUEL_SUBMIT_CARD
   · PASS · VOTE · COUNCIL_VETO · CERTIFY_*
② skip_turn  ── 封 MOVE / PLAY_CARD / ABILITY / ROLL_WHEEL / EQUIP_CARD / RECUPERATE
③ silence    ── 封 PLAY_CARD / ABILITY
④ 力竭封锁   ── 封 ABILITY（passives.ts:108）/ CERTIFY_CHALLENGE（certification.ts:155，既有）
```

⚠️ `COMPARE` 归入豁免族是**取舍而非显然**：它是出牌动作，但更是关隘的第三条解阻塞通道（规格 §5.4）；不豁免 → 死锁，豁免 → 封口者仍可能比牌过隘。取「不制造死锁」，并在此登记。

拒因文案的**优先级顺序同属三层同判**：引擎、枚举、UI 三处必须先说同一句（例如三者都以「你被停手番」开头，而不是引擎说力竭、UI 说封口）。

## 4. 结算锚点与顺序（全局约束，r3 重写）

> **r3 推翻 r2 的「全部挤在 round 末」。** 现查证据：每名玩家每 round **恰好一个手番**（`round.ts:17-27` 的 `aliveOrder[turnIndex % len]` + `isRoundEnd` 的 `turnIndex >= aliveCount`），而 `skip_turn` / `silence` / `immunity` 的写入点全部在**该玩家自己的手番内**（裂隙判色 `barrier.ts:63`、关隘失败 `gate.ts:317/345`、凝神一类是自己在行动阶段出牌）⇒ 若统一在 round 末递减，这些状态会在该玩家下次行动**之前**就被抹平：「停 1 回合」一个手番都停不到、禁言永不生效、免疫窗恒为 0。r2 版 §4 是错的，六个计数器会全为 0。

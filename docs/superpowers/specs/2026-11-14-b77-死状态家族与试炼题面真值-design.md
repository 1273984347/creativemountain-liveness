## 0. 定位与立项

引擎里有**五个**状态类算子只写不读：`poison` / `slow` / `silence` / `skip_turn` 写入 `Player.statuses`（`engine/ops/registry.ts:415-458`），`immunity` 写入 `Player.flags.immunity_<status>`（`engine/ops/registry.ts:459`）。**全仓唯一读取 `statuses` 的地方是 UI 徽章**（`web/ui/hand.ts:71`），`immunity_*` 连徽章都不读。

后果是这些规则**已经印在实体件上、却一条都不发生**：

- 卡面：蚀骨「使其中毒 1 层」、缚灵「减速 1 层」、断送「跳过 1 个回合」、封口「使一名对手封口 1 回合」、凝神「免疫封口 2 回合」；
- 规格：§3.4「（裂隙被拦）失败则**停 1 回合**」、§5.4「败或平局 ⇒ 退 1 格并**被封口**」、§2 术语映射「封口＝**弃牌＋禁言一回合**」。

同时，12 张关隘试炼牌里 **9–10 张的题面与引擎判定谓词矛盾**（§2.4），而实体试炼牌的 IR **只带题面文本**（`build/build-ir.mjs:138`）⇒ 玩家手上的牌写着条件 A，引擎判的是条件 B。

两件事必须同批：12 张试炼里有 3 张的奖励**就是 `immunity`**（`t_oath` 免疫封口 / `t_silent` 免疫减速 / `t_vital` 免疫中毒）⇒ 单独回正题面只会得到「题面正确地描述了一件不存在的事」。

## 1. 目标 / 非目标 / 反目标

**目标**

1. 五个算子各有**消费点**，且消费点复用 B76 已建的入口（§7 清单），不新建平行机制；
2. round 末结算顺序**规格化**并单一实现（§4）；
3. `skip_turn` 有合法兑现手段：`PASS` 端到端接线（§2.3）；
4. 试炼题面从 `pred`/`then` **派生**，加常驻「题面 == 派生」守卫，并钉住「`fallback` 条目数 == 0」（§6）；
5. 重标定与发布基线换代（§9）。

**非目标**：不改攻击牌强度、不改 HP 基准、不动 `shouldVeto`(0.15) / 自恢(0.5) / 救援(0.10) 三个占位概率（B76 §6 已集中登记，归调平衡批次）；不引入死亡/出局新通道（放逐是 `alive:false` 唯一通道，B76 已收口为常驻断言）。

**反目标**：❌ 不让 `silence` 影响山议投票与认证流程（§3.6）——封口惩罚的是「用牌与发动能力」，夺走社交判决通道会让一次封口变成双重出局；❌ 不做「免疫即解状态」（§3.5）。

## 2. 侦察战利品（现查于 2026-11-14 HEAD `523ed3d`）

### 2.1 五个算子的消费点为零

`grep statuses engine/ web/` ⇒ 只有 `state.ts:96` 类型定义、`registry.ts` 五处**写入**、`web/ui/hand.ts:71` 显示。`immunity_<status>` 除写入点外无任何读取。

### 2.2 ⚠️ 读数更正：本批的设计输入换了一批数字

上一轮讨论引用的写入频次来自 **B75.2 回合末清零接线之前**的引擎，接线改变了资源流动与关隘路径频次，**排序整体翻转**。现行 6000 局（4 主题 × 1500，8 人；探针 monkey-patch `OPS` 计数，脚本留在会话临时目录、未入仓）：

| 算子 | 旧口径（B75.1 引擎） | **现行 HEAD** | 激活后的可见性预期 |
|---|---|---|---|
| `poison` | 0.72/局 | **1.290/局** | **主力**（唯一通往 HP 的路径，见 §3.1） |
| `skip_turn` | 0.48 | **0.823** | 次主力（0.82 次/局手番被跳过） |
| `slow` | 1.06 | **0.233** | 接线 + 可取证，**不承诺读数变化** |
| `silence` | **2.88** | **0.227** | 同上；旧数字的「主力」判断作废 |
| `immunity` | — | 0.725（其中针对 silence 0.554） | ⚠️ 空转高危，见 §11 R2 |
| `damage` | 3.90 | 2.712 | 参照 |

`silence` 掉一个数量级的机制原因：B75.2 恢复回合收入 ⇒ AI 更常**付费**过隘，而 `silence` 的两个写入点都在关隘失败侧（`gate.ts:317` 比牌未胜、`gate.ts:345` 未通过放行）。

⇒ 本批判据只能写「**五件全部有消费点、生效可取证、poison 路径抬升力竭触发**」，**不**写「silence 成为可见压制」。力竭触发基线 = **4 人次 / 每百局 0.02**（`docs/balance-report.md:20`），poison 是它唯一的新增来源。

### 2.3 `PASS` 是两端未接的契约成员

`Action` 里有 `{ type: 'PASS', actor }`（`engine/core/action.ts:58`），key 编解码（`action-key.ts:15/102`）、`probe.ts:113`、`web/legal-gate.ts:260`、探针文案（`state-text.mjs:188`「结束手番」）四处 case 齐全，但 **`legal.ts` 从不发它、`performAction` 没有 `'pass'` 分支**。skip_turn 需要「本手番无事可做但仍要推进」的出口 ⇒ 本批把它接上，且**只在 `skip_turn` 生效时发放**（避免给每个手番多一个候选、扰动门 ⑨ 基线）。

### 2.5 48 条题面的派生可行性：今天 100% 可派生

`pred` 全集只有两种：`has_card_count`（32 条）、`dice_is_at_least`（8 条）；`then` 五种：`draw_cards`(16) / `immunity`(12) / `gain_resource`(8) / `heal`(4) / `shield`(4)。**没有一条需要手写**。

但 `terms` 词表的正身不在数据里：四套 `theme.json` **均无 `terms` 字段**，它只存在于 `build/theme-data/*.mjs`（生成器输入），而基准仙侠**连 theme-data 文件都没有**（它是生成器的源）。现行 `terms` 只有 4 键（`hp` / `deck` / `resource` / `gate`），派生题面还缺**类型名**（4 类）与**颜色名**（2 色）⇒ 见 §6.2。

## 3. 五件语义（裁定落地）

> 通用形状：**层数 = 当回合强度，每 round 末衰减 1 层**（poison / slow）；**回合数 = 持续时间**（silence / skip_turn / immunity）。二者不混用。

### 3.1 `poison` 中毒 N 层

round 末结算：**先按层数扣体力，再衰减一层**（2 层 ⇒ 本 round 扣 2 点、下 round 扣 1 点）。扣血致 `hp === 0` ⇒ 调 `triggerExhaustion`（B76 的**第三个**调用点，前两个是 damage op 与险径黑牌），力竭计数器置 2、**当轮不再递减**（§4 顺序 ① 已过）。已力竭者不刷新（沿用 `exhaustion.ts:24`）。

### 3.2 `slow` 减速 N 层

位移罚**并入 B76 既有表达式**（`engine/ops/registry.ts:351`），不新开第二处「下限 1」：

```ts
const penalty = ((pl.exhaustedRounds ?? 0) > 0 ? 1 : 0) + (pl.statuses.slow ?? 0);
const effective = Math.max(1, roll - penalty) + pl.turn.moveBonus;   // 先减后加，moveBonus 不变
```

层数即「本 round 减 N 格」，与 poison 的「本 round 扣 N 血」同构；round 末衰减一层。力竭与 slow 并存时**可叠加到 −2 及以上**，这是设计意图。

### 3.3 `silence` 封口 N 回合

- **禁言**（持续 N 个 round，每 round 末 −1）：`PLAY_CARD` 与 `ABILITY` 被封；`MOVE` / `ROLL_WHEEL` / `EQUIP_CARD` / `RECUPERATE` 照做；豁免族见 §3.6。装备不视为「发言」（B75 设计：装备不产生效果、不产生位移）。
- **弃牌**（一次性，**只在写入那一刻**弃 1 张）：`silence` 的弃牌是「被封口」这个动作的即时代价，不随持续时间重复 ⇒ 「封口 2 回合」＝弃 1 张 + 禁言 2 回合。手牌为空则不弃、不报错。
- 弃牌选择：**玩家自选**（UI 新增选牌交互，照抄 B75 装备模式）；模拟器按既有「最劣牌」启发式；**零 `rng` 消耗**。
- 现行量级：0.227 次写入/局 ⇒ 约 0.23 张弃牌/局，不会与力竭的减半上限（`hand.ts:10`）叠加成「手牌几乎清空」。

### 3.4 `skip_turn` 停 N 个回合

跳过**整个行动面**，但**回合末结算照做**（地形 / 收入 / 守夜人护盾 / 裁牌）——惩罚是「少一次行动」，不是「被抹掉一回合」。实现手段：行动面候选**只发 `PASS`**，`PASS` 走 `finishTurn` → 推进的正常路径（§2.3、§7）。

与 silence 的相互作用（对上一轮 D4 的补注落地）：**弃牌在写入时已发生，skip 不吸收弃牌**；skip 期间 silence 的禁言被 skip 吸收（skip 的封锁集 ⊃ silence），但 **silence 的层数照常衰减**（否则被 skip 的那回合会把封口悬空一回合）。

### 3.5 `immunity` 免疫 N 回合 = **持续窗**，不是抵扣

`flags.immunity_<status> > 0` 期间，该状态的**写入被拒**并写一条日志（`被免疫：<座位> 的 <状态>`）；**不清除已有层数**——免疫是预防不是解药，已中的 poison 照常扣血、照常衰减。⚠️ 施工者不得「顺手」在授予免疫时解状态。

`immunity_*` 继续寄居 `flags`（不迁容器：`set_flag` / `clear_flag` 也写 flags，迁移要动存档与 IR 契约），但**由 §4 的统一递减块一并处理**，并在函数注释里写明「两处容器、一个递减点」。

### 3.6 判据顺序与**豁免族**（对上轮 D6 的技术性修正）

上轮顺序 `skip_turn > silence > 力竭封锁` 成立，但**漏了一类**：结算期的解阻塞动作。若被封者停在未通过的关隘上而 `GATE_RESOLVE` 也被禁，他就**永远出不去**（门 ⑨ 死循环）。故完整优先级：

```
① 结算期解阻塞与社交/认证流程（**永远发放**，不参与封锁）
   GATE_RESOLVE · COMPARE(关隘第三条通道) · BARRIER_RESOLVE · DUEL_SUBMIT_CARD
   · PASS · VOTE · COUNCIL_VETO · CERTIFY_*
② skip_turn  ── 封 MOVE / PLAY_CARD / ABILITY / ROLL_WHEEL / EQUIP_CARD / RECUPERATE
③ silence    ── 封 PLAY_CARD / ABILITY
④ 力竭封锁   ── 封 ABILITY（passives.ts:108）/ CERTIFY_CHALLENGE（certification.ts:155，既有）
```

⚠️ `COMPARE` 归入豁免族是**取舍而非显然**：它是出牌动作，但更是关隘的第三条解阻塞通道（规格 §5.4）；不豁免 → 死锁，豁免 → 封口者仍可能比牌过隘。取「不制造死锁」，并在此登记。

拒因文案的**优先级顺序同属三层同判**：引擎、枚举、UI 三处必须先说同一句（例如三者都以「你被停手番」开头，而不是引擎说力竭、UI 说封口）。

## 4. round 末结算顺序（全局约束，单一实现）

五个 round 级递减 + 力竭全部挤在 `endRound`（现行力竭递减在 `turn-runner.ts:577-586`，`clearTurnStates` 在 575）。**必须写成一个显式块**，否则「先扣 poison 还是先减 immunity」这类歧义不会让测试红，只会让 24000 局读数漂移无从归因。

```
① 力竭递减：exhaustedRounds>0 且 −1==0 ⇒ recoverFromExhaustion('自然')，否则 −1（死者不递减，I2 既有）
② poison 结算：先扣 hp（−层数，clamp 0），−1 层；hp 归零 ⇒ triggerExhaustion（置 2，当轮不再执行 ①）
③ slow 衰减：−1 层
④ silence 衰减：−1 回合
⑤ skip_turn 衰减：−1 回合
⑥ immunity_* 衰减：−1 回合（本轮的写入判定用的是衰减**前**的值）
```

排序理由：① 先跑保证 B76 既有语义逐字不变；② 在 ① 之后 ⇒ poison 触发的力竭当轮不被顺手减一层；③–⑤ 在 ② 之后 ⇒ 层数「先作强度、再作衰减」；⑥ 最后 ⇒ 免疫窗覆盖它所在的整个 round。

**附带项（不在 round 末，列此只为完整性）**：放逐侧 `council.ts` 清状态时，`statuses` 与 `immunity_*` 须和既有的 `exhaustedRounds: 0` 同处一起清（B76 最终审查 I2 的同一条纪律）——死者不得带着状态离场。

施工约束：新增 `engine/core/statuses.ts` 导出 `tickRoundStatuses(state)`，内部严格按 ①–⑥ 顺序，每步注释指向本规格条目号；`endRound` 只留一行调用 + 一行指向 §4 的注释。**不允许**在别处再写任何 statuses/immunity 的递减。

## 6. 试炼题面真值

### 6.1 派生器

新增 `build/trial-text.mjs`：`renderTrialText(effect, terms)` ⇒ 由 `conditional.pred` 生成条件句、由 `then` 生成奖励句，复用 `theme-render.mjs` 的 `renderEffect`（`then` 就是效果）。生成器 `build-themes.mjs:161` 的 `data.trials[i]` 手抄文本列表**删除**，改为派生 ⇒ 「人抄的真相」这条缺口在试炼侧关闭，与卡牌的 `renderCardText` 纪律对齐。

### 6.2 `terms` 的正身（本规格自裁的一项，评审可推翻）

**裁定：`terms` 提升为 `theme.json` 的正式顶层字段，四套齐备，不进 IR。** 理由：门 ⑤ 的顶层检查是**必填白名单**（`theme-validate.mjs:27` 的 `requiredTop` 只查缺失），现查**无顶层多余键拒绝逻辑**（唯一的「多余参数」判红在 `:173`，作用域是 op 参数）⇒ 加字段零风险；守卫与生成器同读 theme 数据 ⇒ 无第二事实源（对齐 `docs/沉淀/从源码派生避免第二事实源.md`）；基准仙侠从此**可自证**。键集：现有 4 键 `hp`/`deck`/`resource`/`gate` **＋** 新增 `types{motion,attack,defense,utility}`（4 词）＋ `colors{red,black}`（2 词）＝ 10 键。派生三套由 `data.terms` 写入（生成器负责），基准手写。施工前置：给门 ⑤ 加一条 `terms` 十键必填校验，并加一条**未知顶层键不影响**的正样本（把上面这个「现查」变成常驻断言）。

### 6.3 白名单 + fallback（守卫的可扩展形状）

`renderTrialText` 维护**可派生白名单**：`has_card_count` / `dice_is_at_least`（§2.5 已证今天覆盖 100%）。白名单外的 `pred` 走 fallback：保留手写 `text`，但派生器**必须**在产物上标 `fallback: true`。

守卫（新常驻，挂**门 ⑤ 主题包校验**内，不动 13 门的门数与 B52 覆盖边界口径）三条断言：

1. 每条试炼 `text === renderTrialText(effects[0], terms)` —— 不一致即红，并打印**第一条差异路径**（沿用 `tests/build/themes-generated.test.ts` 的失败信息惯例）；
2. `fallback: true` 的条目**只查 text 非空**，不查相等；
3. **四套 `fallback` 条目总数 == 0** —— 今天必须为 0；将来真要加非机械判定，得显式改这个数字并在批次记录说明理由。此条防的是「有人塞进一条手写题面，靠 fallback 静默绕过守卫」——即本批要治的病复发。

### 6.4 一石三鸟

派生化同时解决：① 9–10/12 错牌（回正）；② B75.2 遗留 2 的「派生主题印出基准专有词『灵枢』」——派生文本走 `terms.resource`，四套各用自己的词；③ 基准主题不可派生的洞。附带收益归零的代价：`t_oath` 等 12 张牌的题面措辞变朴素（机械句＋奖励句），叙事性由 `terms` 承担——**内容批次（B78 主题）可再润色，本批以正确性优先**。

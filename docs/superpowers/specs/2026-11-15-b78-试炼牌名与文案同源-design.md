## §2 试炼牌名（48 条）

### 2.1 字段裁定

`trials[].name` 是**正式字段**（用户裁定甲）：`readonly name: string`，与 `TrialCard.text` 同级、**必填**。形状对齐既有先例——天机牌已经是 `{id, name, text}`（`parity-check.mjs:91` 的主比对字段就是 `['name','text']`），所以本批不是新发明，是把试炼牌补到同一等公民地位。

### 2.2 三条命名判据

| 判据 | 内容 | 机器/人工 |
|---|---|---|
| **同侧规则** | 同一个 `trial id` 的四套名字必须指向**同一侧**（条件 / 后果 / 门槛），不许一套指条件、另一套指结果 | **无机器检查**（今天不存在也不计划加“同侧 warning”）⇒ 由人工逐字对照 §2.4 表；门 ⑤/⑧ 只判撞名、禁字、长度。⚠️ 门 ⑧ 的 `SAME_NAME_ALLOWED` 是**同名**判据的出口，与同侧无关，两者不许混 |
| **命名侧选择规则** | 默认走**条件侧**（名字的活是「这场考验在叙事上是什么」，题面的活是「引擎判什么」，不重复印量化措辞）。两个例外由数据强制：① **条件相同的族必须走后果侧**——`t_stone` 与 `t_mantra` 同为「功能×2」，只在后果（回复 vs 护盾）上分，若都走条件侧则同套内两条名字形同双胞胎；② **骰子型走门槛侧**——`t_wind`（≥6）与 `t_star`（≥12）无牌面条件，只能靠门槛高低命名 | 人工（写死在本表注释里，防止下一个人「统一回条件侧」） |
| **禁字表（合并版）** | 禁：数字（`0-9`/`０-９`）、`张`、`枚`、`点`、`至少`、`不低于`、`≥`、`红色`、`黑色`、`回合`（B77 第 2 节原裁定）**+ 类目词**`试炼`、`关隘`、`封锁线`、`安全闸`、`阵门`（本批合并）。**≤ 6 字** | 门 ⑤ 硬拦。**单字颜色/单字关允许**：禁的是词组——`红移`、`赤步`、`朱守` 合法，`红色校验`、`关隘` 非法。合并理由：类目词禁的是「与头部『{gate}试炼』重复印在一张牌上」，原禁字禁的是「把题面的量化口径搬进名字」，两者不冲突且对现表零命中（已实测） |

### 2.3 本表的身份声明（防止误读）

**本表 = B78 第 2 节已逐条评审通过的表，只替换一格**：`t_toll` 仙侠「血守」→「朱守」（「血守」因血腥基调被用户否；「赤关」被弃用是因为它会让同列三赤，且「关」与仙侠头部「关隘试炼」读成重复）。其余 47 条**未重取**。凡后续再有人改这张表，必须写明改动了哪几格、为什么。

## §3 `name` 的契约链与版面

### 3.1 九站（少一站就是「数据里有、牌面上没有」）

| 站 | 位置 | 改动 | 漏掉的后果 |

| 3 | `build/theme-data/{urban-psych,scifi-ai,hybrid}.mjs` | 新增 `trialNames: readonly string[]`（12 条，按位对位） | 生成器无源 |
| 4 | `build/build-themes.mjs` `trials.map` | `name: data.trialNames[i]`（缺失即抛，沿用同文件「数少于基准即抛」的形状） | 派生主题 name 为空 |
| 5 | `build-ir.mjs:138` | `{ id, name, text }` | **实体件印不出来**（print 只读 IR） |
| 6 | `engine/types/ir.ts` `IrDocument.trials` | 加 `name` | IR 契约与产物漂移 ⇒ 门 ⑥ |
| 7 | `tools/ir-validate.mjs` 可追溯段 | 从「只比 `text`」扩成「比 `name` + `text`」 | IR 里 name 与 theme.json 不一致无人查 |
| 8 | `tools/parity-check.mjs:90` / `:136` | 主比对 `['text']` → `['name','text']`（与 `:91` 天机牌同形）；`must` 加一行试炼牌名 | 「进了 JSON 没进版面」查不到 |
| 9 | `build/print-parts.ts:215` `trialSvg` | 标题行渲染 + 空 name 短路 | 牌面上没有名字 |

**站 3 的键名不许改回 `trials`**，注释原样写进代码：B77 曾有一个 `trials` 字段（手抄题面）已被删除；复用旧名会让「这个字段是不是又回来了」的歧义重现。`trialNames` 只承载 12 条名字，不承载任何文本。

**站 8 第二半是 S2 的机器防线**：`checkSvgVsIr` 用「去空白后子串包含」判文本是否真被渲染 ⇒ 把 name 加进 `must` 等于断言「这个名字确实印在牌上」，而不是只在数据里活着。⚠️ **禁止裸 `t.name`**：若 name 与页脚/正文有子串重叠会误匹配。施工时先跑一次 `trialSvg` 取实际标题行格式，再定锚定串（形如 `试炼·<name>` 的带上下文前缀），把结论写进 `must` 那一行的注释。

### 3.2 版面（用户裁定甲）

卡面 69×94mm，正文可用 63mm，现行 12 张题面折成 3 行 = 14.4mm ⇒ 加一行标题不挤爆任何东西。

- **甲案**：头部第一行保持「`{gate}`试炼」+ 右上 `#N`；**新增第二行** = name（字号 6.4 加粗、左对齐）；正文起点 `pad+20` → `pad+27`。
- 弃乙案（把头部左串换成 name、类目挪页脚）的两条理由：① 类目是玩家识别「这是试炼牌不是符箓」的第一层信息，不能为名字让位；② 页脚即将在 R2 里变成**派生的规则句**，再往页脚堆东西会让「页脚 ≡ 派生」那条守卫的措辞比对复杂化。
- **渲染层防御（不是门禁）**：`if (name)` 短路——name 为空串时标题行**不渲染**、正文起点**不下移**。门 ⑤ 本已拦空 name，这条只是保证「数据错也印不出空白标题行 / 错位正文」。
- **SVG 文件名保持 `试炼牌-01-t_mirror.svg`，不含 name**（name 易变、中文进文件名有编码风险）。将来「按名字找牌」用 `print/<主题>/ir.json` 的 `trials[]` 反查，不靠文件名承载易变字段——这条同时进 §6 不做清单。

### 3.3 IR `version` 不升（用户裁定），两条注释必须在位

- `build-ir.mjs:84`（`version: 1` 旁）：「B78：`trials[].name` 是 IR 版本 1 的**字段扩展**，不升版本号。IR 无跨版本读取方（存档用 `v:2` 信封装 `State`，不是 IR），升版本只会逼 `ir-validate` 与所有 `print/*/ir.json` 一起改，换不到任何保障。字段形状变更靠 `engine/types/ir.ts` 约束，不靠版本号。」
- `ir-validate.mjs:42`（`ir.version !== 1` 旁）：「版本 1 的字段形状在 B78 有扩展（`trials[].name`），version 保持 1——理由见 `build-ir.mjs:84` 注释。」

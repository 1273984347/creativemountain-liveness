### §2.3 身份称谓 8 行 + 第 4 个占位符 `{identity:<座位>}`

**形状（本批唯一的新机制，写死）**：占位符**自带座位号**——`{identity:2}` 读作"2 号座位在本套主题下的身份称谓"。理由不是设计洁癖，是实测：

| 站点 | 主体是谁 | 能不能由「本条日志的 actor」推出 |
|---|---|---|
| `certification.ts:176/177`（山主特权） | 触发被动的 actor | 能 |
| `council.ts:91`（仲裁者否决，`useCouncilVeto` 的 note） | 调用者 actor | 能 |
| **`council.ts:190`（山议裁定：仲裁者否决…）** | **`state.council.vetoBy`** | **不能**——`resolveCouncil(state)` 不收 actor，它在 `turn-runner.ts:550`（结算期）与 `web/main.ts:745`（按钮）被调用，那一刻的 actor 未必是否决者 |
| `turn-runner.ts:67/236/477`（三条被动日志） | 被动的 actor | 能 |
| `web/main.ts:750`（UI 否决 notice） | `ui.seat` | 能（但来源是 UI 而非日志） |

⇒ 如果按「无参 = 主体座位」设计，`council.ts:190` 要么喊错人、要么特例化（特例就是下一个人踩的坑）。**座位参数化后 8 处一视同仁**，引擎只需知道自己一直在用的座位号——它本来就知道（`actor` / `vetoBy`），且**不因此持有 theme**，B79 的分工不破。

- 展开：`expandIdentityNames(raw, nameOf)`，`nameOf: (seat: number) => string` 由出口提供：
  日志出口 `nameOf = (seat) => identityName(state, theme, seat)`；UI notice 出口同理。
  与 `expandThemeWords`（静态 8 叶，查 `terms`）**分成两个函数**：一个查静态词表、一个查运行时主体，
  合成一个"大替换"就把两件不同的事糊成一团，将来加 `{faction:N}` 时没有落点。
- ⚠️ 解析不到 ⇒ **抛错**，不许让玩家看见花括号（与 B79「缺叶抛错、不静默兜底」同口径）。
  座位越界、`identityId` 在主题表里查无此人，都算解析不到。
- **形状写死**：解析正则 `/\{identity:(\d+)\}/g`；一条消息里出现多个 ⇒ **全部替换**（带 `g`，不是换第一个）；替换完再扫一遍，**仍残留 `{identity:` 即抛错**（防格式写坏与嵌套）。⚠️ 这条不写清，施工写成无 `g` 的 `replace` 就会静默漏掉第二个称谓，而单测若只造一个占位符永远照不出来。
- ⚠️ 这条是**我自己写错的第二处**（第一版 §2.3 断言「8 处主体全是 actor，逐处已核」，其实只核了 7 处）。
  教训与 B79 #40 同族：带「全部 / 都 / 逐处」的句子，必须真的逐处列出，否则就是没核。

### §2.4 明确不做

- 不造 `{deck}`/`{hand}`/`{seal}`/`{boon}`/`{plain}`/`{branch}`：句子层实测 0 处（§0.1）。**L-B79-4 的「顺带复核 deck」这一半就此关掉**，结论是「无对象」，而 §4.4 当年因同形词「指令」排除它——两条理由现在都成立且都不需要动代码。

- 不动棋盘格名与岔路标签 → **B81**。
- 不改 `glossary` 的任何值（它是印刷层对照表，本批只把值**复制**进 `terms`；门⑤ 判等负责两边不分叉）。

## 0. 项目定位

《创界山·活人认证》是《爱情公寓3》中虚构桌游「创界山」的 **2026 重制版**。它保留原作的精神骨架（骰子指令、双骰系统、种族差异、身份体系、资源经济、关隘副本、登顶争夺），剥离其时代产物（三国杀式卡牌措辞、UNO、乐高、魔兽等第三方 IP 与实体），并用一个全新的终局机制 **「活人认证」** 取代原作「登顶即胜」的平淡收尾。

**一句话**：在信息全公开的竞速登顶中淘汰掉对手，登上山顶只是入场券——真正赢下这局的，是那些能被在场所有人当场验明「是活人」的人。

**双轨交付**：同一份主题包数据，同时驱动 ① 数字轨（单文件 HTML，双击即玩，离线可跑）② 实体轨（可直接打印的 PDF + 可编辑 SVG/Markdown 源文件）。两轨内容由机器校验保持一致。

## 1. 设计支柱

| 支柱 | 含义 | 推论 |
|---|---|---|
| **公开信息竞速** | 无暗牌、无暗身份、无狼人杀式推理 | 策略来自资源博弈与卡组构筑，而非信息不对称 |
| **登顶≠胜利** | 峰顶是「待认证区」，不是终点 | 终局引入人际对抗，消除「爬得快就赢」的无聊 |
| **活人认证** | 登顶者须被在场玩家现场验明 | 项目代号升格为核心机制；现场出题不可被卡牌穷举 |
| **主题可换皮** | 核心规则与世界观彻底解耦 | 同一引擎支持 4 套主题；双轨由同一数据源生成 |
| **规模自适应** | 人数决定关卡数、牌库量、认证门槛 | 3–8 人都有合理局长与难度 |
| **可机器验证** | 规则引擎是纯函数，无 DOM | 自动化测试 + 对局模拟 + 双轨一致性门禁 |

**术语边界（防误读）**：「公开信息」指**牌面、身份、阵营、灵枢、手牌、位置等一切游戏状态一律公开**，任何玩家都可查阅复核。唯一的例外是**山议投票的投票行为匿名**——匿名是为防报复与串联而做的社交博弈设计，不构成狼人杀式的信息推理。认证阶段的「现场出题」是公开表演，同样不涉及隐藏信息。

### 2.2 移除（时代产物 / IP 风险）

- 三国杀式具体措辞：`杀`、`闪`、`万箭齐发`、`南蛮入侵`、`无懈可击`、`借刀杀人`、`铁索连环` 等 → 一律重写为自研语义（灵刃、护符、万灵齐鸣…）

- 第三方实体依赖：`梦幻西游手办`、`真三国无双手办`、麻将、扑克牌实物 → 改为卡牌/骰子自持
- 判定用实体：`不准说为什么的警报灯`、`手铐`、`签`、`钥匙`、`各种酒` → 改为规则内的「封口」与「放逐」

### 2.3 新增（2026 增补）

- **活人认证**终局机制（本文档 §5）
- **山议投票**：周期性公投放逐，替代原作「杀人/妖侠」身份对抗
- **声明式机制原语**：主题包只能引用注册的算子，不能内联代码（本文档 §6.4）
- **双轨同源校验门禁**：实体 PDF 与数字轨内容必须机器比对一致（本文档 §9.3）
- **AI 对手接口**：`getLegalActions()` 纯函数枚举合法动作，为后置 AI 实现预留（本文档 §7）

## 3. 核心循环

```
天机牌揭示 ──► 行动阶段（每人一次：行棋 / 问天 / 行事）
                        │
                        ▼
              关隘 / 险径 / 福地结算 ──► 灵枢收支 ──► 裁牌
                        │
                        ▼
                每 N 回合：山议公投 ──► 放逐（保留 ≥3 人）
                        │
                        ▼
              抵达峰顶 ──► 待认证 ──► 活人认证（签印/质疑）
                        │
                        ▼
                  坐上【活人席】= 胜利
```

### 3.1 回合结构

1. **天机阶段**：翻开牌堆顶一张「天机牌」，对全场生效（时段、事件、修正）。
2. **行动阶段**：按座次依次行动，**每人每回合仅一次行动**，三选一：
   - **行棋**：掷 6 面移动骰，前进对应格数；
   - **问天**：掷 20 面指令骰，执行对应指令（§3.2）——**这是 20 面指令骰唯一的掷出时机**，全文无其他触发点；
   - **行事**：打出一张手牌，或发动身份/阵营的一次性能力。
3. **结算**：结算格位效果（福地、险径、关隘、裂隙）。
4. **裁牌**：手牌数超出体力上限则弃至上限（可主动弃）。
5. **经济**：存活玩家灵枢 +1（上限 10）。
6. **牌库循环**：牌库抽空时，将弃牌堆洗回牌库重新使用（弃牌堆为空则跳过抽牌）。
7. **山议**：若达到 §5.6 的间隔则召开。
8. **认证**：若有玩家处于待认证状态，按 §5.3–§5.4 结算本回合的认证轮次。

**位移归属规则（消除「能不能又走又问天」的歧义）**：

| 选项 | 掷骰 | 位移来源 |
|---|---|---|
| 行棋 | 6 面移动骰 | 掷出点数 = 前进格数 |
| 问天 | 20 面指令骰 | **仅当指令本身含位移**（第 5 / 6 / 9 / 17 条） |
| 行事 | 不掷骰 | 仅当卡牌或能力自带位移 |

- 因每人每回合仅一次行动，**问天掷出非位移指令后本回合不再移动**；行棋后本回合不再问天。
- 指令表第 5 条是**问天内部的二次掷骰**（20 面 → 6 面），不构成第二次行动。
- 指令表第 14 条允许**链式问天**：立即再掷 20 面并执行，但**不可再连锁**（第二次问天掷出的指令即使再命中第 14 条也不再生效）。

### 3.2 指令骰（20 面）——「问天」行动

**触发时机**：行动阶段选择「问天」时掷出 20 面骰，按点数查「指令表」执行对应指令。这是 20 面骰唯一的掷出时机。

**指令表是主题无关的通用表**（主题包可覆盖个别条目）：

| 点数 | 指令 | 点数 | 指令 |
|---|---|---|---|
| 1 | 抽 1 张牌 | 11 | 指定一名玩家弃 1 张牌 |
| 2 | 灵枢 +1 | 12 | 指定一名玩家后退 1 格 |
| 3 | 抽 2 张牌 | 13 | 获得 1 张指定类型手牌 |
| 4 | 灵枢 -1（给自己） | 14 | 立即再掷一次 20 面指令骰并执行（**不可再连锁**） |
| 5 | 掷 6 面移动骰并按点数前进 | 15 | 免疫本回合的「封口」 |
| 6 | 前进 2 格 | 16 | 与一名玩家交换手牌各 1 张 |
| 7 | 抽 1 张牌 + 灵枢 +1 | 17 | 本回合移动 +2 格 |
| 8 | 弃 1 张牌抽 2 张 | 18 | 获得 1 枚灵枢（不超上限） |
| 9 | 前进 1 格并抽 1 张牌 | 19 | 指定一名玩家抽 1 张牌 |
| 10 | 全员弃 1 张牌 | 20 | 自由执行一次「阵营轮」效果 |

指令表在数字轨与实体轨各有一份，**必须由同一 JSON 生成并机器比对**。

### 3.3 移动与山道

- 山道 = 线性格序列（长度见 §8 规模表），牌面向下延伸至峰顶。
- 部分位置存在**支路**（如 12 格处可走「云梯」直达 18 格，或走「栈道」多 2 步但触发福地）。
- 玩家在**同一格**相遇：进入「对峙」——双方同时亮 1 张手牌，比颜色/点数，高者将低者推后 1 格，低者抽 1 张牌（高者不额外收益，避免滚雪球）。
- 已通过关隘的格不再触发关隘。

### 3.4 地形

| 地形 | 效果 |
|---|---|
| 平原 | 无 |
| 福地 | 立即抽 2 张牌，灵枢 +1 |
| 险径 | 亮 1 张手牌判定颜色：红=安全通过；黑=体力 -1，且失去本回合剩余行动 |
| 裂隙 | 对手可花 2 灵枢在此放置「封路印」，持有者经过时需判定，失败则停 1 回合 |
| 关隘 | 见 §3.5 |
| 峰顶 | 进入待认证区，见 §5 |

### 3.5 关隘（副本）

关隘是山道上的硬门槛，每座提供两条通过路径：

- **付费通道**：支付关隘标价（3–5 灵枢）立即通过；
- **试炼通道**：抽一张「试炼牌」执行其要求。示例：
  - 「展示 2 张同色手牌」——失败则停 1 回合；
  - 「掷指令骰 ≥ 15」——失败则退 1 格并被封口；
  - 「灵枢 ≥ 4」——失败则本关改为付费；
  - 「回答其他玩家提出的 1 个问题」——答不上则退 1 格。

试炼牌为公开信息，抽取时全场可见（保证可推断、可博弈）。已通过同座关隘的试炼牌不再被抽取。

> 试炼中的「回答问题」是**关隘试炼**的一环，由试炼主持者（上帝）判定，判定标准写在试炼牌上；它与 §5 的**活人认证**是完全不同的机制，不要混淆——认证的判定权归属与复议流程见 §5.3。

## 4. 身份、阵营与经济

### 4.1 身份（公开，明牌竞速）

每名玩家开局获得 1 个身份，**全员可见**。身份 = 1 条被动特权 + 1 条终局目标。

| 槽位 | 特权（示例） | 终局目标（示例） |
|---|---|---|
| 开拓者 | 每回合首次移动 +1 格 | 最先通过 3 座关隘 |
| 匠师 | 每场限 1 次免费造物 | 累计装备 3 件法宝 |
| 观星者 | 每回合可看牌堆顶 1 张 | 累计抽牌 ≥ 12 张 |
| 仲裁者 | 山议中可投 2 票 | 成功否决 1 次放逐 |
| 守夜人 | 一次为他人挡「封口」 | 存活至终局且体力 ≥ 初始值 |
| 窃火者 | 每回合可偷 1 灵枢 | 累计偷取 ≥ 5 灵枢 |
| 织梦者 | 每回合 1 次改一次判定结果 | 累计改判 ≥ 3 次 |
| 山主 | 认证时首次被质疑自动通过（第二轮起恢复正常） | 成功质疑 1 次且未被复议推翻 |

终局目标达成者获得 **【印记】**。

**印记通用效果（所有身份一致）**：持有【印记】的待认证者，**所需签印数减半（向上取整）**，最低为 1。

- 例：5 人局 N=3，有印记者只需 2 枚签印；8 人局 N=4，有印记者只需 2 枚。
- **印记不叠加**：重复获得不额外生效（同一玩家同时只享 1 枚印记的效果）。
- **印记不绕过终局**：仍必须走完签印 / 质疑流程，只是门槛更低。

**山主特权叠加**：持有印记且为山主者，「认证时首次被质疑自动通过」仍然生效——即山主第一轮认证中的任何质疑自动视为签印；第二轮起恢复正常质疑规则。

**「成功质疑 1 次」的定义**（山主终局目标的达成判定）：该玩家作为认证人发起质疑，使待认证者的判定结果为「不通过」，且该判定在当轮未被复议推翻（待认证者未申请复议，或复议后维持原判）。

### 4.2 阵营（四阵营槽位）

每名玩家同时属于 1 个阵营，提供初始体力、初始灵枢、牌库偏好与 1 项能力。**体力上限即手牌上限**（沿用原作「手牌数 = 体力值」），因此体力基准定为 6–8 而非原作的 9–24，否则手牌会无谓堆积。**阵营轮**是原作「转盘」的现代化：每名玩家持一枚所属阵营的轮盘，掷轮可触发该阵营专属效果（每局限 1 次）。

四套主题的阵营命名：

| 主题 | 阵营 A | 阵营 B | 阵营 C | 阵营 D |
|---|---|---|---|---|
| 仙侠 2026 | 仙门 | 龙裔 | 散仙 | 灵丘 |
| 近未来科幻 | 人类联盟 | 义体 | AI 集群 | 轨道联邦 |
| 奇幻科幻融合 | 仙门 | 妖盟 | 人间 | 天机 |
| 都市异能 | 觉醒者 | 血族 | 械灵 | 凡人 |

### 4.3 灵枢经济

- 初始灵枢 = 人数 + 1（见 §8）
- 上限 10；达到上限必须立刻花掉，否则下一回合开始扣 1 灵枢
- 收入：回合末 +1；通过关隘 +2；山议未被放逐 +1；灵枢卡 +2
- 支出：移动类卡 1–2；改判定 2；放置封路印 2；免于放逐（凭证）3；复活队友 4；**发起质疑 1**（无论成败，见 §5.3）；申请复议 2

## 5. 活人认证（终局机制）

> 本节是本作的立身之本，也是项目代号的正式归宿。

### 5.1 进入条件

玩家抵达**峰顶格**即进入「待认证」状态，**此时不构成胜利**。待认证者停在峰顶，获得「待认证」标记，并公示当前所需签印数。

若待认证者因判罚后退而离开峰顶格，则**待认证状态即时终止**（他需重新登顶才能再次发起认证）。

### 5.2 认证规则

- 场上每名存活玩家（不含待认证者）持有 **1 枚认证印**，每轮认证中只能使用一次「签印」、发起一次「质疑」，或弃权。
- 待认证者需要集齐 **N 枚签印**（N 见 §8 规模表）。
- **实际门槛**计算顺序（写进引擎实现，不可颠倒）：
  1. `base = min(N, 存活人数 - 1)`——签印人只能来自其他存活玩家，因此门槛必须随存活人数收缩，否则大人数局会出现「门槛永远无法满足」的死锁；
  2. 若持有【印记】→ `base = ceil(base / 2)`（向上取整，最低 1）；
  3. `base` 最低为 1（任何情况下都不允许 0 门槛，否则登顶即通关）。
- 认证最多进行 **2 轮**。第 2 轮结束仍未集齐 → 待认证者退回山道 60% 位置，本次登顶作废。

### 5.3 签印、质疑与判罚权归属

#### 5.3.1 三种选择

每位认证人每轮可做一次选择：

| 选择 | 前置成本 | 效果 |
|---|---|---|
| **签印** | 无 | 直接贡献 1 枚签印 |
| **质疑** | **立即消耗 1 灵枢**（无论成败，见 §5.3.4） | 待认证者须连续回答认证人提出的 **3 个问题**；答对 ≥ 2 题 → 认证人视为签印；答对 ≤ 1 题 → 该认证人不签印，且待认证者后退 1 格 |
| **弃权** | 无 | 本轮不使用该认证印，保留到下轮 |

**门槛固定为 3 问取 2**（答对 ≥ 2 即通过），不随人数或主题变化。

#### 5.3.2 判罚权归属（关键：防止「认证人说了算」）

判罚权采用**三方结构**，而非认证人单方裁定：

1. **认证人初判**：认证人出题、待认证者回答后，由认证人给出「通过 / 不通过」的初步判定。
2. **待认证者复议权**：若认证人判「不通过」，待认证者可**消耗 2 灵枢申请复议**。
3. **第三方裁定**：复议由**除认证人与待认证者外的存活玩家**投票（匿名，多数决）裁定「该回答是否算「活人」」：
   - 复议**成功** → 该题改判为通过（该认证人视为签印）；
   - 复议**失败** → 维持「不通过」，且**待认证者额外扣 1 灵枢**，待认证者后退 1 格。
   - **平票 → 视为复议成功**（保护被质疑方）。
   - **独立第三方不足 2 人时（即在场仅 3 人）**，改为掷 6 面骰：**4–6 算复议成功**（给被质疑方 50% 的反制机会），1–3 算失败。
   - 每位待认证者每轮最多申请 1 次复议。

#### 5.3.3 出题合规性检查

认证人出题后，待认证者有权**拒绝回答明显不可当场验证的题目**（如「你昨晚梦到了什么」「你三岁时的记忆」「你昨天中午吃了什么」——记不清不等于不活），并要求换题：

- 是否「明显不可验证」由**全场非当事人玩家**匿名多数决裁定。
- 裁定为**不可验证** → 认证人须换题，且**本轮内不得再出同类题目**。
- 裁定为**可验证** → 待认证者必须回答，**拒绝视为答错**（即认证人判定通过）。
- 换题不消耗认证轮次；同一认证人每次质疑最多换题 1 次。

#### 5.3.4 质疑成本对称（消除「零成本恶意质疑」）

| 结果 | 认证人代价 | 待认证者结果 |
|---|---|---|
| 质疑**失败**（答对 ≥ 2） | 发起时已扣 1 灵枢 + **再扣 1 灵枢**（共 2） | 视为被该认证人签印（认证推进） |
| 质疑**成功**（答对 ≤ 1） | 发起时扣 1 灵枢（共 1） | 该认证人不签印，待认证者后退 1 格 |
| 发起复议 | 2 灵枢（待认证者付） | — |

- **零成本恶意质疑已被消除**：发起质疑固定付费，失败还要再付一次。想反复阻拦就得反复掏灵枢，而灵枢同时是移动与改判定的硬通货。
- **失败即视为签印**（而非「失去资格」）是有意设计：它保证认证流程**不会因某一人的敌意而彻底卡死**，同时用 2 灵枢的代价让敌意付出真实成本。

签印是**默认省力选项**，质疑是**高风险高收益选项**：质疑成功可阻断一次有把握的否决，失败则净损 2 灵枢。因此认证阶段天然产生博弈与表演张力。

### 5.4 题目来源

1. **现场出题**（主）：认证人自由出题。必须满足「可当场验证」原则——题目答案取决于**此刻在场真实发生的事**或**该玩家的个人经历**，不可由规则书或卡牌穷举。
   - 合格示例：「说出本局你亲眼看到的、任何人偷偷做过的 1 件事」「描述你左手此刻摸到的东西」「复述 3 回合前别人说过的一句话」
   - 不合格示例：「2+2 等于几」「《爱情公寓》第几集」
   - **判定标准须先公开**：认证人提问前必须**先说明他将如何判定「通过」**（例如「答案必须描述本局真实发生过的一件事」「必须是你亲身经历的」）。该标准一经说明即**全场可见，本轮内不得更改**，且认证人的判定必须**对照已公开的标准**执行——这把「判定权」从主观偏好约束为可被复核的承诺。
2. **认证题卡**（辅）：每套主题配 1 组认证题卡（12–20 张），提供保底题库。题卡仅作为出题参考，不强制使用。

**与关隘试炼的区别**：认证题卡由**认证人**在认证阶段使用，判定权与申诉流程见 §5.3；关隘试炼牌由**上帝**在关隘处判定，判定标准写在牌面上（见 §3.5）。两者互不通用，不要混淆。

### 5.5 双人互验（防死锁）

若场上**同时**出现 2 名待认证者，触发**双人互验**：两人互相出题、互相签印。

- **每人的实际门槛降为 1**（对方的签印即达标），由 §5.2 公式在此处覆盖——因为此时潜在认证人只剩对方一人，原门槛必然无法满足。
- **第三人的认证印不计入门槛判定**，仅作加速：第三人使用时可指定给任一方（不受「必须选边」的困扰，因为门槛已降为 1）。
- **不产生死锁**：双方互签即各自达标，第三人签不签都不影响推进。
- **同时达标时**：本回合内**先完成认证者先占席**；若两人都想同时占席且本局只剩这一席，则**并列封顶**（双活人席，本局以并列胜出结束，规则书须明确写出此结局）。
- 戏剧性来源：「活人」问题升级为「你们互相证明对方是活的」——双方都必须在对方出的题上真的开口、真的答得出。

（注：放逐下限恒为 3，故本局面下至少还有 1 名第三人在场，见 §5.6。）

### 5.6 山议投票（与认证的配合）

- 每 N 回合召开一次**山议**（间隔见 §8）。
- 全员**匿名**投票（仲裁者可投 2 票），得票最高者被**放逐**（出局，退出本局）。匿名是为防报复与串联而设，属社交博弈设计，**不构成信息不对称推理**（见 §1 术语边界）。
- 被放逐者失去认证印资格，其身上的印记作废。
- **放逐下限**：任何时候场上存活玩家不得少于 3 人 —— 这保证活人认证永远存在至少一位认证人，杜绝「孤峰无认证」的死局。
- **凭证**：被提名者可在投票结束前消耗 3 灵枢出示「凭证」免疫本次放逐（凭证为公开信息，使用后全场可见）。
- **仲裁者否决**：仲裁者身份可消耗一次特权否决本次放逐（每局 1 次）。

### 5.7 胜利判定

1. 集齐**实际门槛**（§5.2 公式）枚签印 → 坐上【活人席】，本局结束。
2. **印记加速**：持有【印记】者门槛减半（向上取整，最低 1）——**印记不直接封顶**，仍须走完签印 / 质疑流程。
3. **山主特权**：持有【印记】且为山主者，第一轮认证中的任何质疑**自动视为签印**（第二轮起恢复正常）。
4. **双人互验同时达标**：并列封顶（双活人席），本局以并列胜出结束（见 §5.5）。
5. 若场上仅剩 1 人（因放逐下限恒为 3，正常不会发生）→ 判定为「活人缺席」，无人胜出，重开一局。

### 5.8 全局回合上限与兜底排名（防无限局）

认证轮次上限只约束**单次认证**，不约束整局。若玩家互相放逐、无人登顶，或登顶者反复被判后退，整局可能无限延续——因此设置**全局回合上限**：

- **上限 = 12 + 人数**（3 人局 15 回合，4 人局 16，5 人局 17，6 人局 18，7 人局 19，8 人局 20），见 §8 规模表。
- 上限回合结束时若**仍无人坐上活人席**，按以下顺序排名，**最高者胜**（不是并列）：
  1. **距峰顶格数**少者胜（越接近峰顶越前）；
  2. 若相同 → **已获签印数**多者胜；
  3. 若仍相同 → **灵枢**多者胜；
  4. 若完全相同 → **并列胜出**（本局以多人共享活人席结束）。
- 兜底结果必须**显式播报**（「本局因达到回合上限，由第 N 名封顶」），不得让玩家误以为是正常登顶。

### 6.2 引擎状态

单一不可变状态对象，所有动作是纯函数 `state → state'`：

```ts
type State = {
  seed: number;              // 可复现随机源
  phase: '天机' | '行动' | '山议' | '认证' | '终局';
  round: number;
  turnIndex: number;
  activePlayer: number;
  players: Player[];        // 体力/灵枢/手牌/身份/阵营/位置/印记/待认证标记
  board: Tile[];             // 地形与格位
  decks: { hand: Card[]; heaven: Card[]; trial: Card[]; cert: Card[] };
  pending: PendingEffect[];  // 延迟结算栈
  log: LogEntry[];
};
```

### 6.3 动作模型

引擎只接受**声明式动作**：`{ type, actor, params }`。UI 与（未来的）AI 都只能提交引擎枚举出的合法动作。

```ts
type Action =
  | { type: 'MOVE'; actor: number; steps: number }
  | { type: 'PLAY_CARD'; actor: number; cardId: string }
  | { type: 'ABILITY'; actor: number; abilityId: string; target?: number }
  | { type: 'ROLL_WHEEL'; actor: number }
  | { type: 'COMPARE'; actor: number; cardId: string; target: number }
  | { type: 'PASS'; actor: number }
  | { type: 'VOTE'; actor: number; target: number }
  | { type: 'CERTIFY_SIGN'; actor: number; target: number }
  | { type: 'CERTIFY_CHALLENGE'; actor: number; target: number }
  | { type: 'CERTIFY_ANSWER'; actor: number; questionIndex: number; ok: boolean };
```

### 6.4 机制原语注册表（关键约束）

主题包**不允许内联代码**。所有效果以「算子 + 参数」表达，算子必须在 `ops/registry.ts` 中注册并实现。

**效果算子（ops）**：

| 类别 | 算子 |
|---|---|
| 资源 | `gain_resource` `spend_resource` `transfer_resource` `set_resource` |
| 牌 | `draw_cards` `gain_card` `discard_self` `discard_opponent` `exhaust_card` `peek_deck` `add_to_deck` `remove_from_deck` `swap_deck_top` |
| 位移 | `move_forward` `move_backward` `move_to_tile` `move_relative_to` `swap_position` `teleport` |
| 骰子 | `extra_roll` `reroll` `keep_die` `set_die_result` `roll_opponent` |
| 状态 | `shield` `poison` `slow` `silence` `skip_turn` `immunity` `double_next_vote` `extra_signatures_required` `set_phase` `set_flag` `clear_flag` |
| 战斗 | `damage` `heal` `compare_cards` `disarm` |
| 投票 | `vote_modifier` `extra_vote` `cancel_vote` `exempt_from_vote` |
| 认证 | `certify_extra_signer` `certify_free_pass` `certify_extra_round` `certify_forbid_challenge` |
| 阵营 | `spirit_wheel`（掷阵营轮） |
| 组合 | `sequence` `conditional` `count` `random_from_deck` |

**条件谓词（predicates）**：`tile_kind` `has_card` `resource_at_least` `hand_count` `is_pending_cert` `phase_is` `players_alive` `card_type_is` `identity_is` `faction_is` `hp_at_least` `flag_set` `last_dice_even` 等。

**组合表达**：`conditional` 嵌套 `pred` + `then`/`else`；`sequence` 顺序执行多个算子。**不提供任意表达式求值**，不使用 `eval` / `Function`。

### 6.6 数字轨

- 构建产物：`dist/创界山-活人认证.html`，**单文件**（引擎 + UI + 4 套主题数据内联），双击即玩，离线可用，无外部请求。

### 6.7 实体轨

- SVG 同时作为「可编辑排版源文件」交付。

## 8. 规模自适应

| 人数 | 山道格数 | 关隘数 | 初始灵枢 | 起始手牌 | 牌库总量 | 试炼牌 | 认证题卡 | 认证签印门槛 N | 印记后门槛 | 山议间隔 | 放逐下限 | 全局回合上限 | 预计局长 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 3 | 24 | 2 | 4 | 5 | 40 | 10 | 12 | 2 | 1 | 每 6 回合 | 3 | 15 | ~35 min |
| 4 | 28 | 3 | 5 | 5 | 48 | 12 | 14 | 3 | 2 | 每 6 回合 | 3 | 16 | ~45 min |
| 5 | 32 | 3 | 6 | 6 | 56 | 12 | 14 | 3 | 2 | 每 5 回合 | 3 | 17 | ~55 min |
| 6 | 32 | 3 | 6 | 6 | 64 | 14 | 16 | 4 | 2 | 每 5 回合 | 3 | 18 | ~65 min |
| 7 | 36 | 4 | 7 | 6 | 72 | 14 | 16 | 5 | 3 | 每 4 回合 | 3 | 19 | ~80 min |
| 8 | 36 | 4 | 8 | 7 | 80 | 16 | 18 | 5 | 3 | 每 4 回合 | 3 | 20 | ~90 min |

设计说明：

- **山议间隔随人数缩短、回合数缩短**：人数多时公投节奏更快，保证淘汰压力不塌。
- **放逐下限恒为 3**：确保活人认证永远可进行（§5.6）。
- **签印门槛随人数递增，但收紧至「存活人数 - 1」以内**：5 人局原定 N=4 等于要求除自己外全员签印，只要 1 人坚持质疑就永远登不了顶——这是**终局僵局**，不是难度。5 人局已下调为 N=3，6/7/8 人局同步下调为 4/5/5。门槛须保证「至少 1 名在场者可以拒绝」而不致死锁。
- **印记后门槛 = ceil(N/2)**（最低 1）：印记是强加速器，但不是免死金牌——仍需至少 1 枚实打实的签印。
- **山道格数非线性增长**：8 人仅比 6 人多 4 格，避免后期拖沓。
- **全局回合上限 = 12 + 人数**：防止无人登顶或反复被后退导致的无限局（§5.8）。
- 人数 2 人与 9+ 人：**不支持**（活人认证至少需要 3 人在场，见 §5.6）。

## 9. 测试与验收

### 9.1 引擎单元测试

- 每个 ops 算子至少有 1 个用例；每个 predicate 同理。
- 回合状态机：回合推进、行动次数、裁牌、经济结算。
- 移动：格位、分支、同一格对峙（比颜色/点数，胜者不额外获益）、退回与前进。
- 牌库循环：牌库抽空后洗回弃牌堆。
- 险径判定：亮牌判红/黑两种分支。
- 关隘：付费 / 试炼 / 失败惩罚三路径。
- 山议：投票、放逐、下限保护、凭证免役、仲裁者否决。
- 活人认证：签印收集、质疑判罚（答对 2 / 答对 1）、双轮上限、退回 60%、双人互验、印记门槛减半。
- 判罚权：认证人初判 → 待认证者付费复议 → 非当事人多数决；3 人局改掷 6 面骰（4–6 成功 / 1–3 失败）；平票视为复议成功。
- 质疑成本：发起扣 1 灵枢、失败再扣 1、灵枢不足时不可发起。
- 出题合规：拒绝明显不可验证题目 → 全场裁定 → 换题 / 必须回答两条分支。
- 山主特权：第一轮质疑自动通过、第二轮恢复正常。
- 全局回合上限：超限后按「距峰顶 → 签印数 → 灵枢」排名；完全相同则并列胜出。
- 门槛收缩：存活人数下降时门槛随之收缩，且最低为 1（不允许 0 门槛）。
- 规模表：3/4/5/6/7/8 人各跑通一局。
- 随机可复现：同 seed → 同结果。

### 9.2 对局模拟（Smoke）

- 固定 seed 跑 1000 局，覆盖各人数档位。
- 断言：无异常抛出、无死循环、无非法状态、每局在**全局回合上限内**结束、每局必有胜负（或明确的并列胜出 / 「活人缺席」结局）。
- 专项统计：**认证轮次分布**与**兜底触发率**——若兜底触发率过高说明门槛或山道长度失衡，须记录并讨论。
- 统计各身份/阵营胜率分布，作为平衡性参考（不设硬阈值，但胜率偏离 > 15pp 需记录并讨论）。

### 9.3 双轨一致性门禁（关键）

**比对对象不选 PDF 文本层**——中文 PDF 在换行、字距、字体嵌入下提取极不稳定，逐项比对会大量误报，门禁会退化成「每次都红、然后被手动豁免」。改为**两级比对 + 一级粗检**：

**① 主比对（精确，判红依据）**：比对 `build-print` 的**中间渲染数据模型**（生成 PDF 之前的那层结构化 IR）与主题包 JSON / 数字轨内联数据，逐字段全等：

- 卡牌名、费用、效果描述
- 阵营名、能力描述
- 身份名、特权与目标
- 指令表 20 条
- 规模表全部数值（含全局回合上限、印记后门槛）
- 认证题卡文本

**② 辅比对（精确）**：解析产出 **SVG 的文本节点**（SVG 是 XML，可精确解析），验证关键字段确实被渲染进实体件——防止「IR 正确但模板漏印」。

**③ PDF 粗检（不逐项比对）**：仅校验可打开、页数与预期一致、字体已嵌入。

任一不一致 → **exit 1**，本地门禁判红。这是「双轨同批交付」不漂移的唯一硬证据。

### 9.4 主题包校验

`tools/theme-validate.mjs`：JSON 结构校验 + 引用完整性（所有 cardId / trialId / factionId 可解析）+ ops 白名单校验（出现未注册算子 → 报错）+ 数量一致性（牌库总量与配置相符）+ 规模表一致性。

### 9.5 验收清单（Definition of Done）

- [ ] 3–8 人各一局可完整跑通并分出胜负
- [ ] 活人认证全流程可用：签印 / 质疑 / 复议 / 合规检查 / 双轮上限 / 双人互验 / 印记减半
- [ ] 山议放逐下限生效，不出现无认证人局面
- [ ] 4 套主题包均可加载，能力/事件/认证题正确生效
- [ ] 单文件 HTML 断网可玩，控制台无报错
- [ ] 实体 PDF 打印后可直接开局（牌面清晰、尺寸合规、规则书完整）
- [ ] parity-check 门禁通过（IR + SVG 精确比对，PDF 粗检通过）
- [ ] 引擎单测 + 1000 局模拟全绿，且无局超出全局回合上限
- [ ] 规则书内所有数值与引擎实际行为一致（由 parity-check 覆盖）

## 10. 里程碑与批次

双轨并行、同批交付，但内部按可验收批次推进：

| 批次 | 内容 | 验收 |
|---|---|---|
| **B1 引擎骨架** | State / Action / 回合机 / 骰子 / 移动 / 资源 / 手牌 / 地形；**确定构建链 = esbuild**（零配置、产出单文件 bundle，避免 B5 卡在工具链） | 引擎单测骨架通过，能在 Node 里空跑；`esbuild` 打包出一个可加载的 HTML 骨架 |
| **B2 机制原语** | ops registry + predicates + 组合器 | **验收标准 = 「能表达 4 套主题包的全部效果」**（逐一核对主题包中出现的每个 op 均已注册且有单测），而非「算子数量达到 N」——后者会在实施中发现不够而返工 B2 |
| **B3 核心玩法闭环** | 关隘、山议、活人认证（含复议 / 合规检查 / 成本对称）、印记减半、胜负判定、回合上限兜底 | 3 人局可完整跑通，且 §5.3/§5.8 各条规则均有对应测试 |
| **B4 主题包 ×1** | 仙侠 2026 全量数据 + 校验器 | theme-validate 通过 |
| **B5 数字轨 UI** | 单文件 HTML 打包 + 牌桌 UI + 认证面板 | 断网可玩，4 人局体验完整 |
| **B6 实体轨管线** | SVG 模板 + 打印 HTML → PDF + 规则书生成 | 可打印 PDF 产出 |
| **B7 parity-check** | 双轨文本比对门禁 | 人为制造一处漂移 → 必须判红 |
| **B8 主题包 ×3（最小可行）** | 科幻 / 融合 / 都市异能：**每套只差异化**阵营命名与能力微调、术语表 `glossary`、认证题卡、1–2 张标志性卡牌；卡牌池与事件池复用仙侠主题的通用池 | 4 套主题均通过校验与对局；**全量差异化移至 V1.1**，B8 不得膨胀为内容黑洞 |
| **B9 规模与平衡** | 3–8 人规模表落地 + 1000 局模拟 + 平衡记录 | 模拟全绿，胜率分布记录在案 |
| **B10 收官** | 规则书定稿、README、发布包 | 验收清单全勾 |

批次顺序上 **B4 早于 B8**：先用一套主题把管线跑通，再复制到其余三套，避免 4 套并行返工。

## 11. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 活人认证变成「互相抬轿」或「无限刁难」 | 高 | 签印为默认选项；**质疑付费且失败加倍扣灵枢**（消除零成本恶意质疑）；判定须对照已公开标准；复议与合规检查双保险；认证双轮硬上限 |
| 认证人滥用判罚权（主观判错、刁钻题） | 高 | 待认证者付费复议 + 非当事人多数决（3 人局掷骰）+ 出题合规性裁定 + 判定标准须先公开 |
| 签印门槛过高导致终局僵局（无人敢登顶） | 高 | 门槛收紧至「存活人数 - 1」以内（5 人局 N 由 4 降至 3）；印记减半提供加速出口 |
| 全局无限局（无人登顶 / 反复被后退） | 中 | 全局回合上限 12 + 人数，超限按「距峰顶 → 签印 → 灵枢」排名兜底（§5.8） |
| 山议放逐导致场面崩盘（尤其 3 人局） | 高 | 放逐下限恒 3；凭证可免役；仲裁者否决 |
| 主题包表达力受限（某些效果原语拼不出来） | 中 | 宁可扩充 registry（原语是代码，安全），也不放开主题包内联代码 |
| 双轨内容漂移 | 中 | parity-check 门禁 + 规则书表格由数据生成 |
| 单文件 HTML 体积膨胀 | 低 | 4 套主题数据内联约 2–4 MB，可接受；必要时按主题分包 |
| 实体 PDF 中文排版 / 字体问题 | 中 | 走 headless Chrome 打印路径，字体由系统渲染 |
| 原作 IP 残留 | 中 | 禁用词清单（§2.2）+ 规则书与卡面全量重写；法务层面本作仅做「精神继承」不复制具体表述 |
| 2012 年的「元宝 / 灵气」语汇在 2026 显得过时 | 低 | 资源名与全部术语由主题包 `glossary` 覆盖，仙侠主题也用新语汇（例：灵枢、符箓、执事） |

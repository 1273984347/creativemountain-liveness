# Laya sidecar V2 预研 · 总纲

> 日期：2026-11-08｜路径裁定：架构级（新增跨语言进程边界 + 落地规格 §7 接口）
> 本文只定**切分、依赖、判据、红线、缺口**；实施细节见 `2026-11-08-creativemountain-laya-sidecar-design.md`。
> 上游规格：`2026-11-07-creative-mountain-liveness-design.md` §7（AI 对手接口，V1 后置到 V2）。

## 一、要回答的问题

按优先级，预研只答这三问，**不答「AI 打得过谁」**：

1. **工程可行性**：引擎的状态能否喂给一个本地判断模型、再稳定回解成合法动作？延迟与 token 预算是否允许真人桌局使用？
2. **接口真实性**：规格 §7 承诺的「UI 与 AI 使用同一枚举」能否变成可机械验证的契约？
3. **分发代价**：`file://` 双击即玩的单文件数字轨，能否在不破坏「离线可用」的前提下叫到一个本地模型？

成功判据见设计文档 §4.7（P0–P6 读数表）。**预研的产物是结论与数据，不是产品能力**：任何情况下都不进发布包、不进 `npm run gate`。

## 二、为什么牵扯出三个批次

起点是「加个 sidecar」，但探上下文时发现规格 §7 是空头支票，而它牵出两个既有缺陷：

| 事实 | 证据 | 后果 |
|---|---|---|
| `getLegalActions` 枚举 13 类动作里的 8 类，缺 出牌 / 被动 / 问天 / 关隘 / 认证作答；反向还枚举了 `CERTIFY_VALIDATE_QUESTION`（对应算子零调用方） | `engine/core/legal.ts:11-68` ↔ `engine/core/action.ts:24-36`、`engine/core/certification.ts:305` | AI 无面可选，且枚举里含执行不了的动作 |
| UI 与 sim 都不调用该枚举，各自用 `performAction(state,seat,phase,payload)` | `web/main.ts:243`、`tests/sim/run.mjs:240` | 「同一枚举」当时不成立 |
| `gatesPassed` 计数器无写入方，而四套主题各有一个身份目标是 `pass_gates` | `engine/goals/registry.ts:38` ↔ `themes/*/theme.json:126-127` | **4 个身份目标永不可达** |
| 关隘逻辑 `payGate` / `drawTrial` 全仓零引用 | `engine/core/gate.ts`（与 B13 之前的对峙同形） | 关隘在数字轨不可达 |
| 引擎不校验出牌费用；UI 也不拦；只有 sim 当门槛 | `engine/core/turn-runner.ts:221-232`、`web/ui/hand.ts:24`、`tests/sim/run.mjs:232` | 数字轨可免费出牌 |

所以预研被切成三批，其中 B14 是缺陷修复而非新功能。

## 三、批次切分

| 批次 | 内容 | 改哪些面 | 门禁影响 | 依赖 |
|---|---|---|---|---|
| **B14 关隘接线** | `payGate`/`drawTrial` 接入落格结算 + 付费/试炼双通道 + `gatesPassed` 写入 + UI 面板 + E2E | 引擎对局行为 | ⑨ 冒烟与 `docs/balance-report.md` **必须重跑**；③ 同步规格 §3.5；规则书地形章节一并补 | 无（可最先做） |
| **B15 §7 枚举落地** | `getLegalActions` 补 出牌/被动/问天（关隘待 B14 并入）+ 试跑式一致性 + rng 隔离 + UI 门禁下沉 `web/legal-gate.ts` | 引擎枚举与 UI 判断来源 | ①②③；⑨ 仅回归比对（对局行为不变） | 与 B16 并行起步 |
| **B16 sidecar 探针** | `laya-serve` + Node 反代 + 影子决策探针 + 浏览器可达性探针 | 无（全在 `tools/`） | 十道门零改动；无服务即 SKIP | P0 环境自检先过 |

**B14 单独成批单独成 spec**：它会改对局行为，必须配独立的平衡验收设计，塞进预研会让两边都失焦。本轮只交付 B15 + B16 的设计与实施计划。

## 四、红线（四条，违反即返工）

1. **确定性不得被模型污染**。十道门与 `docs/balance-report.md` 的固定 seed 复现路径上，不得出现任何模型调用。探针只读引擎、不改对局。
2. **发布包零增量**。`esbuild.config.mjs`、`build/build-package.mjs` 不引用 sidecar 文件；Python 依赖不进 `package.json` / `package-lock.json`。「双击即玩」是产品承诺。
3. **模型只见公开信息**。喂给模型的文本必须 ⊆ 该座位可见信息集，禁止集（他人手牌、牌堆顺序、双方暗选的对峙牌）出现在文本里由测试断言保证。否则 AI 开天眼，预研结论整份作废。
4. **本地服务只绑环回**。官方 `laya.serve` 的 `LAYA_HOST` 默认 `0.0.0.0`，必须显式覆盖为 `127.0.0.1`；权重启动前按 sha256 对拍，不符即拒绝启动。

## 五、缺口登记（本批不裁定，逐条给出建议归属）

- **G-a 出牌费用语义未定义**。规格 §3.1 只写「打出一张手牌」，未写支付；付费只出现在 §3.5 关隘。引擎不扣、UI 不设门槛、sim 当门槛、实体件印着费用——四方各说各话。建议随 B14 一并裁定（它同时动 §3.1 与 §3.5 的资源口径，且改变平衡，需重跑 ⑨）。
- **G-b 待认证者可用位移牌绕过 §5.1 锁定**。引擎的 `act` 分支不检查 `pendingCert`，现在只靠 UI 禁用整块行动区挡着。修复路径：`turn-runner.ts` 的 `act` 分支补 `pendingCert` 检查 ⇒ sim 本就过滤 motion 牌、UI 本就禁用行动区，两者都不会提交该动作，故行为近似不变，由门 ⑨ 回归比对背书。**本批按 §2 评审决定仅登记、不修**；若要收进 B15，批次执行时说一声即可，成本极低。
- **G-c `gatesPassed` 无写入方**。归 B14，性质是缺陷修复，优先级最高。

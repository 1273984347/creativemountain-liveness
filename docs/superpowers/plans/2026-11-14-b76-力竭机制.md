# B76 · 力竭机制实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** HP 归零触发「力竭」（可逆惩罚：上限减半 / 骰移 -1 / 主动被动封锁 / 不可发起质疑），三条恢复路径（自然 / 自恢 2 灵枢 / 救援 1 灵枢），收口 damage 暗杀分支——放逐仍是唯一出局通道，§5 零改动。

**Architecture:** 新建 `engine/core/exhaustion.ts` 承载触发 / 解除的**唯一实现**（damage、险径、endRound、RECUPERATE 四个调用点共用，防「同一口径两份实现必漂移」）；力竭走独立字段 `Player.exhaustedRounds`（不入 `NegativeStatus` 免疫通道）；恢复动作用**单成员** `RECUPERATE { actor, target? }` 进动作契约（自恢 / 救援按 target 有无区分）；三层同判（枚举 = UI 门禁 = 引擎）按 B75 纪律；报告计数器走 duelCount 同款 log 扫描模式。

**Tech Stack:** Node 24 ESM + TypeScript（`node --test` 跑 `.ts`）；纯 `.mjs` 里不得用 TS 语法；13 道门禁；无新增依赖。

**Spec:** `docs/superpowers/specs/2026-11-14-b76-力竭机制-design.md`（权威；本计划是它的施工论证，冲突以 spec 为准，含 r1.1–r1.3 修订）。

## Global Constraints

- **规格先行**：`Player.exhaustedRounds` 进规格 §6.2（Task 1）后才改 `state.ts`（C9 只扫 State 顶层字段，Player 行手工同步）；§6.3 的 `RECUPERATE` 行与 `action.ts` **同一任务**落（action-contract 常驻断言钉住规格表 == 代码）。
- **数值口径（spec 固定值，逐字照抄）**：`exhaustedRounds = 2`、round 末 `max(0, exhaustedRounds - 1)`、解除回血 `hp = max(当前 hp, Math.ceil(hpMax / 2))`、手牌上限 `Math.ceil(hpMax / 2)`、骰移 `max(1, 骰面 - 1) + moveBonus`（**先减后加**）、自恢 **2** 灵枢、救援 **1** 灵枢。
- **触发不立即裁牌**：上限变化在下一次回合末裁牌生效（`handLimitOf` 常规调用点）。
- **力竭不入 `NegativeStatus`**：免疫算子对它无效；四态（poison/slow/silence/skip_turn）本批**不修**。
- **`alive: false` 唯一写入通道 = 山议放逐**：damage 暗杀分支删除后加**常驻源码断言**（Task 2）。
- **穷尽 switch 显式 case、无 default**（probe.ts / legal-gate.ts / performAction 分发——B67/B68 教训）。
- **随机流纪律**：模拟器新增占位分支的 `rng.next()` 消耗点如实登记（Task 8 注释）；`goalPursuit` / `maybeUseAbility` 本身不改（力竭者 `performAbility` 被 `abilityAvailability` 拦下 ⇒ 自动回落，零改动）。
- **AI 占位声明**：自恢 p=0.5、救援 p=0.10 无经验依据（B75.1 §6 同款声明），由 Task 10 重标定覆盖。
- **重标定只在 Task 10 一次**：T1–T9 不得重生成 `docs/balance-report.md` / 发布基线（T8 的报告计数器代码落地但报告重生成留给 T10）。
- **Git**：只 stage 任务列出的确切路径；禁止 `git add -A` / `.` / `stash` / `reset` / `checkout --`。提交信息 `feat(B76): …` / `docs(B76): …`（中文）。
- **门 ② 令牌纪律**：scratch 输出写 `D:/Temp/`，不入仓。
- **三层同判纪律**：`legal.ts` 枚举 = `web/legal-gate.ts` UI 门禁 = 引擎判据，driftScenes 双侧场景（自救/救他人教训 E87）。

## Review Focus

规格隐含、但没有单任务测试天然覆盖、最容易咬到使用者的五类输入：

1. **旧存档缺 `exhaustedRounds`**（undefined 参与 `ceil` ⇒ NaN 手牌上限）——预期：按 0 处理。Task 3 钉。
2. **heal 抬血后的解除**（力竭期间被 heal 到半血以上，解除不得倒扣）——预期：`max(当前, ceil(hpMax/2))` 保底。Task 4 钉。
3. **力竭 + 待认证 + 印记三态叠加**（认证轮内被打空）——预期：印记不清、认证继续、本人不可发起质疑但可被他人质疑、自恢可用。Task 6/7 钉（R-B76-1）。
4. **力竭者发起救援**——预期：被拒（救援是主动动作，力竭封锁）。Task 6 钉。
5. **触发当轮末的递减笔误**（`max(0, -1)` 型错误 ⇒ 当轮末即解除）——预期：触发当轮末剩 1、下一轮末解除。Task 4 钉。

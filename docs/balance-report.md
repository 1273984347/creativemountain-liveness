### 2. 但有一项**结构性问题**必须记录在案：胜率差异来自「座位顺序」，不是身份强度

四套主题的身份胜率几乎一致，且**沿座位顺序严格单调递减**（以科幻·AI 纪元为例）：

| 座位 | 身份 | 胜率 |
|---|---|---|
| 座0 | 先行者（每回合首次移动 +1 格） | 22.4% |
| 座1 | 工程师 | 21.1% |
| 座2 | 深空观测者 | 20.2% |
| 座3 | 仲裁官 | 14.3% |
| 座4 | 守闸人 | 10.1% |
| 座5 | 窃电者 | 6.3% |
| 座6 | 织码者 | 3.9% |
| 座7 | 塔主（首次被质疑自动通过） | 1.7% |

**成因**：`engine/core/setup.ts` 的 `assignIdentitiesAndFactions` 按**座位轮转**分配身份与阵营
（`identities[i % 8]` / `factions[i % 4]`）⇒ 身份与阵营**和座位一一绑定**；
而先行动的座位在「登顶 → 认证 → 封顶」这条主线上占先 ⇒ 胜率沿座位递减。
阵营胜率同理（第 1 阵营 32.5% vs 第 4 阵营 15.5%），**不是阵营强弱差异**。

**为何形式上仍达标**：规格以「偏离均匀分布 > 15pp」为记录阈值，而单调递减把总偏差摊薄到每一项，
单项最大仅 -10.9pp ⇒ 未触发记录线。**这是阈值与结构性问题之间的盲区**，故在此主动记录。

**建议（V1.1 评估，不在 V1 改）**：

1. 开局**随机分配**身份与阵营（而非按座位轮转）⇒ 胜率反映机制强度而非座位顺序；
2. 或每局**随机化座位顺序**（同一局内固定）⇒ 保留身份轮转的设计意图，但打散座位绑定；
3. 补充一项门禁：胜率沿座位顺序的**单调性**（当前 8 项胜率严格递减 ⇒ 座位效应可判定）。

### 3. 模拟 AI 的已知偏置（读数时须打折）

- 脚本化 AI **优先登顶**、认证人**倾向签印**（质疑率 20%）⇒ 放大了「先登顶 = 先赢」的座位优势；
  真人对局里认证是社交博弈，座 0 先登顶未必占优（可能被质疑）。
- 攻击牌目标由 AI 随机选取；真人会挑最脆弱的对手 ⇒ 攻击类牌的实际分布会不同。
- 复议路径的模拟策略较粗（第三方随机投票）⇒ 复议次数与结果的统计仅供参考。
